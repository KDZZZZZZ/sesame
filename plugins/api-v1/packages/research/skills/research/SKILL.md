# 调查并回答用户的问题

1. 明确用户想弄清的关系、对象、期限和已有成果。信息足够就开始，先沿用户观点找证据和方法；非关键未知不反复询问。
2. `research_methods({query,limit})` 查候选，`research_read({ids:[...]})` 每次读 1–5 项。候选的 references 是按需资料 ID；同一目录驱动查询与读取。无 query 可查看方法列表。
3. 轻量摸底后确定关键问题、需要的证据、分析方法、回答顺序及完成条件，不预填结论。未命中或混合问题读 `adapt-and-compose`，选主线后借入必要调查，不拼接整套报告。
4. 复用固定成果，独立取证和分析可以并行。来源/数据用 data-access 等插件，专业解释用对应知识，计算用实际计算能力；保存支撑判断的原始观测或计算结果及口径、单位、时点与来源，不只留文字总结。复杂或最大努力任务使用现有编排和工作流，不另造调度器。受限成员通过现有任务输入取得所需方法摘录。
5. 每个重要发现检查它支持哪个问题、是否存在相反解释；关键矛盾或可改变答案的缺口触发定向补查。按需读 `evidence-and-judgment`、`review-and-recovery`，字段含义和历史问题可从相关资料进一步查阅。
6. 依据结果调整答案结构，逐项核对用户问题已回答、剩余缺口的影响或用户明确删减。每份报告先直接回答核心问题，给出关键结论，再展开分析；条件判断先点明决定结果的关键条件。正文组织参考 `adapt-and-compose` 的“组织报告”，合并子研究的重复内容，不拼接完整小报告。只修改视觉时直接复用成果，不重新研究；允许 Reports 按本次目标重组章节、图型和文字，不锁定旧图数和版式。
7. 把初稿的判断、每段表达意图、实际数据、引用和关键条件交 Reports，按“要让用户看懂什么”做保持原意的视觉设计，尽可能把数据组织成图表；取证时保留可绘图的数据，交付时先设计图文表达，多条件展望用决策树，图型与排版由 Reports 决定。不以数据已在旧图、表格或数值列表里当作完成；原版式可重组，缺失事实不编造。研究复杂或用户指定报告路径时实际发布并验证报告可见；简单问答可直接回答或使用回答内组件。正文解释发现与意义，避免逐项重复图中数据。内部调查表、工作过程和校验术语不自动搬入正文。

完成由研究 Agent 根据问题和证据判断。一次适用检验未完成不等于全部研究失败；未测不能写成通过。继续推进有价值的路径，无新条件不反复重试同一失败。
