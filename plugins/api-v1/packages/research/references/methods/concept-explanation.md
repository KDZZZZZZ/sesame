# 概念、机制与简单计算

直接解释用户不理解的关系，用必要市场例子或复算回答。

## 找到理解缺口
识别用户要的是定义、机制、数字解释还是小计算，先用已有上下文和专业知识回答。术语有多义且会改变答案时澄清关键含义；不把每个普通词都变成研究项目。
时效性事实或具体数字需要实际来源；小计算保留输入、单位和公式，金融术语可保留并说明。用户观点先确认边界，寻找能帮助理解的例子，不以缺少自己的知识轻易否定。
## 回答组织
直接回答所问关系，补一个必要例子或计算；只有会混淆时才区分近似概念。一段足够就结束，不套公司、宏观或策略整篇结构。
## 完成检查
回答是否解决具体困惑，是否多讲了无关背景，例子是否被误写成已验证事实。需要组件帮助理解可交 Reports 呈现；简单问答不强制生成报告。
