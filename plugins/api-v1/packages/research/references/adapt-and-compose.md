# 任务适配与组合

先看用户要解释、比较、诊断、判断条件、复盘还是查事实，再看对象、期限、事前/事后和已有证据。不要见股票就套公司研究，见未来就补交易方案。

## 有预设
选择能回答主问题的方法，按用户范围裁剪。共同对象、数据、来源和历史结果取得一次。方法中的回答结构只是内容顺序，不规定页面、图表或字数；任何字段知识都不是必填表。

## 混合问题
选一条主回答线，再借入其他方法的必要调查，避免拼接整套模板。
- “利润增长为什么股价跌了”：以事件解释为主，借财报点评核对事前预期、盈利质量和指引，再看同期市场；只有价格预期确实相关时才深入估值。
- “AI 投资能否提高电力公司长期价值”：以价值形成与估值为主，借宏观传导调查需求、资本开支、融资、监管回报及现金流；不用先写全球宏观综述。
- 同一事件的事实查询、债券传导、持仓影响分别采用事实时间线、利率路径、实际暴露；不要只更换报告标题。

## 未命中
目录检索只是词义提示，不是任务分类器。换用关键关系或不传 query 查看目录，读取最相近方法，结合轻量取证补本次独有的问题；主动寻找可发现的专业插件、数据渠道与一手参考。没有同名方法不是停止条件。
临时计划通过已有任务文本/工作区记录目标、关键问题、证据、方法和预期回答，不新增固定 JSON 协议。新证据可以改动结构，不能悄悄丢掉用户要求。可复用的新方法在确认价值后维护，不把每次临时大纲自动升级成规则。

## 用户和成果优先
用户指定结构与删减优先；Agent 为省事删掉章节不代表用户放弃问题。简单解释可只答一段；只要事件日历就交事件；仅改视觉直接交 Reports。已有成果先核对时效和口径后复用，更新任务只取发生变化的证据。
