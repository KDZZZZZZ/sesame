# 定向复核、恢复与交付

## 研究完成检查
由实际执行研究的 Agent 判断，不由方法目录或静态 schema 自动打分。
- 用户明确问题是否有对应答案，关键关系是否解释清楚，而不是只填数字或统一“判断/依据/风险/下一步”。
- 结论是否能定位到相应证据；关键数字、单位、期限与比较口径是否一致；是否隐含把未来数据带回过去。
- 是否存在会改变主要答案的矛盾、替代解释或具体缺口；如果有，只补查受影响部分。
- 是否把无关方法、重复背景、过程术语或重复图注写进正文；关键反例和条件不能以精简为由删去。
- 剩余未知是否影响用户的实际问题。短答案不因章节少而不充分，长报告不因栏目齐全而自动完成。
- 报告开头是否直接回答原问题；章节是否沿同一条回答线推进；支撑判断的各组数据是否已通过图表呈现，包括比较基准、区间端点、参照及已计算的敏感性，而非只画一组。有剩余数字串时核对是否漏图；删掉重复铺垫和数字复述，保留会改变判断的证据。

## 失败与条件不足
先判断缺的是权限/配置、来源、数据口径、可执行计算还是方法知识，并主动使用已有配置和数据能力处理。尝试替代来源时保留含义变化；没有新条件不重放同一失败请求。
与需求无关或环境无法进行的检验不阻塞其他工作。把未测、不可适用、失败与已通过分清，交付能支持的结果；缺少真正决定问题的输入时说明其影响，再索取必要信息。
新证据推翻猜想时修改解释与相关结论，保留原假说和检验记录。不要整轮重算已经成立的结果，不以增加角色、查询次数或报告篇幅代替进展。

## 检查旧验证语义
原报告的采样、概率、来源与机制检查已经迁到 `evidence-and-judgment` 和各字段资料，属于研究复核提示，不再是报告发布的研究门槛。核对计数、固定引用与单位可以自动化；“是否充分、机制是否可信、方法是否适用”仍须结合当前任务判断。

## 交付
使用现有编排管理成员、Run、通知和暂停恢复。成员把答案、固定证据、必要条件与剩余问题交回；主 Agent 汇总并向用户简要说明发现及已经开始的下一步。
复杂研究或用户指定报告路径时，使用 Reports 实际发布报告并检查可读、可见及统一呈现。交付内容与真实研究主题匹配；策略回测进入策略报告空间，普通研究进入研究空间。只有摘要、成果引用或保存 JSON 不等于用户已看到报告。
只问概念或简单事实可直接回复。报告渲染/导出检查归 Reports；账户和交易动作依然遵循现有授权与执行能力，本指南不增加交易权限。
