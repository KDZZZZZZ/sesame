# 投资委托书

委托书（Mandate）是投资前的资源分配与授权：在 IPS 的长期规则之内，为这段时间、这批投资任务划出资金额度、损失预算和复审时点。它回答五个问题：为什么投、投什么、最多投多少、最多愿意承担多少损失、何时重新决定。

委托书不是投资后的绩效评价。编写时不需要策略已有运行记录，也不计算 Sharpe、Sortino、Calmar、Profit Factor、历史最大回撤等业绩指标；这些放到策略研究与评价环节。

## 何时需要

| 情况 | 做法 |
| --- | --- |
| 研究结果会动用资金或交易授权：开发准备部署的策略、交易决策、建仓或调仓、资产配置、决定投什么和投多少 | 研究前先编写委托书 |
| 已有委托书仍在有效期内，并覆盖这次的账户、投资种类和额度 | 直接沿用；这次超出它的范围时修订 |
| 行情或个股问答、方法与知识研究、不涉及资金的因子挖掘、复盘已有交易 | 不需要 |

拿不准时看这次的结论会不会变成“某个账户拿多少钱去做什么”。会，就先写委托书。用户明确说不需要时，照用户的意思跳过。

## 先读取 IPS 和账户

- **IPS**：用 `memory_search` 找「账户名称 · IPS」，再用 `memory_read` 读全正文。没有 IPS 时，向用户说明，并只问编写委托书必需的几项：投资目标、允许的投资品类、可接受的损失和近期用钱计划。
- **风险红线**：涉及交易时用 `memory_trading_context({})` 读取已确认的 `trading/risk-rules`。
- **账户**：资金和持仓用已绑定后端实时读取，如 `portfolio_execution_context`、`qmt_read`。读不到时用用户给出的数字并注明时点。记忆和 IPS 里的金额不是当前余额。

## 四个决策步骤

| 步骤 | 决策原则 | 所需信息 |
| --- | --- | --- |
| 1. 确定可分配资金 | 账户资金减去提款需求、备用流动性、已有交易的保证金缓冲和其他已承诺资金 | 账户资金、现有持仓、IPS |
| 2. 选择投资种类 | 只检查三项，见下文 | IPS、账户的实际交易条件 |
| 3. 分配投资额度 | 按任务的重要性和风险边界分配，不要求用满全部资金 | 可分配资金、IPS 里的偏好 |
| 4. 制定执行边界 | 每项任务最多用多少钱、最多承担多少损失、何时复审 | IPS、风险红线、账户约束 |

选择投资种类时检查三项：

1. **目标适配**：能否服务这次的目标，如现金管理、长期增值、主动交易、对冲。
2. **期限与流动性**：资金什么时候要取出，这种投资能否在那时退出。
3. **风险与交易权限**：是否在 IPS「允许投资的品类」和杠杆限制之内，账户是否真的能交易。IPS 写着“待确认”的品类，先问用户再放进委托书。

分配额度用简单的额度法：

1. 先保留必要资金：提款需求、备用流动性、已有交易的保证金缓冲。
2. 长期资产写目标比例；主动交易和量化研究只写最高可用额度，不要求立即投入。
3. 每项任务的损失预算从 IPS 剩余的损失容量里划出，合计不超过它。

不预测各资产的未来收益率，也不运行优化算法。几项同类任务缺少区分优劣的证据时，可以先给等额，再按风险限制修正；风险不同的投资不无条件等额。样本估计的复杂优化在样本外常常不胜过等权（DeMiguel、Garlappi、Uppal，2009），但这不是等额配置的理由。

## 四个指标

| 指标 | 怎么得到 | 是否必须 |
| --- | --- | --- |
| 可分配资金 | 账户数据减去不可动用资金和预留 | 必须 |
| 投资额度 | 按目标、用钱计划和 IPS 定出每项任务的上限 | 必须 |
| 最大允许损失 | 从 IPS 允许的损失容量里为本委托划出 | 必须 |
| 最大杠杆或敞口 | 按 IPS 和账户权限确定 | 仅杠杆投资 |

它们都能在投资前定出来。最大损失是风险控制预算，不保证实际亏损不超过它：跳空、滑点和杠杆强平都可能造成超额损失。向用户说明时照实写。

## 五个字段

| 字段 | 回答 | 写法 |
| --- | --- | --- |
| 1. 投资目标 | 为什么投 | 这段时间要达到什么 |
| 2. 投资范围与分配 | 投什么、最多投多少 | 每个投资种类的比例和金额，保留现金单列；注明是目标比例还是额度上限 |
| 3. 风险限制 | 最多承担多少损失 | 本委托的损失预算金额；杠杆投资写最大杠杆或敞口；无法有效控制风险时降低额度或不交易 |
| 4. 投资任务与周期 | 每笔钱做什么 | 每项任务的用途和交易周期，如“长期配置”“研究日内至波段策略，获准后才实盘” |
| 5. 复审条件 | 何时重新决定 | 有效期、定期复审、提前复审的触发条件，如资金需求变化、损失预算触及 |

委托书有效期和策略交易周期相互独立：三个月有效的委托书可以授权研究分钟级、日内或日线策略。

以下不是编写委托书的必要条件：具体交易信号、止盈止损距离、因子选择和策略参数。它们在后续研究里确定。量化交易只需写清可用额度、允许的市场、最大损失和需要哪一级交易授权；额度怎样分到各策略，等策略研发完成后再定。

## 用户确认

把草案给用户看：可分配资金及扣除了哪些、各项比例和金额、损失预算、复审条件，并注明依据的 IPS 条目和账户数据时点。用户确认投资范围、比例和损失预算后委托书生效；符合 IPS 的草案，用户可以直接采用。

只追问 IPS 没写、又会改变分配的事，例如近期是否有提款需求。IPS 已写明的不再问。

委托书不授予实盘权限，也不改变风险红线。损失预算不能超过 IPS 和已确认的风险红线，两者冲突时以红线为准并告诉用户。实盘交易权限仍由用户在交易流程里单独授予。

## 编进计划并交给后续插件

- 把“编写投资委托书”写成计划的第一条待办，用户确认算完成；研究待办用 `after` 接在它后面。
- 参考 `strategy.development` 时，把预设步骤 `mandate` 放进这条待办。用户确认后调用 `strategy_development_plan`，把委托书写进 `mandate.context`：`source` 用 `"user"`，`evidence` 引用用户确认的原话，额度、市场、周期、杠杆和复审条件填进对应的 `fields`，对应不上的写进 `mandate.brief`。上报时 `refs` 给出返回的 `mandateRef`。
- 交给 investment-research、trading-decision 或子 Agent 时，在任务目标或输入里写明与它有关的条款：投资范围、额度、损失预算和复审条件。交易决策仍会自行读取风险红线。
- 已有有效委托书时不再写这条待办；参考了工作流时用 `have` 和 `refs` 声明已有的委托。

## 保存与沿用

委托书确认后在本次计划里使用。用户希望之后的会话沿用时，按长期记忆的规则单独记一条「账户名称 · 委托书」：来源引用用户确认的消息，有效期末写入 `expires_at`，复审时间写入 `review_at`。新委托书替代旧的时修订原条目，不另建一条相反的记录。

## 示例

假设账户可动用现金 ¥100,000。数值只说明字段怎样组织，不是配置建议。

| 字段 | 内容 |
| --- | --- |
| 投资目标 | 长期资产增值，同时用一部分资金研究量化交易机会 |
| 投资范围与分配 | 股票/ETF 50%（¥50,000，目标比例）；量化交易 20%（¥20,000，额度上限，不要求持有等额风险头寸）；保留现金 30%（¥30,000） |
| 风险限制 | 本委托损失预算 ¥2,000；不突破 IPS 的杠杆和风险限制；无法有效控制风险时降低额度或不交易 |
| 投资任务与周期 | 股票/ETF 长期配置；量化额度用于研究和验证日内至波段策略，获准后才实盘部署 |
| 复审条件 | 每月复审；资金需求变化或损失预算触及时提前复审 |

```json
{
  "action": "open",
  "title": "开发股指日内策略",
  "workflow": "strategy.development",
  "have": ["UserRequest"],
  "steps": [
    {"step": "mandate", "title": "编写投资委托书", "description": "按账户 IPS 和当前资金拟定额度、损失预算和复审条件，用户确认后写入策略开发委托。", "presets": ["mandate"]},
    {"step": "data", "title": "准备行情与成本", "description": "取得委托书允许市场的行情、交易约束和成本模型。", "presets": ["market"], "after": ["mandate"]}
  ]
}
```
