# 组织研究与协作

## 1. 明确目标并发现现成能力

编排按研究问题组织协作。面对实质任务或能力缺口，用 plugin_discover 按目标、已有输入、所需交付查找合适插件，读取声明后加载；当前默认挂载的工具不是产品的全部能力，不先用自写脚本重做已有插件。工作流可由声明 start:workflow 效果的公开函数启动，不能只按 kind="workflow" 筛选而漏掉启动入口，也不调用内部控制器。信息能力交付有来源、时点、覆盖和固定引用的证据，方法回答局部问题，工作流选择互补方法并综合支持、反证与分歧。已有证据和匹配计算可以复用；多个同源指标不等于独立验证。日常问答可直接回复，不强制报告或拆分任务；给成员明确目标、输入、方法和可调用能力，不为凑角色扩大工作流。

按职责组合插件，不找一个包办全部工作的插件：工作流组织阶段，技术知识提供理论与方法，数据能力供给证据，计算和回测验证，报告能力交付。根据用户的机制和研究问题主动发现、读取相关知识，把它落实为假设、特征、实验或解释；不能因为纯知识没有函数就忽略，也不只读目录简介就称已使用。关键词无匹配时换用相关概念或浏览可发现目录，不把一次搜索为空当作没有方法。给工作流或子 Agent 一并传入选中的知识包和数据/计算能力，并说明方法在该阶段的用途。auto-factor-mining 的 config.research、investment-research 的 research 均可组合知识和工具插件，具体调用仍须符合各自合同。

## 2. 选择执行深度与工作流

先按目标选择执行方式，不把默认成员表当作所有任务的固定流程：

| 情况 | 采用的方式 |
| --- | --- |
| 单个清楚的问题、轻量研究或现有证据足够 | 主 Agent 直接做，或用 `host_agent_run` 委派一个明确阶段。 |
| 现成工作流能覆盖业务目标，但成员、研究角度、验证环节或时间预算不合适 | 调整该插件公开的计划字段，再从其公开入口启动。已有验证机制仍按真实需求与执行合同处理。 |
| 若干独立问题需要并行、后续步骤依赖前序结果，或需要跨多个插件综合 | 自定义阶段计划，用宿主 Agent 工具或多个真实工作流 Run 执行；先完成依赖，再开始使用结果的阶段。 |
| 需要把一种新业务流程长期复用、周期执行或形成自己的持久控制逻辑，而现有插件无法表达 | 使用插件开发能力实现明确注册的 workflow/graph，再调用其公开能力。一次性研究不必先开发插件。 |

用户改变目标、已有证据使某些环节重复、需要新增独立反证、数据依赖不同，或希望减少延迟与成本时，都应主动考虑自定义。先复用能满足目标的部分，调整有实际收益的角色、输入、顺序、并行组和交付；无需等用户说出“自定义编排”。用户明确限制范围、深度或成本时，计划遵从这些限制。

用户明确要求“最大努力”“最大功率”“全力”或“高强度”研究时，发现、加载适配工作流并调用其声明的公开启动入口。单品种可以组织工作流，某个 evaluator 的多品种要求不代表工作流只能做多品种。因子挖掘、候选筛选和因子组合试验按实验目标查找 auto-factor-mining 及真实 evaluator，读取其数据和评价合同；investment-research 的可配置阶段可承担适合的证据调查和方法研究，但不能把这类研究说成已完成缺失的数值试验。纯知识指南不执行工作流。只有真实工作流 Run 受理才称已启动，发现、加载或普通 subagent 并行不能代替。将数据获取、评价实现和流程组织分别解决；某一项缺失时，继续能独立完成的数据准备与研究阶段。经发现和契约核对确认没有适合的工作流时，说明具体缺口，再委派独立问题并行处理，不称已使用工作流。复用证据，保持依赖顺序和阶段报告交付，不用主 Agent 串行包办全部研究。

用户明确要求“轻量研究”或“快速研究”时，主 Agent 可以直接使用相关能力完成，不强制启动工作流或为凑流程委派子任务，研究深度与耗时遵从本次要求。轻量执行方式不取消研究报告要求；日常问答仍可直接回复而不生成报告。

## 3. 准备输入与交付阶段

数据缺失时先复用工作区与缓存，再按标的、数据类型、时段和粒度发现来源能力。data_providers 只列已注册来源，不能据此认定所有插件都没有数据；按声明尝试适合的其他行情源、搜索、网页获取或文件下载，核实真实标的与时间粒度后再交给下游。补齐可自行处理的输入是主 Agent 的工作，不以某个连接失败为由直接让用户上传文件、切换账户或选择下一步。具体授权和恢复规则遵循宿主总提示。

主 Agent 将实质研究组织为有用的阶段，按需把独立或专业工作委派给 subagent 或适合的工作流，说明本阶段问题、已有输入、可用能力、完成条件和报告目的地。每个交付阶段都要实际生成并发布报告；数据量大或复杂的分析任务也需要报告，不以用户是否说出“报告”为前提。创建阶段任务时传 report 输出并授予写作、发布和核验所需能力，报告绑定到实际交付阶段的 Run，不把长期主对话绑定为研究报告任务。主 Agent 负责协调、解决前置问题、复核、综合与简报。子 Agent 完成自己负责的阶段，不默认递归委派；工作流内部成员交接证据和结论，由指定综合者交付阶段报告，无需每个方法或成员另建一份。

## 4. 调用编排工具并安排协作

这些工具由宿主直接提供，编排插件负责其使用方法：

| 工具 | 何时使用 |
| --- | --- |
| `host_agent_run` | 创建一个明确的阶段或明确授权的协调 Agent；返回真实 Run 引用。 |
| `host_capabilities_invoke` | 调用已注册的 Agent / 工作流能力，需要 `operationId`、报告输出或协作图等调用选项时使用。 |
| `host_runs_list`、`host_runs_read` | 找到已有任务，读取同一 Run 的状态、输出、消息与实际成果。 |
| `host_runs_wait` | 当前步骤确实需要等待某个 Run 的结果时使用；普通完成通知无须靠轮询取得。 |
| `host_runs_message` | 给已有任务补充资料或修正要求；它不代替恢复中断。 |
| `host_runs_interrupt`、`host_runs_resume` | 缺少关键依赖时暂停，处理具体阻碍后恢复同一 Run。 |
| `host_runs_cancel` | 按用户要求或已明确结束的任务范围取消运行，并核对实际收尾。 |

自定义协作按以下步骤执行：

1. 为每个阶段写明问题、输入及来源、完成判据、所需知识与调用能力、依赖和成果去向。相互独立的阶段可以并行；综合、复核或回测必须拿到其需要的真实前序结果后再启动。
2. 单次委派用 `host_agent_run` 的 `title`、`objective`、`instructions`、`input` 描述任务，`plugins` 选择方法知识，`allowedCalls` 授予实际工具，`output` 绑定交付。研究与回测报告分别放入适合的 research / strategy 空间，完整参数示例见 [Agent 与 Run 调用参考](references/agent-runs.md)。
3. 直接由主 Agent 协调几个阶段时，逐个提交独立 Run 并保存真实引用。需要一个独立协调者管理成员时，明确授权它再次委派，传入所需的宿主和业务能力；默认“子 Agent 不递归委派”的规则不阻止这一项明确分工。
4. 需要显示协作结构时，通过 `host_capabilities_invoke` 的 `task.collaboration` 声明稳定成员及关系，内部成员调用以 `task.agentId` 绑定身份。关系线是展示信息，不执行依赖调度；协调者或业务控制器仍须实际安排调用、等待结果和传递证据。具体例子见 [工作流计划与可调整阶段](references/workflow-plans.md)。
5. 定制现成工作流时，只修改它公开支持的计划字段。Investment Research 可以改阶段及阶段内并行成员，Auto Factor Mining 可以配角色和可选规划/评审/反思，Trading Decision 可以配顺序复核；这三者都不能用一个任意 DAG 替代其真实执行合同。

协作图、计划文本与普通 Agent Run 都不自动变成业务 workflow。要求启动真实工作流时，仍须使用已注册的工作流或其公开启动函数，以实际受理的 Run 为准。

host.agent.run 的 plugins 可显式选择知识包，工具所属包会自动加入；完整方法资料使用 allowedCalls 中明确授予的 sesame/plugin-manager#plugin_read 读取。plugins 不授予工具，allowedCalls 仍是调用能力的唯一清单；纯知识包没有可调用函数，也不应伪造执行回执。

委派明确目标、输入和可用能力。宿主统一提供 host_runs_read、host_runs_wait、host_runs_interrupt、host_resources_read 四项基础能力，资源读取仍受任务范围限制，额外能力由 allowedCalls 显式选择。Run 受理不等于完成，最终结果以 completed 的 run.output 和同一任务绑定的成果为准。依赖缺失时暂停并向主 Agent 报告，不能用替代目标冒充完成；取消不回滚外部副作用。

## 5. 接续成果与下一阶段

阶段任务受理后，主 Agent 可继续启动不依赖其结果的独立阶段并行研究；没有独立工作时，向用户说明已开始的研究，再结束当前回复并空闲等待。顶层 Agent 或工作流 Run 完成并收尾后，宿主自动通知并唤醒所属主 Agent；工作流内部成员先返回控制器，无需为接收完成结果反复轮询。主 Agent 核对同一 Run 的结果、报告当前路径、发布状态与精确修订的渲染回执，向用户简要汇报发现、边界及实际报告。已有任务授权内还有有价值的下一阶段时，先实际启动，再说明正在进行什么；没有有效下一步时收束本轮。自动通知不是新增用户授权，用户明确的暂停、取消与范围仍有效。固定数据成果、草稿与聊天回复不代替报告区中的实际文件，Run completed 本身不证明报告已交付。

## 6. 应用本次要求与长期偏好

业务流程按任务调整：当前明确要求优先于适用的长期偏好，再采用插件默认。用户明确要求长期沿用时，使用 memory 保存 user/workflow 与真实用户消息来源；执行前读取正文、适用范围和版本，将选择转换成该工作流声明支持的计划。临时变更不改长期默认，偏好不授予交易权限、不绕过证据和风险约束。已受理的 Run 保留冻结计划，改变计划另开研究。

需要选择 Investment Research、Auto Factor Mining 或 Trading Decision 的可配置阶段时，按需读取 [工作流计划与可调整阶段](references/workflow-plans.md)。
