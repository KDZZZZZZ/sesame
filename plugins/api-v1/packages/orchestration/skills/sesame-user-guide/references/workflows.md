# 按你的目标使用 Agent

依赖与本机配置先检查并复用，确认缺失后才按任务需要显式安装并验证。工作区计算使用本机当前用户权限，不是 OS 沙箱；报告和指标的前端只读渲染隔离仍然保留。

下面的示例是普通聊天请求，品种、时间和资料换成用户自己的。涉及当前可用性时先核验配置、来源与权限；不要把本页当成已完成过所有任务的证明。

## 让工作台围绕你的问题变化

你不用逐张添加、选周期、改布局。告诉主 Agent 想对照什么，它可以打开行情图、调整窗口宽度、平铺图表、定位或最大化某张图。既有图表、锁定和正在拖动的布局应被尊重。

> “把 EURUSD 的 H1、H4、D1 同时放出来，H1 占左半边，其他两张上下排列。把聊天栏缩窄一点。”
> “保留现在的图，另外加一张我券商的黄金 M15，找不到品种就先查名称。”

得到的是可继续手动调整并自动保存的工作台。图表编排成功不代表交易已经执行，主 Agent 需检查当前前端回执后才说“已显示”。

## 并行研究：更快对照不同角度

可以让主 Agent 把一个问题拆成多个独立 subagent，例如分别读新闻、检查数据、分析价格结构或验证策略假设。各自先产出最终报告，由主 Agent 汇总共识、冲突与仍缺的证据。并行数量、速度与成本受模型和运行环境影响，不承诺无限并行。

> “并行安排三个 subagent：一个读我给的公告，一个检查价格和成交量，一个找反对观点。最后给我一页带来源的结论和分歧。”
> “让两个 subagent 分别研究趋势和均值回归方法，再比较它们在哪些环境容易失效。”

成果放在右侧 Research / Strategy，能引用、追问和修订；子任务结束后临时过程清理，最终成果保留。主 Agent 最后负责把需要的曲线放到 Dashboard，subagent 不直接抢占用户布局。

### 宿主编排接口（供 Agent 按需参考）

本指南不提供工具。普通 Agent 和工作流使用同一套宿主 Run 生命周期，工具是否可用以当前工具列表和明确授予的能力为准。

| 能力 ID | Agent 工具名 | 输入与结果 |
| --- | --- | --- |
| `host.agent.run` | `host_agent_run` | `title/instructions/objective/input/allowedCalls` 定义任务，返回受理的 Run 引用。`model` 和 `output` 可选。 |
| `host.runs.list` | `host_runs_list` | 用 `sessionId/parentRunId/capabilityId/status` 等筛选运行，返回分页概要；不创建任务。 |
| `host.runs.read` | `host_runs_read` | `runId` 读取真实状态；可用 `include/cursor/limit` 读取消息、调用、事件、输出和资源。 |
| `host.runs.wait` | `host_runs_wait` | `runId` 配合 `until:"settled"` 等待最终结果；`until:"changed"`、`afterVersion` 用于观察变化。返回等待原因与最新 Run。 |
| `host.runs.interrupt` | `host_runs_interrupt` | `reason` 说明阻碍；子 Agent 省略 `runId` 时暂停自身，主 Agent 操作其他任务需指定 `runId`。 |
| `host.runs.resume` | `host_runs_resume` | `runId/interruptIds` 明确选择已处理的中断，`response` 提供解决信息；恢复同一个 Run。 |
| `host.runs.message` | `host_runs_message` | `runId/text` 向现有运行发送补充信息，不能代替明确的恢复操作。 |
| `host.runs.cancel` | `host_runs_cancel` | `runId` 和可选 `reason` 请求取消；以后续读取的真实状态确认收尾。 |

`instructions` 给出相关能力、因果明确的原则与约束，`objective` 给出可核验目标；不要让子任务重新猜测已经知道的输入或依赖。`allowedCalls` 使用 `{pluginId,capabilityId}`，其中 `capabilityId` 是局部 ID，例如 `{pluginId:"sesame/data-access",capabilityId:"data_query"}`。每个 Agent 自动拥有 read/wait/interrupt 三项基础 Run 能力；`allowedCalls:[]` 不授予业务工具、再次委派、恢复或取消权限。

`model` 省略时复用宿主配置，显式选择需使用 `host#models` 返回的 `{provider,id,configurationDigest}`。需要幂等操作标识时，通过 `host.capabilities.invoke`（工具 `host_capabilities_invoke`）向 `host.agent.run` 传递 `input` 和 `operationId`；不要把 `operationId` 塞入 Agent 任务输入或以新 ID 重启未确认的动作。

报告任务可指定 `output:{type:"report",space:"research",path:"comparison.html"}`，也可用 `space:"strategy"`。这是该 Run 的报告交付位置，正文标题由最终报告内容决定。普通任务可省略 `output` 或使用 `{type:"none"}`，无需为了运行 Agent 创建报告。

受理返回的 `run.id` 是后续控制和读取的身份；只有 `completed` 的 `run.output` 才是最终结果，包含 `text/sessionId/model/turns/toolCalls`。等待超时只结束本次等待，不取消任务；`changed` 可因细小进度提前返回，不适合反复轮询最终成果。依赖缺失时暂停并报告具体需求，等待返回 `reason:"interrupted"` 后由主 Agent 核验并处理具体阻碍；已授权范围内可修复的依赖不要求新的用户回复。恢复前从同一 Run 读取待处理中断，明确选择实际解决的 `interruptIds`，是否需要用户输入遵循宿主控制契约，不默认把一个答复套到全部中断。正常结束由宿主收尾，无需另行完成调用；取消不回滚已发生的外部副作用，结果未知时读取 Run 与对应后端状态。

## 不写代码，也能提出想看的曲线

说清“输入什么、怎么算、画在哪里、是否跟随新行情”。Agent 可在图上发布 JavaScript 指标，或把 Python 等研究计算得到的最终数值序列画到主图/副图。

> “在这张 H1 图上画 20 周期均线和最近 50 根 K 线的最高价、最低价通道，新行情来时更新。参数保留可修改。”
> “按 @波动率研究 的口径，在副图画滚动波动率，并标清周期和单位。”

代码曲线是可阅读、可改参数的实现；改公式后可以继续迭代。在线指标随已加载行情重新计算，静态研究序列不会自行变成实时数据。图内指标不能直接联网、读本机文件或下单；需要额外资料时先研究、整理数据，再画最终序列。图上的效果不是盈利或回测证据。

## 从资料得到能追问的研究报告

> “分析 `/绝对路径/我的数据.csv`，先检查缺失和重复，再比较各组结果，把方法、来源与图表做成 Research 报告。”
> “读取我提供的三个公开网址和 RSS，去重后给出事件时间线，区分事实与判断。”
> “比较 @研究甲 和 @研究乙 ，解释它们为什么得出不同结论，再做一个合并版本。”

用户得到可核对的数据口径、图表和引用，而不只是没有依据的一段答案。网页登录、付费墙或缺失文件可能需要用户补充合法可取得的内容；Agent 应报告具体缺项。报告把数据、代码和图形资源固定为一个版本，可重开并检查原数值；筛选不偷偷更新行情，演示数据显眼标注。修改会生成新版本，原始证据仍保留。

## 把策略设想变成可以验证的工程

> “把这套入场、出场和仓位规则写成 MT5 策略，先复述规则，再生成状态图、源码和参数；对指定时间区间做真实回测并解释失败场景。”

用户可以从想法逐步得到版本化规则、源码、编译结果、真实 Tester 记录与报告。先明确品种、周期、时间范围与风险约束。通用策略先编写 SVL 源并检查，再由 MT5 等目标插件翻译、说明平台差异并执行原生验证。固定输入演算只检查通用规则，不等于原生回测或撮合。旧的原生 MQL5 和 visual-mql-v1 工程保留自身身份，不自动变成 SVL。真实挂载取决于目标插件支持和当前账户权限；普通研究请求不触发部署。

## 让经验在以后继续有用

> “记住我更喜欢简洁结论，但每个重要数字要能追溯来源。”
> “这次研究的数据口径错了，把修正和适用条件记下来，以后同类任务先检查。”
> “对未来可验证的判断，事前记录期限和证据口径，到期复盘，比较哪些判断准则值得继续验证。”

长期记忆保存可复用结论与来源，避免每次重新交代；判断复盘帮助观察偏差、适用条件和变化。主 Agent 按任务需要读取持久复盘清单并决定何时处理，重启保留待办；证据不足会等待或说明原因，候选准则不能直接叫“可靠方法”，也不保证收益。主 Agent 可提醒相关 subagent 读取适用准则。

## 把重复工作整理成插件

> “把每次整理网页资料、去重并生成摘要的流程做成可复用插件，先测试，再告诉我怎么使用和关闭。”

在 [官方插件目录](https://sesame.bot/zh/plugins/) 找到方法，复制精确名称（如 `sesame/web-extract`）交给 Sesame。Agent 先核对当前版本与目录兼容性：随应用提供的功能直接启用；可安装包按固定版本校验并测试后加载。实际工具成功可调用后才说已可用。安装不代表第三方服务认证已完成。

## 一个更容易得到好结果的请求

交代 **目标 + 对象/资料 + 范围 + 交付形式 + 约束**。例如：“帮我判断这两套方法在哪种市场环境更稳定，数据用指定文件，分别并行研究，最终给比较报告和两条图表曲线；这次只研究，不部署。” 缺少关键输入时 Agent 只问必要的问题，有现成资料时先查，不能编造用户没给的条件。
