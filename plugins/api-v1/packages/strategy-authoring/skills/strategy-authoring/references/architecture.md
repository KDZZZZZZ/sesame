# 从研究规则到可核验策略

本参考适用于 SVL/1 当前原语，不定义新字段、执行引擎或订单 API。没有安装交易后端时，仍可完成 source → graph → 固定事件 replay → 报告。以下章节是创作顺序，不要求源码照搬某个平台的模块或类。

## 1. 先把需求写成可以判断的规则

分别写出信号、进入条件、退出条件、持有期、数量、最大风险、停止条件和缺数行为。对于 PA、ICT、趋势等研究描述，把已经确认的定义和仍模糊的条件分开；不要让翻译器暗自补交易规则。每条规则应能指向一个源节点、状态或明确的目标限制。

采用小型事件状态机，还是信号 → 目标仓位 → 风险 → 执行的组合设计，由策略决定。图必须展示源码中实际存在的节点和边界，不能加一个“风控”标题代替缺失的风控逻辑。

## 2. 数据、时间和可用性

保留完整 InstrumentRef、来源/连接、价格口径、单位、周期、交易时段与调整方式。Bar 的时间是 openTime 和 endTime；Quote 是 time。来源墙钟保留 authority、zone、fold，不猜 UTC。事件 availableAt 表示可获知时间，不能替换柱区间。

M1 更新时，尚未闭合的 H1 柱不是“最后一根已闭合 H1”。预热不足、分页不完整、缺值或无法证明时间对齐时，保持 not_ready 或明确拒绝。跨输入 cross 必须有逐项可比时间；不能用数组长度、宿主收到消息的时间或自行合成的序号证明同步。

包内两个无时间价格样例只验证同输入教学逻辑。它们不证明市场顺序、交易所闭合、真实时序或完整防前视。真实适配应保存原始固定 DataRef，并明确窗口选择及何时可知。

## 3. 信号与有界状态

将纯计算和状态改变分开。明确一次信号何时生效、失效、允许再次触发。形成中柱修订不能无条件变成重复订单；同一事件重交与新的市场事件要有不同的真实身份。

先运行 close-threshold 源及四事件 fixture，手算 99/101/100 相对阈值 100 的结果；再运行 crossover 的单次入场语法。后者没有退出、保护或完整订单生命周期，不能直接当成完整交易策略。

## 4. 数量、资金分配与未决敞口

信号强弱、目标数量、当前持仓和未决敞口不是同一个值。每个数量保留 unit，每个金额保留 currency，每个价格保留 instrument。固定数量的示例是 100 share，不能静默改成 100 lot。

两资产各分配 5000 USD 的手算问题，还需要价格、汇率、合约乘数、步长、费用与购买力规则；这些输入缺失时不能从“50% 权重”直接生成数量。当前原语没有通用组合分配器；显式可表达且有依据的计算才写进源，其余说明限制。整数算术产生 Decimal 字符串，状态类型与量纲要一致。

## 5. 风险、退出和归属

写清最大敞口、剩余风险额度、保护的建立时机、部分成交后的保护数量与保护失败策略。order.submit 的 stopPrice 是 stop/stop_limit 订单触发价，不是市价入场自带的止损。软件在线检查与券商原生保护具有不同停机风险。

当前源没有通用父子保护关联，也不能凭 positionEffect:"close" 证明精确关闭某个套保持仓。用户要求无法无损表达时，目标返回 unsupported/limited；不得退化为无保护交易，或在原生代码中悄悄加规则后宣称该策略全部可视化。停止新增风险和核验未知结果优先于猜测补单。

## 6. 执行账本与恢复

源产生意图；目标负责持久提交、原生请求与回报关联。本次 replay 不联网、不撮合，也不替下一事件维护 orders/pendingIntents。账户决策视图必须同时读齐持仓、工作订单和本 run 未决账本，才能写 complete:true。

| 场景 | 应保留的事实 | 不允许的推断 |
| --- | --- | --- |
| 提交前失败 | 无原生发送证据 | 不能说已挂载或成交 |
| 发送后丢回执 | unknown 与原请求身份 | 不能换 operation ID 自动补单 |
| 部分成交 | 已成交量、剩余量及真实回报身份 | 不把已成交部分撤销成零 |
| 重复回报 | 相同原生回报只记一次 | 不重复增加持仓 |
| 撤单/成交竞态 | 查询最终订单和成交记录 | 撤单请求成功不等于未成交 |
| 重启 | 同源/参数/账户/run 的检查点及未决账本 | 不认领另一个 run 或旧账户请求 |

上述表是目标实现与故障测试要求，不意味着参考 replay 已实现原生持久执行器。recovery handler 目前只要求引用已声明输入；目标应说明其恢复输入映射，不能冒称通用类型证明。源身份、参数或翻译改变后不能继续使用不匹配的旧检查点。

## 7. 用分层证据验证

依次区分源检查、固定输入求值、翻译核对、原生回测、通道检查和实际运行。使用独立手算预期，不由被测翻译生成预期。至少覆盖预热、形成中柱、缺数、重复事件、未决 unknown、单位冲突和事件回滚。

保存完整 ArtifactRef、sourceDigest、固定输入/参数、目标 profile、翻译摘要、环境和每层验证结果。只允许真实运行采集的 DecisionTrace 解释成交路径；图布局、教学回放或 Agent 解说不属于成交证据。trace 中出现拟发 order 节点也不证明事务提交或发送。

## 8. 选择目标并写报告

从目录发现后端，读取目标的真实 profile、工具 schema 和 Skill，再检查事件、数值、数量单位、保护、归属与恢复支持。没有目标仍可交付 source/graph/replay；安装目标、准备依赖与实际交易是独立动作，不自动执行。

报告通过固定 DataRef、source/translation/result 和 RunRecord 引用展示事实。明确 demo、观测数据与推导数据，列出未支持和未观测范围。编译成功、回测盈利和真实成交分别陈述，不互相替代。
