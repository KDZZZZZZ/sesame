# 从研究规则到可核验策略

本参考区分三层：SVL 源语义、插件方法与执行账本、真实后端适配。它是工程检查表，不自行定义新 schema。没有安装交易后端时，仍可完成 source → graph → 固定事件 replay → 方法工作流 → 报告；真实模型判断使用独立的 strategy_decision 服务。以下章节是创作顺序，不要求源码照搬某个平台的模块或类。

## 1. 先把需求写成可以判断的规则

分别写出信号、进入条件、退出条件、持有期、数量、最大风险、停止条件和缺数行为。对于 PA、ICT、趋势等研究描述，把已经确认的定义和仍模糊的条件分开；不要让翻译器暗自补交易规则。每条规则应能指向一个源节点、状态或明确的目标限制。

采用小型事件状态机，还是信号 → 目标仓位 → 风险 → 执行的组合设计，由策略决定。图必须展示源码中实际存在的节点和边界，不能加一个“风控”标题代替缺失的风控逻辑。

## 2. 数据、时间和可用性

保留完整 InstrumentRef、来源/连接、价格口径、单位、周期、交易时段与调整方式。Bar 的时间是 openTime 和 endTime；Quote 是 time。来源墙钟保留 authority、zone、fold，不猜 UTC。事件 availableAt 表示可获知时间，不能替换柱区间。

M1 更新时，尚未闭合的 H1 柱不是“最后一根已闭合 H1”。预热不足、分页不完整、缺值或无法证明时间对齐时，保持 not_ready 或明确拒绝。跨输入 cross 必须有逐项可比时间；不能用数组长度、宿主收到消息的时间或自行合成的序号证明同步。

包内两个无时间价格样例只验证同输入教学逻辑。它们不证明市场顺序、交易所闭合、真实时序或完整防前视。真实适配应保存原始固定 DataRef，并明确窗口选择及何时可知。

## 3. 信号与有界状态

将纯计算和状态改变分开。明确一次信号何时生效、失效、允许再次触发。形成中柱修订不能无条件变成重复订单；同一事件重交与新的市场事件要有不同的真实身份。

先运行 close-threshold 源及四事件 fixture，手算 99/101/100 相对阈值 100 的结果；再运行 crossover 的单次入场语法。后者没有退出、保护或完整订单生命周期，不能直接当成完整交易策略。

## 4. 数量、资金分配与未决敞口

信号强弱、目标数量、当前持仓和未决敞口不是同一个值。每个数量保留 unit，每个金额保留 currency，每个价格保留 instrument。固定数量的示例是 100 share，不能静默改成 100 lot。

两资产各分配 5000 USD 的手算问题，还需要价格、汇率、合约乘数、步长、费用与购买力规则；这些输入缺失时不能从“50% 权重”直接生成数量。SVL 通用算术与集合原语可表达自定义计算，插件已提供 [methods.md](methods.md) 的动态品种池和等权/置信度/逆波动率分配器，通过 strategy_workflow 实际生成数量和现金余量。它是明确的线性估值与预算模型，不等于券商购买力、非线性衍生品或所有组合优化方法。Decimal 与量纲保持一致；信号失效、池中移除默认按明确 hold/flatten 政策处理，不隐式卖掉持仓。

## 5. 风险、退出和归属

写清最大敞口、剩余风险额度、保护的建立时机、部分成交后的保护数量与保护失败策略。order.submit 的 stopPrice 是 stop/stop_limit 订单触发价，不是市价入场自带的止损。软件在线检查与券商原生保护具有不同停机风险。

SVL 的基本 order.submit 不凭空获得原生父子关系，也不能凭 positionEffect:"close" 证明精确关闭某个套保持仓。插件 [execution.md](execution.md) 已实现独立的订单程序和账本：有界拆单、平旧仓后确认零持仓再反向开仓、按实际成交量激活/修改保护单、OCO 部分成交联动、保护失败处理。它输出明确命令，不保证券商原子保护；target 必须声明 native/software/unsupported，软件实现要有实际固定证据。精确 ticket/magic 归属、MT5 账户模式和原生请求映射由目标验证。无法无损表达时返回 unsupported/limited，不退化成裸单，也不能在翻译里悄悄加规则后宣称全部可视化。

插件组合风险已实现净值回撤、总/净敞口和分组上限，基础 pipeline 再与硬数量限额、Agent 意见合并。硬限制取更严值，Agent 无权放宽。风险退出保存 guard，旧信号不会在冷却结束后复活。请求的可用时间、模型版本、输入摘要、取消与迟到结果由 [agent-inputs.md](agent-inputs.md) 的独立服务记录。

## 6. 执行账本与恢复

源产生意图；目标负责持久提交、原生请求与回报关联。strategy_replay 只求值 SVL，既不撮合，也不替下一事件维护 orders/pendingIntents。strategy_workflow 的 executionReplay 则按明确事件维护订单、累计成交、净持仓、待决请求和 outbox，可保存 checkpoint 恢复；它仍不发送真实请求。账户决策视图必须同时读齐持仓、工作订单和本 run 未决账本，才能写 complete:true。

| 场景 | 应保留的事实 | 不允许的推断 |
| --- | --- | --- |
| 提交前失败 | 无原生发送证据 | 不能说已挂载或成交 |
| 发送后丢回执 | unknown 与原请求身份 | 不能换 operation ID 自动补单 |
| 部分成交 | 已成交量、剩余量及真实回报身份 | 不把已成交部分撤销成零 |
| 重复回报 | 相同原生回报只记一次 | 不重复增加持仓 |
| 撤单/成交竞态 | 查询最终订单和成交记录 | 撤单请求成功不等于未成交 |
| 重启 | 同源/参数/账户/run 的检查点及未决账本 | 不认领另一个 run 或旧账户请求 |

上述事实和状态转移已在插件执行账本中做固定事件测试；目标仍要提供真实回执、持久事务/outbox、原生查询和故障注入验证。恢复时活跃订单统一核对，旧待发送命令不盲重发；查不到未结单不足以证明请求失败，必须包含已结历史和完整成交明细。SVL recovery handler 的输入映射与 execution checkpoint 是不同层，不能冒称前者自动完成后者。源、账号、run、参数或翻译改变后不能继续使用不匹配的旧检查点。

## 7. 用分层证据验证

依次区分源检查、固定输入求值、翻译核对、原生回测、通道检查和实际运行。使用独立手算预期，不由被测翻译生成预期。至少覆盖预热、形成中柱、缺数、重复事件、未决 unknown、单位冲突和事件回滚。

保存完整 ArtifactRef、sourceDigest、固定输入/参数、目标 profile、翻译摘要、环境和每层验证结果。只允许真实运行采集的 DecisionTrace 解释成交路径；图布局、教学回放或 Agent 解说不属于成交证据。trace 中出现拟发 order 节点也不证明事务提交或发送。

## 8. 选择目标并写报告

从目录发现后端，读取目标的真实 profile、工具 schema 和 Skill，再检查事件、数值、数量单位、保护、归属与恢复支持。没有目标仍可交付 source/graph/replay/workflow；可先调用 strategy_functions 获取固定指标函数，strategy_decision 保存模型判断，再将冻结时间线接入方法工作流。安装目标、准备依赖与实际交易仍是独立动作。模型服务或本机桥启动不等于原生后端已经成功消费；目标必须对回放与实际运行给出各自证据。

报告通过固定 DataRef、source/translation/result 和 RunRecord 引用展示事实。明确 demo、观测数据与推导数据，列出未支持和未观测范围。编译成功、回测盈利和真实成交分别陈述，不互相替代。
