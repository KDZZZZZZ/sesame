# Native Tester path acceptance (MT5 1.1.4)

On 2026-10-09, MT5 build 6230 / Wine 10.0 / macOS arm64 failed to load a frozen EX5 at a 270-character Windows absolute path. The file existed before and after startup with identical 75,540 bytes and SHA256. Native diagnostics were `tester EX5 not found` / exit -1000012355. The same EX5 and native settings loaded successfully from a short dedicated directory, despite the same first-start MQL5 update/recompilation. This isolates the path issue; no speculative initialization prewarming is used.

Tester now uses a fresh private native temporary directory, rejects EX5 paths of 240 or more characters before launch, and records portable runner/expert paths, length, existing cache source, and EX5 hashes before/after startup. Only the selected broker symbol's existing history/ticks and symbol metadata are copied (ordinary copies, no shared writable links). Native MT5 may fetch missing data itself; a source/network failure remains a failure. The runner is deleted only after native process cleanup is confirmed; unconfirmed cleanup preserves it for diagnosis. The existing user terminal is never attached to or closed by this runner.

Actual full `Tester.execute` acceptance used the application's previously frozen Agent-authored EX5 unchanged and genuine history/tick cache from a successful dedicated Tester. It collected SDK result/equity/trace, checked actual inputs and unchanged EX5, and returned `succeeded`: net profit -0.26, one simulated trade, 14,163 equity rows, three deal rows and 13,653 trace rows. The native Job confirmed zero active processes and the owned runner was removed. A separate attempt during repeated broker disconnections failed with canceled tick download/no history; that is not counted as successful acceptance. No live mounting or broker orders occurred.

Offline ownership/cleanup tests and native dependency/platform regressions passed (14 tests). `tests/mt5-native-tester.test.js` provides opt-in repeatability using explicit local pass, connection and EX5 receipts; it never prints credential values. Windows/Linux native acceptance remains untested. Strategy profitability and semantic equivalence are outside this path fix.

To opt in, set `MT5AGENT_NATIVE_TESTER_TESTS=1`, `SESAME_TESTER_PASS_JSON` to the frozen native pass receipt, `SESAME_TESTER_CONNECTION_JSON` to a local MT5 connection configuration, and `SESAME_TESTER_EX5` to that pass's exact compiled binary. `SESAME_TESTER_CACHE_DIRECTORY` may identify an existing read-only MT5 data directory; only the requested broker/symbol caches are copied. Run `tests/mt5-native-tester.test.js` with the host SDK import hook. Never commit these local inputs or credentials. Live authorization inputs remain false and the test does not mount or open an EA on the user terminal.
