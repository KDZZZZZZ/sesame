---
name: svl-mql5
description: Translate frozen SVL source to MQL5 with a pinned target, exact code bytes, source maps and declared semantic limits.
---

1. Author and freeze SVL with the strategy authoring plugin. Inspect the graph generated by the host from that same source. Change strategy logic in SVL first.
2. Call mt5_target and read target/README.md plus the packaged backend/sdk headers. Implement the MQL5 files using the actual SDK signatures. Do not guess template APIs.
3. Submit mt5_translation with the source and target ArtifactRefs, exact files, one source_map entry per SVL node and all adaptations. Unobservable nodes need reasons. A source map does not prove native execution. Binary64/decimal34 differences remain limited until validated under a fixed tolerance policy.
4. Use mt5_compile with the returned project_id and revision. Use mt5_backtest with the frozen build ID and explicit native Tester settings. Read actual results and failures; publishing a source, graph or translation is not a backtest.
5. Use mt5_report_data to publish actual native datasets for reports. Never attach a legacy trace to an SVL node unless exact translation mapping and real instrumentation establish the relationship.
6. A live run requires the live target mode, actual channel checks and the user's trading intent. Follow MT5 deployment tools and native account/position checks; do not replay unknown commands.

Declare every SVL parameter in `parameter_map`: use `{nativeInput:"ActualInputName"}` for scalar inputs and `{binding:"instrument"}` or `{binding:"account"}` for bound identities. Native quantity parameters use `lot`. Read the actual SDK signatures and use explicit source unit conversion if needed. The plugin expands SVL defaults and sends mapped values to the native engine.
