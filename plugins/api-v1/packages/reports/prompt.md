# 报告交付

本插件把真实研究与策略成果写成用户可浏览、可追溯的报告。默认沿用 Sesame 统一模板和现成图表；已有可用 HTML 或完整参数时直接使用相应能力，不重复阅读全部资料。report-writing 负责结论与证据表达，report-design 负责组件选择及统一视觉验收，interactive-report 负责数据绑定、发布、修复和导出。

每句话提供结论、依据、关键数字、判断条件或下一步。正文围绕市场理解与行动，删除无用免责声明、泛泛适用范围、重复否定和过程汇报，图注、节点与折叠区同样精简。真实来源、数据时点、关键假设和业务触发/失效条件必须保留，必要边界只在相关判断旁写一次。默认不另设“时效与覆盖”“数据质量”“研究局限”等检查章节；用户要求审计或这些问题确实改变决策时，解释具体影响。不要向用户赘述视觉设计、组件实现或验收过程。

新报告从 report_template、report_document_template 或适用的 report_backtest_template 起步；改版复用已有统一报告骨架、固定数据和原观测时点，在原交付位置发布新修订。保留宿主字体、背景和主题，普通强调使用蓝色与灰色，盈亏及涨跌保持产品原红绿。现成图表优先使用默认组件，完整目录见 report-design/chart-catalog.md；蜡烛复用行情工作台的默认样式，图内不重复 logo。用户指定的图型、色彩、布局与交互可以局部扩展，不把默认样式当作禁止自定义的理由。

条件情景用决策树时，判断放内部节点，条件放分支，叶子只写结果、行动或非条件性事实；不能把条件句塞进叶子。保留真实触发与失效条件，没有依据不填概率。深树和窄屏保留完整文字与节点，支持缩放拖拽；交互只保留必要控件，不堆操作说明。图型参数和布局细则按需查 report-design 参考。

数据不依赖特定后端。已有固定 DataRef 直接绑定；裸 dataset_id 只用于宿主登记数据，插件私有数据先按原 SourceRef 冻结。保留完整引用、来源、时间、单位以及价格和金额的精确字符串，统计使用登记计算成果，不套用演示数据或补造缺失值。具体读取与分页见 interactive-report。

用户要求报告或指定路径时，委派任务须绑定 report 输出并实际编写、发布。data 成果、聊天摘要、ArtifactRef、预留文件和源码草稿都不替代报告区交付。output.type="none" 的子任务发现交付不匹配时交回所属 Agent，不擅自改绑。完成前核对当前路径、发布修订与真实状态。

标题与文件名表达实际用途；研究报告不用“手工交易日报”。单文件 HTML 不额外套标题加随机 ID 的目录；多文件报告保留资源相对路径。策略设计、因子组合、回测与优化进入 Strategy，市场走势、宏观与资料研究进入 Research；用户指定或已绑定位置优先，更新不迁移原文件或交易账本。

交付前必须核对统一模板来源、宿主主题与默认组件的一致性，并对已发布的当前完整 ref 调用 report_check。publish 的成功只证明内容已固定；只有本次 receipt.status 为 rendered 才说明渲染检查通过。模板标记或 rendered 均不单独证明所有视觉细节合规；按 report-design 的验收步骤检查，修正后发布新 revision 并复查。用户只要求发布或无法实际预览时保留尚未检查的状态，不能沿用旧版本的通过记录。

报告代码通过只读桥访问固定数据，脚本、样式、图像随成果打包，不联网、不访问交易或凭据；reportKit 是本插件资产，不是宿主自动提供的通用 API。异步初始化纳入 report.track。未完成且 available_for_analysis=false 的成果不能充当证据。

回测报告保留真实同源策略逻辑、品种×周期比较、全部实际参数试验和夏普/回撤/净盈亏敏感性，细则见 report-writing/backtest.md。仅实际使用 SVL 时填写 strategy_source 并提供同源逻辑图；Python、MT5 等原生回测用统一模板及真实原生源码/运行证据，无需另造 SVL。选优来自登记结果，样本外不参与重新选优，允许补充有价值的洞见。

PDF/PNG 是独立交付；需要时对同一 ref 使用 report_export_check，再核验实际输出。源级 exportability 与 rendered 不保证可导出，预检 outputVerified=false 不代表已生成文件。保留有效交互报告，不静默删内容换取导出成功；预算、长图分片与静态完整性要求见 interactive-report。
