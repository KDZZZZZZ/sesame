# Reports

把已有研究初稿编辑成读者容易理解的图文报告或回答组件，统一内容呈现、文字与视觉。调查、专业计算和研究判断由 Research 或对应专业能力负责。默认直接 components_show；不熟悉时按需 components_list / components_describe，components_validate 不是必经步骤。

完整报告提供 title、lead、highlights 和 content.sections。开头用一小段 lead 直接回答核心问题，随后以 1–6 项 {label,value,tone?} 展示最重要结果；结构入口为 report.highlights。主问题的完整回答及关键条件在开篇与首个相关正文中优先交代，再展开依据，不让读者读完背景和所有数据才找到答案。章节随用户问题组织，不编号、不套固定研究模板。target=answer 的独立组件不需要报告骨架。

采用“初稿 → 图文编辑 → 组件生成 → 核对”。visual-compose 在同一个图文编辑步骤内先安排全文骨架，再编排表达形式、编辑语言并通读成品。先明确主回答、支撑关系与实质反证，再选择章节和段落的顺序；原段落、表格和旧图都是可重组的素材，不按取数、计算或子 Agent 的工作顺序拼接。编辑目标是让文章更好理解，不是单纯缩短文字或增加图表。

表达形式服从信息关系：连续解释用段落，并列证据或选择用列表，横向逐项对照用表格，模式、分布与关系用图。一节涉及不同论证任务时，用简短小标题分层；不把不同主题压进长段，也不把连续推理拆成碎片列表。不规定这些形式的数量。金融术语保留，文字说明发生了什么、为何重要、哪些变化会调整判断。

围绕表达意图设计图的意义：每幅图服务一个清楚的阅读任务，让相关参照、差距、模式或异常可见。标题或已有标签点明有依据的重点，单位、范围和编码清楚，读者不必先读长文或心算才能理解。允许合并、替换或移除没有新增理解的图，明细可留在既有附件；不能借去重删掉尾部、分歧或反证。少量数字可直接写正文，不以字数、图数或覆盖率验收。解释用 paragraph/markdown，不在每图后重复附长图注或零碎小字。

需要逐层判断的分支用 chart.decision-tree，条件在分支、结果在叶子，保留阈值及且/或关系；少量平行情景可用紧凑表格或列表，简单单条件可一句话说明，事件日期按时间组织。用户明确指定的视觉实际使用对应组件。已有数字的简单差值、比例和单位转换可核对后用于表达；新统计或研究推断交回研究者。不能通过构图创造因果、概率或更强的结论。

图文编辑保留事实、数值、单位、口径、关键条件、反证与结论含义，标题、首屏和正文的判断强度及时点一致。会改变结论的未知影响就近交代一次；未核实材料、工作过程和通用提醒不逐项搬进成品，图中已有条件不再否定复述。重生成不锁旧章数、图数或原句；具体报错修复才局部调整。使用受控组件、固定数据和宿主发布链，修订沿用原报告及精确修订，不提交自由 HTML/CSS/JS。

交付前从读者角度通读：开篇能否回答主问题，层次是否便于理解与浏览，段落是否连贯，图文是否互补而不重复。调整实际问题并核对原意后发布，再检查当前修订的 report_check；渲染通过不代替编辑审查，导出另行确认。详见 visual-compose、references/text.md 与 report-delivery。
