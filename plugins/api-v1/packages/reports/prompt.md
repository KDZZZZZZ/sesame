# Reports

把已有文字和数据呈现为统一视觉的报告或回答组件。默认直接 components_show；不熟悉时按需 components_list / components_describe，components_validate 不是必经步骤。

完整报告必须使用三个结构：title 标题、lead 开篇回答、content.sections 正文章节。lead 用一小段直接回答用户最关心的问题，写已有关键结论和主要理由；渲染器把它放在标题后、章节前，不另加“摘要”标题。章节按实际问题命名，不编号、不套固定研究模板。target=answer 的独立回答组件不需要报告骨架。

只决定视觉、排版和交付，不选择研究方法或要求固定章节；调查与判断交给 Research 或对应专业能力。正文用 paragraph/markdown，图表只保留必要标题、轴、图例和数据标签，不另造小字说明。

先安排支撑结论的图表，再写必要解释。主要论据涉及比较、趋势、区间、分布、构成或关联时，必须使用对应视觉，不能只写数字段落或堆表格。合并回答同一问题的相关数据，再按关系选图：区间与参照用 range，变化与敏感性用 line，前后差距用 dumbbell，增减贡献用 waterfall，关联用 scatter，类别大小才用 bar/hbar；分布使用实际样本或已计算统计量。完整覆盖不等于一组一图，图型多样性来自数据关系，不设图表数量指标。单个数值用 metrics，精确查数用 table；概念解释不造数据凑图。不熟悉时查组件目录。图文同源，正文解释发现、原因和意义，不复述全组数字。

多个条件路径使用 chart.decision-tree：条件在分支，叶子只放结果；简单条件可一句话说明。用户点名图表、表格或决策树时实际使用对应组件。报告或回答中都可用 components_show；target=answer 直接嵌入回复，默认 report。发布前对照核心判断，确认支撑它的数据关系已实际画出，只有文字提到图表不算完成。

使用受控组件、固定数据和宿主发布链。修改沿用原报告及精确修订，不改原数字、来源或研究结论，不提交自由 HTML/CSS/JS。发布后核对当前修订的 report_check；导出另行确认。详细步骤见 visual-compose 与 report-delivery。
