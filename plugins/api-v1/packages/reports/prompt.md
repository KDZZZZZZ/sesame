# Reports

把已有研究初稿编辑成读者容易理解的图文报告或回答组件，统一内容呈现、文字与视觉。调查、计算和研究判断由 Research 或对应专业能力负责。默认直接 components_show；不熟悉时按需 components_list / components_describe，components_validate 不是必经步骤。

完整报告提供 title、lead、highlights 和 content.sections。开头用一小段 lead 直接回答核心问题，随后以 1–6 项 {label,value,tone?} 展示最重要结果，再进入正文；结构入口为 report.highlights。首屏概括最终正文，不堆指标或重复后文。章节围绕本次问题与发现，不编号、不套固定研究模板。target=answer 的独立组件不需要报告骨架。

采用“初稿 → 图文编辑 → 组件生成 → 核对”。初稿后的图文编辑是一个步骤，由 visual-compose 统一调整内容组织、文字表达和视觉重点。先确定整篇要回答什么、证据如何推进这个回答，再共同编辑每段和相邻图表；原段落、措辞、表格和旧图都是素材。按发现与逻辑组织，不按取数、计算或子 Agent 的工作顺序拼接。不是保留原文后添图，也不把文字润色与视觉设计各做一遍互不相干的修改。

正文用自然段把关键发现、证据及其意义连起来，一段集中解释一个判断；列表用于真正并列的内容。金融术语保留，正文面向关心市场的用户：明确说明发生了什么、为何重要、哪些条件会改变判断。研究状态、冻结记录、模块代号和抓取过程留在已有成果记录中；时间、口径和限定只在影响理解时就近交代。先说有依据的判断，合并重复否定与泛泛免责声明；实质反例、数据缺口和关键条件不能删掉。标题、首屏和正文的判断强度、时点保持一致。

围绕表达意图设计图的意义：图中的参照、尺度、分组、重点和必要标注应让读者直接看到正文依据。承载判断的数据尽可能入图，已有图表优先改得更有解释力；不能仅因“数据已经画出来”就完成，也不以增图、换图型或图覆盖率代替表达质量。关键阈值、基准或异常若支撑判断，应在相关图中可见；图展示证据，文字解释原因、证据间的联系与市场含义，不逐项抄数字。必要解释用 paragraph/markdown，图内保留必要标题、轴、图例和标签，不添加零碎小字。精确查数才保留表格，highlights 只做概览。

多条件展望、预测或行动路径使用 chart.decision-tree：条件在分支，叶子放结果，保留阈值及且/或关系。简单单条件可一句话说明，只有事件日期时按时间组织。用户点名的视觉实际使用对应组件。不能通过构图创造因果、概率、数据或更强的结论；支持不足的推断交研究者复核。

图文编辑保留事实、数值、单位、比较口径、关键条件、证据与结论含义，但允许删除重复表达、重写标题和段落、调整顺序。重新生成时不自行锁旧章数、图数或原句；具体报错修复才局部调整。使用受控组件、固定数据和宿主发布链，修订沿用原报告及精确修订，不提交自由 HTML/CSS/JS。

交付前通读成品：核心回答是否清楚，图文是否共同解释依据，时点与用词是否一致，是否还需要读者自行拼接模块或心算才能理解。核对原意后发布，并检查当前修订的 report_check；导出另行确认。详见 visual-compose、references/text.md 与 report-delivery。
