# 首屏直接给结果

先看 `report_structure.first_screen_fields`。全部适用问题在报告开头直接回答，具体表达方式参考 TC：方向几个字，价位/收益/次数给数字，理由一句，持仓/日历用短表。模板与长度建议可按用户要求调整；分析方法完全独立。

使用 `content.kind:"document"` 和 `content.overview`。首屏只有标题、一行结论、短结果以及确有必要的一张内置图。`summary` 是列表摘要，渲染器不再重复显示；正文从依据开始，不再写开场总结。

```json
{
  "kind": "document",
  "overview": {
    "conclusion": "合成示例：短期偏强，长期仍在震荡。",
    "facts": [
      { "label": "短期走势", "value": "偏强", "format": "phrase" },
      { "label": "中期走势", "value": "震荡", "format": "phrase" },
      { "label": "长期走势", "value": "震荡", "format": "phrase" }
    ]
  },
  "sections": [{ "title": "支持判断的依据", "blocks": [] }]
}
```

- `conclusion`：中文建议一行、32字内，上限48字。直接说更支持什么。
- `meta`：共享的资产代码、日期、期限只写一次，不占一排结果格。中文上限80字，通常20–40字足够。
- `facts`：最多18项。每项 `label/value/format`；`phrase` 用短词（中文上限16字），`number` 放原始数字/范围（36字），`sentence` 一句话（48字）。不为填满网格加内容。
- `note`：通常省略；只有缺少它会误解结果时才放一句短注，中文上限32字。来源、方法解释和完整限制下移。金融场景名词可以保留，别硬翻译成更长的标题。
- `tone`：盈亏/涨跌等按真实符号使用 `positive/negative`；回撤、波动和一般比较不染红绿。样式不改变数字或推断方向。
- `table`：与普通表同样的 `columns/rows/caption?/column_tones?`，最多7列6行。持仓每资产一行，日历每事件一行；更多条目保留在后文。窄屏自动按行展开，所有值仍可见。
- `chart`：一个现有 `type:"chart"` 内容块，数据与普通图完全相同；高度180–280，默认200。价格路径、期权损益等有必要就直接放图，完整图在正文只保留一次。不要为了装饰添加图或重复综合情景树。
- 渲染器自动提供“详细分析”入口；不要把导航当一个结果卡片。无数据写“未取得”或“未估算”，不伪造分数或概率，不把“中性”当缺失。

R01–R11 及 X03/X04 相近参考的完整映射见 `templates/first-screen-plans.json`。`tc_fields/question_refs/sesame_fields` 只供 Agent 核对，用户看普通标签和结果。合并重复问题时仍要回答它们的原意；例如资产类别分散不能替代行业分散，公允价值不能替代价值投资特征。

保留回撤、年化收益、估值、期权。删掉首屏的 AUC、isotonic、前推、检验期增量等研究语言；这些原始指标可留在末尾。不要自动把历史频率改名成当前概率，也不要把回撤写成本金亏损。
