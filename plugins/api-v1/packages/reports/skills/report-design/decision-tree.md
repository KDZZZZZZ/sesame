# 条件情景决策树

用 `decision-tree` 把判断条件、分支和最终结果表达为树结构。适合报告结尾已有依据的条件情景，尤其适合没有可辩护概率的探索性研究。节点大小和线宽都不表示概率、收益或置信度。

综合报告先在树前的判断或 `takeaway` 里说清当前更倾向哪种情景，再用树回答什么变化会维持、推翻或切换这一判断。各结果给出明确倾向，不能只并列多空可能，或用“检查资料 → 等待结果”的流程代替行情情景。回顾报告只判断对应历史期间，不冒充当前预测；资料审查任务才使用资料检查树。

先保留原文的边界：只有材料明确记录的条件才进入树。节点或分支缺少依据时，在相应说明里写清缺少什么，不编造数值、价格或补出一个看似完整的分支。如果路径有多个入口、汇合、循环或时间回访，采用流程图、关系图或分开的情景说明，不强塞成树。

## 先把逻辑建成树

- 内部节点提出一个判断，分支写该判断的结果或进入条件。连续确认拆成连续节点；“并且”用逐层通过表达，“或者”用不同分支表达。
- **叶子只写最终判断、行动或待补信息。** 叶子的 `label` 和 `detail` 不再出现“如果、若、否则、仅当、才、失效条件”等尚待判断的逻辑。需要进一步确认、判断失效或切换路径，就新增内部节点和对应分支，不能把整段条件说明塞进叶子。
- 目标、参考值、来源、非条件性限制可以保留在叶子。例如“观察下一阻力”是行动；“突破后才观察下一阻力”需要先建一个突破判断节点。
- 尚未确认的路径落到明确的“等待确认”或“补齐资料”叶子。条件未知不等于条件不成立，不为补齐树形虚构证据、互斥关系或概率。
- 沿任一根到叶子的路径，应能从节点和分支直接读出完整判断过程，无需再解析叶子中的条件句。失效判断同样进入树结构；原表中的条件和边界保留供核对。

## 数据与调用

在 `document` 中使用下面的 `chart` 内容块；Report 自动加载本地图形和交互。真实报告的节点来自固定研究依据，或用户明确给出的条件，不上传 HTML 或回调。下例全部为组件演示，所在发布请求应标 `provenance_kind: "demo"`。

```json
{
  "type": "chart",
  "kind": "decision-tree",
  "title": "演示 · 后续收盘如何改变判断",
  "columns": ["id", "parentId", "label", "condition", "detail"],
  "options": {"height": 360},
  "rows": [
    {"id": "start", "parentId": null, "label": "下一次日收盘在哪里？", "detail": "演示当前收盘为 100；每次日收盘重新判断。"},
    {"id": "range", "parentId": "start", "condition": "95–105（含边界）", "label": "更倾向区间震荡", "detail": "区间内暂未出现单边突破。"},
    {"id": "up", "parentId": "start", "condition": "高于 105", "label": "转为偏强", "detail": "退出区间判断，关注上行能否延续。"},
    {"id": "down", "parentId": "start", "condition": "低于 95", "label": "转为偏弱", "detail": "退出区间判断，下行风险上升。"}
  ],
  "takeaway": "演示当前更倾向区间震荡；日收盘越界后切换判断，回到区间则撤回单边倾向。",
  "source_note": "全部数值和判断仅演示内容形式，不是实际行情、指定分析方法或概率估计。"
}
```

默认字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 唯一节点 ID。 |
| `parentId` | 父节点 ID。全树只有一个根，根写 `null`。输入行顺序决定同级分支顺序。 |
| `label` | 内部节点写判断问题；叶子写最终结果或动作。 |
| `condition` | 可选。进入本节点的分支条件，显示在连线上，独立换行。 |
| `detail` | 可选。补充证据、目标值、来源或非条件性说明。叶子中不再嵌套条件逻辑；可换行，不截断全文。 |

已有数据使用别的列名时，在 `options` 中传 `id`、`parent`、`label`、`condition`、`detail` 来映射。例如 `parent: 'previous_node'`、`condition: 'trigger_text'`。节点没有数量字段，也不需要人为赋权。

`options.height` 是可选的交互视口高度。它不删减节点或改变树的布局。作者提供完整节点和映射，Report 负责选择联动、缩放与资源释放。

## 布局与视觉

- 只使用紧凑的从左到右树形布局。小屏、长文字或较矮图幅都不切换为缩进列表；通过缩放、拖动和“显示全貌”查看同一棵树。内部判断用细竖标记，叶子用小圆点，分支条件与结果分开呈现。
- 中文、英文、长标识符和显式换行都参与换行和布局计算；分支条件独立保留空间，节点与连线不穿过文字。完整文字直接呈现，不以截断或删节点换取紧凑。
- 首次展示适配全部节点。视口内可用滚轮缩放、指针拖拽，触屏可捏合缩放和平移；仅保留小型放大、缩小、适配全图图标。双击恢复实际尺寸，键盘 `1` 恢复实际尺寸、`0` 适配全图，方向键平移。控件名称由 `title` / `aria-label` 提供，不额外添加操作说明、缩放百分比、重复路径摘要或配置栏。
- 沿用 Report 的背景、文字、强调色、分隔线与字体。背景保持现有报告颜色，不引入独立底色、渐变、阴影或一套情景彩虹色。分支连线使用灰色参照，保证与实际背景至少 3:1 的图形对比度；选中节点时，以蓝色强调从根到该节点的整条路径。
- 点击节点，或键盘聚焦后按 Enter / 空格，可选中原始行；拖拽用于移动视口，不触发行选择。图中保留全部文字；悬浮提示不是阅读完整结论的唯一入口。
- 打印时清除交互缩放和平移，按完整树展开并隐藏控件。PNG 导出重新挂载报告，使用初始适配全图的概览，不继承正在浏览的缩放位置。静态文件不能拖拽放大；超过可读页面预算的大树应拆为几个有意义的情景章节，并检查实际 PDF / PNG 的文字大小。

发布前同时检查桌面与窄屏的缩放、拖拽和复位，核对当前倾向是否明确、条件是否由判断节点和分支完整表达、叶子是否只剩明确结果或行动、原有触发与失效边界是否保留。不要把尚未发生的情景写成已经证实的结论。相同原始节点数据由 Report 放在末尾附录，便于查阅；不用重复在正文再放一份原始表。
