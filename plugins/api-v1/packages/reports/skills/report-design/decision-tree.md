# 条件情景决策树

用 `decision-tree` 把判断条件、分支和最终结果表达为树结构。适合报告结尾已有依据的条件情景，尤其适合没有可辩护概率的探索性研究。节点大小和线宽都不表示概率、收益或置信度。

先保留原文的边界：只有材料明确记录的条件才进入树。节点或分支缺少依据时，在相应说明里写清缺少什么，不编造数值、价格或补出一个看似完整的分支。如果路径有多个入口、汇合、循环或时间回访，采用流程图、关系图或分开的情景说明，不强塞成树。

## 先把逻辑建成树

- 内部节点提出一个判断，分支写该判断的结果或进入条件。连续确认拆成连续节点；“并且”用逐层通过表达，“或者”用不同分支表达。
- **叶子只写最终判断、行动或待补信息。** 叶子的 `label` 和 `detail` 不再出现“如果、若、否则、仅当、才、失效条件”等尚待判断的逻辑。需要进一步确认、判断失效或切换路径，就新增内部节点和对应分支，不能把整段条件说明塞进叶子。
- 目标、参考值、来源、非条件性限制可以保留在叶子。例如“观察下一阻力”是行动；“突破后才观察下一阻力”需要先建一个突破判断节点。
- 尚未确认的路径落到明确的“等待确认”或“补齐资料”叶子。条件未知不等于条件不成立，不为补齐树形虚构证据、互斥关系或概率。
- 沿任一根到叶子的路径，应能从节点和分支直接读出完整判断过程，无需再解析叶子中的条件句。失效判断同样进入树结构；原表中的条件和边界保留供核对。

## 数据与调用

先加载 `assets/editorial-charts.js`，再加载 `assets/charts-decision.js`。数据与其他图表一样来自固定报告数据，或者明确写在报告中的固定条件节点。

```js
const tree = SesameCharts.chart('#scenario-tree', {
  kind: 'decision-tree',
  title: '演示：资料核验路径',
  height: 480, // 可选：交互视口高度，不限制完整树的布局尺寸。
  // 仅为组件演示，不是市场研究数据或投资建议。
  rows: [
    { id: 'start', parentId: null, label: '原文与引用是否一致？', detail: '以原始材料与记录的时间为准。' },
    { id: 'matched', parentId: 'start', condition: '一致', label: '时间、样本和定义是否一致？' },
    { id: 'mismatch', parentId: 'start', condition: '不一致', label: '返回核对引用', detail: '保留原文与引用的差异记录。' },
    { id: 'missing', parentId: 'start', condition: '原文无法追溯', label: '暂停使用该结论', detail: '待补材料：可追溯的原始来源。' },
    { id: 'usable', parentId: 'matched', condition: '一致', label: '保留为本阶段证据', detail: '附来源版本及适用范围。' },
    { id: 'bounds', parentId: 'matched', condition: '不一致', label: '修正引用范围，重新核验', detail: '记录已查明的时间、样本及定义差异。' },
  ],
  onSelect(row, index) { /* 联动原始证据表；返回原行及原索引。 */ },
});
// 清理时使用 tree.destroy()，或统一 SesameCharts.destroy(reportRoot)。
```

默认字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 唯一节点 ID。 |
| `parentId` | 父节点 ID。全树只有一个根，根写 `null`。输入行顺序决定同级分支顺序。 |
| `label` | 内部节点写判断问题；叶子写最终结果或动作。 |
| `condition` | 可选。进入本节点的分支条件，显示在连线上，独立换行。 |
| `detail` | 可选。补充证据、目标值、来源或非条件性说明。叶子中不再嵌套条件逻辑；可换行，不截断全文。 |

已有数据使用别的列名时，可传 `id`、`parent`、`label`、`condition`、`detail` 来映射。例如 `parent: 'previous_node'`、`condition: 'trigger_text'`。节点没有数量字段，也不需要人为赋权。

`height` 是可选的交互视口高度，默认 `480` px；沿用图表核心允许的 `120…12000` px 范围。它不删减节点或限制树的实际宽高。现有 `rows`、字段映射、`onSelect(row,index)` 和 `chartselect` 事件保持不变。

## 布局与视觉

- 所有屏幕与层级都使用紧凑的从左到右布局：内部判断用细竖标记，叶子用小圆点，细灰曲线连接分支。深树和窄屏通过缩放、拖拽阅读，保留全部节点与同级顺序。
- 中文、英文、长标识符和显式换行都参与换行和布局计算；分支条件独立保留空间，节点与连线不穿过文字。完整文字直接呈现，不以截断或删节点换取紧凑。
- 首次展示适配全部节点。视口内可用滚轮缩放、指针拖拽，触屏可捏合缩放和平移；仅保留小型放大、缩小、适配全图图标。双击恢复实际尺寸，键盘 `1` 恢复实际尺寸、`0` 适配全图，方向键平移。控件名称由 `title` / `aria-label` 提供，不额外添加操作说明、缩放百分比、重复路径摘要或配置栏。
- 沿用报告的 `--report-paper`、`--report-ink`、`--report-muted`、`--report-accent`、`--report-line` 和字体。背景保持现有报告颜色，不引入独立底色、渐变、阴影或一套情景彩虹色。分支连线使用 `--report-context`（缺省回退 `--report-muted`），保证与实际背景至少 3:1 的图形对比度；选中节点时，以蓝色强调从根到该节点的整条路径。
- 点击节点，或键盘聚焦后按 Enter / 空格，可选中原始行；拖拽用于移动视口，不触发行选择。图中保留全部文字；悬浮提示不是阅读完整结论的唯一入口。
- 打印时清除交互缩放和平移，按完整树展开并隐藏控件。PNG 导出重新挂载报告，使用初始适配全图的概览，不继承正在浏览的缩放位置。静态文件不能拖拽放大；超过可读页面预算的大树应拆为几个有意义的情景章节，并检查实际 PDF / PNG 的文字大小。

发布前同时检查桌面与窄屏的缩放、拖拽和复位，核对条件是否由判断节点和分支完整表达、叶子是否只剩结果或行动、原有触发与失效边界是否保留。不要把尚未发生的情景写成已经证实的结论。保留一份相同数据的表格，方便查阅和选择联动。
