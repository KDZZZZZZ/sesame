---
name: visual-compose
description: 将研究初稿统一做图文编辑，结合内容组织、自然叙述与视觉重点，在原意不变的前提下形成易读的报告。
---

1. 读取初稿和固定证据，确认用户问题、主回答、关键发现、数字、单位、口径、时点与改变判断的条件。初稿可以是研究结果、已有报告或用户材料，不要求先写长文。区分必须保留的事实与判断、可重写的表述、只需留在成果记录中的工作过程；仅改呈现时复用研究。
2. **统一做图文编辑。** 内容组织、文字润色和视觉设计在这一步共同完成，不把它们拆成互不相干的输出。先安排整篇回答的推进顺序，再逐段考虑“读者要理解什么、证据是什么、图文怎样合力讲清楚”。内部大纲服务编辑，不成为成品中的字段或章节。
   - **组织内容。** 按本次问题与发现展开，合并重复背景、来源、同类证据和子研究结论。段落之间说明支持、补充、转折或条件关系；已有顺序合适就保留，不为改版强行重排。章节标题点明问题或有依据的发现，不能比正文更确定，也不能把历史解释写成当前已确认状态。
   - **重写文字。** 一段围绕一个判断，用清楚的主题句、关键证据和必要的意义解释自然展开，不机械套三句模板。术语精确、语气直接；先表达成立的判断，再就近交代会改变理解的条件。合并反复的“不是／不能／未核实”等防御性说明，保留实质反例与未知的影响。内部代号、冻结状态、工具和取数步骤不进入正文；时间精度以判断所需为准，完整记录仍留在固定证据中。正反例与文字位置见 references/text.md。
   - **设计图的意义。** 图要把本段判断的依据画清楚：相关参照、阈值、变化、异常及分组在同一视觉里能看懂，不能藏在图外文字中。优先改进已有图的重点、尺度和组合，不以新增数量验收。图展示实际数据，正文解释为何重要、证据如何共同作用，不逐点复述。一个意图可由图文共同完成，不强制一段一图。能用标签表达的关键差值无需再堆一张图；不同单位不得强放同轴。组件选择与已有标注能力见 references/composing.md。
   - 多条条件路径使用 decision-tree，分支保留阈值、时间及且/或关系，叶子只写结果；只有日期按时间组织。解释不能用箭头把相关画成因果，历史频数不能借图变成未来概率。缺事实或计算交回研究者，不为编辑补造结果。
3. 将编辑结果映射到组件。完整报告提供 title、lead、highlights 和非空 content.sections，便捷形式同样提供前三项。最后根据完成的正文校准开篇回答和 1–6 项关键结果；首屏概览不代替证据图。解释只放 paragraph/markdown，图里留必要标题、轴、图例与数据标签；不加零碎小字、编号章节或固定附录。数据用实际 rows 或固定 data_id。target=answer 的独立组件不需要报告骨架。不熟悉组件时查 components_list / components_describe。
4. 通读成品并对照原稿，完成同一次图文编辑的复核：用户能否沿图文理解主回答及依据？图的重点是否覆盖它实际要说明的判断？是否还有重复数值、过程自述、空泛总结或断开的模块？调整这些表达问题，再核对数字、单位、证据时点、反例、条件和结论强度。读起来流畅与原意准确要同时满足；不按图数、禁词数或句长打分。
5. components_show 一次展示，默认 report，target=answer 用于对话内组件；需要先查格式时用 components_validate。发布和当前修订检查见 report-delivery，格式或渲染通过不代表内容编辑已经达标。

重新生成或改版时复用事实与数据，不默认保留原句、旧章节数、图数或版式；委派只传表达目标和必须保留的证据边界。只有修复具体报错时局部调整对应字段。图文编辑记录留在工作中，不写成用户报告的“编辑过程”章节。
