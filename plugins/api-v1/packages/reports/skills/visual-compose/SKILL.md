---
name: visual-compose
description: 将研究初稿统一做图文编辑，按用户问题组织全文，结合信息层次、自然叙述与图表重点，形成原意准确的文章。
---

1. 读取初稿和固定证据，确认用户问题、主回答、关键发现、数字、单位、口径、时点与改变判断的条件。初稿可以是研究结果、已有报告或用户材料，不要求先写长文。区分必须保留的事实与判断、可重写的表述、只需留在成果记录中的工作过程；仅改呈现时复用研究。
2. **统一做图文编辑。** 以下是同一个编辑步骤内的工作，不新增阶段任务、独立交付或模板字段。
   - **全文组织。** 先在内部排出主回答、关键论点、支撑与反驳关系，再安排阅读顺序。用户最关心的问题及必要条件在开篇和紧接的正文中交代完整，背景与详细验证随后解释依据；不能只在 lead 给方向，再把判断条件放到全文末尾。问前景就优先讲前景与改判条件，问原因就优先解释主要机制，不按研究执行顺序拼接。大纲服务编辑，不成为报告的“编辑计划”。
   - **内容编排。** 按论证任务划分章节与必要的小标题；连续解释用段落，并列证据用列表，平行情景或多项精确对照用表格，模式、分布、变化与关系用图。不要把不同任务挤进长段，或为了形式数量切碎推理。每幅图要增加理解，允许合并、替换或删除冗余图；尾部、分歧和反证仍需可见。标题或已有标记点明图的重点，单位、参照和尺度清楚。递进分支用 decision-tree，简单条件用更紧凑的形式；用户指定的视觉优先。具体组件与层次写法见 references/composing.md。
   - **语言编辑。** 用主题句、证据与必要解释展开一个判断，并说明它与相邻论点的关系，不机械套三句模板。保留金融术语，减少抽象短语和重复数字；目标是清楚，不是越短越好。已有条件写成可观察的变化及对应判断，保留会改变结论的缺口、反证和时点；其余核查过程和通用提醒不自动进入正文或附录。正反例与文字位置见 references/text.md。
   - **成品审读。** 从头连读一次重编的文章：只读开头是否知道主回答和关键条件？浏览小标题能否分清不同论证？段落与图是否共同推进结论，还是重复或彼此脱节？若移走某图，是否丢失实际证据而非只少一张图？据此重排、合并或补足解释，不以字数、图数、小标题或列表数量打分。
3. 将编辑结果映射到组件。完整报告提供 title、lead、highlights 和非空 content.sections，便捷形式同样提供前三项。最后根据正文校准开篇回答和 1–6 项关键结果，避免一段摘要替代完整回答。章节内小标题与列表可用 markdown，解释用 paragraph/markdown；图里留必要标题、轴、图例与数据标签，不另堆长图注。不要编号章节或增设固定附录。数据用实际 rows 或固定 data_id。target=answer 的独立组件不需要报告骨架。不熟悉组件时查 components_list / components_describe。
4. 对照原稿核对事实、数值、单位、证据时点、实质反例与结论强度。保留分支阈值、时间及且/或关系；条件未满足不能写成已发生，相关与历史频数不能变成因果与未来概率。已有数字的简单差值、比例和单位转换可核对后用于标题或标签；新统计、归因或预测交回研究者，不为编辑补造结果。表达流畅与原意准确要同时满足。
5. components_show 一次展示，默认 report，target=answer 用于对话内组件；需要先查格式时用 components_validate。发布和当前修订检查见 report-delivery，格式或渲染通过不代表内容编辑已经达标。

重新生成或改版时复用事实与数据，不默认保留原句、旧章节数、图数或版式；委派只传表达目标和必须保留的证据边界。只有修复具体报错时局部调整对应字段。图文编辑记录留在工作中，不写成用户报告的“编辑过程”章节。
