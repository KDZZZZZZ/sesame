---
name: visual-compose
description: 从表达意图设计初稿，在原意不变的前提下尽可能把数据组织成直观图表。
---

1. 读初稿和固定数据，标明必须保留的判断、数字、单位、比较口径、关键条件、时间范围及来源。这里的初稿可以是研究结果、已有报告或用户材料；不必先写完整长文。仅改呈现时复用既有研究。
2. **按表达意图做视觉设计。** 逐段读初稿，先写清“这一段要让用户看懂或判断什么”，再确定用哪些数据、参照、分组和重点让这个意思一眼可见。将正文、表格、指标和旧图中的数据一并纳入，尽可能设计成图表；不先按数据关系筛选哪些才值得画图。内部安排为“表达意图 → 数据与参照 → 视觉构图和重点 → 必要解释”，先定内容分工与阅读顺序，再选具体组件。设计过程不搬进报告，例子见 references/composing.md。
3. 围绕意图重设计旧图、合并相关数据、增加必要标注或选新图型；不能因为数据已经在某张图或表里就跳过设计。读者应直接看出所强调的幅度、位置、差异、占比、分布或转折，不用自己逐点查数再心算。图型是实现意图的手段：区间端点与参照可用 range，前后差距用 dumbbell，有序变化用 line，增减贡献用 waterfall，关联用 scatter，类别大小用 bar/hbar；不默认一指标一图，也不为凑种类换图。不熟悉时查 components_list / components_describe。
   原值与变化率、基准与目标尽量结合到同一视觉的必要标签中，避免正文再抄数字。单位不同且必须对照时用共享顺序的并排小图，明确各自尺度；不能强放同轴。保留精确查数确实更方便的表格，孤立数值优先考虑能否成为已有图的参照或标注，不为缺少参照的事实编造图形。
   展望、预测和行动判断存在多条条件路径时用 decision-tree，分支保留完整条件、阈值及其组合关系，叶子只写结果，不用表格或段落代替树。仅有事件日期时按时间组织；简单单条件可一句话说明。
4. 完整报告一次提供 title、lead、highlights 和 content.sections；component/components 便捷形式同样提供前三项。lead 直接回答问题；highlights 在正文前用 1–6 个 {label,value,tone?} 提炼最重要结果，定性判断也可用，不凑满项目、不加入泛泛免责声明。首屏结果栏承担概览，正文主要证据仍需对应图表。正文按本次问题展开，无编号、无固定业务章节；target=answer 的独立组件不需要报告骨架。图表与解释相邻，正文补充发现、原因和意义，不复述整张图。说明只放 paragraph/markdown，图内只留简短必要标签，不把冗余数字串挤进标题。数据用实际 rows 或已声明固定 data_id，图文同源。
5. components_show 一次展示；target=answer 用于对话内组件，默认 report。需要先检查时用 components_validate。
6. 重新生成、改版或使用新版组件时，基于既有证据重新做视觉设计；除用户明确要求保留，旧章节、图表数量、版式和段落均可重组。委派目标应保留研究含义并改善表达，不得自行追加“保留旧图数、只适配 schema”等限制。只有修复具体报错时才最小调整对应字段或布局。缺少分析交回生产者，不在视觉层补算或虚构。

完成：逐段核对表达意图和原意。用户能否直接从图中看懂这一段想说明什么？仍在文字或表格中的数据，能否入图、并图或成为标注而更容易理解？可以就完成转换，不能把“已有图”“原配置未改”或“渲染通过”当作完成证据。首屏结果简明，多条件路径已画成树，正文留下发现、原因与意义。合并重复图，不按张数验收；完整表达不要求每组数字独立成图。核对数字、单位、基准、端点、关键条件和时间，区间不伪装类别，敏感性保留既定输入条件。数据见 references/data-binding.md，交互见 interactions.md，文字见 text.md。
