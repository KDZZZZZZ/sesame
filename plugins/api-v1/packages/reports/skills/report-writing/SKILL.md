name: report-writing
description: 把分析结果写成有用、可核对的结论：先回答问题，再给关键证据与下一步，必要边界贴近对应判断；编写报告文字时使用。
---

研究开始先读 [以判断主导研究和报告](judgment-first.md)，明确用户需要判断什么、从哪些角度，再安排取证、分析和正文。图和事实用于回答这些问题，不能代替判断。

读者需要先知道三件事：结论是什么、有什么依据、下一步观察或行动什么。把已登记数据转成可核对的判断，不复述分析过程。先读取 `host_reports_describe`；宿主选中本插件时，用 `host_reports_publish` 的 `input.content` 和可选用户 `input.style` 呈现。`report_publish` 只是默认内容的便利转接，不覆盖宿主提供者；`document.sections` 可组合判断、图表和简短推理，不以业务模板限制表达。组件见 [report-design](../report-design/components.md)。

正文保留结论、关键证据和必要表格。完整原始 JSON、大结果和执行回执保留为可追溯的固定数据引用或证据附件，在末尾 `details` 附录中标明对应来源；同一份完整回执不在多个章节重复嵌入。读者应能沿引用核对全部细节；数据引用不代替报告本身的编写与发布。

需要下载完整文件时，在 `input.assets` 声明真实附件，用末尾 `attachments` 块的 `items: [{label,path,description?}]` 链接同一路径；不要用 Markdown 相对链接。文件与数值保持原字节，组件仅生成可点击的附件入口；路径和格式边界见[组件说明](../report-design/components.md)。

每句话都要提供结论、依据、关键数字、判断条件或下一步。正文、图注、元信息、节点说明和折叠区一起精简：删除模板化免责声明、泛泛适用范围、无意义的否定和自我辩护，无用文字直接删除。必要边界写成具体事实、对当前判断的影响或还需观察什么，保留真实来源与条件，不用空泛套话代替信息。

## 每个字段写什么

用户需要回答的分析问题应有明确结论或倾向。已有清晰结论直接保留，只补缺失的必要结论，让原来的分析与图表围绕它展开；不能只有数据、两面可能、否定或“继续观察”。相邻字段可共用判断、对象和期限，不逐项填满一套栏目。日期、来源等背景事实保持原义，不为每个数字另造预测。信息不全时先说已能支持的判断及范围，再说明具体未知；不硬编方向，不用“中性”填空。定性倾向与置信度分开，预测概率仍须有对应历史统计。

因果和规律的判断先回答“什么关系更可能成立、为什么、何时成立”。未严格证明因果不等于没有因果，无法推广到所有环境不等于规律无用；用实际机制、时间顺序、同类历史和替代解释支持最合理的解释，说明影响范围与改判依据。不要以“不能归因”“相关不等于因果”结束分析，也不把相关性或未经验证的机制夸大成已证实因果。

判断随问题变化：行情说方向，比较说强弱，估值说相对贵便宜，风险说主要风险在哪里，因子说何时可用、何时停用。因子可以有条件使用，不以通过全部检验为前提。判断如何得出仍由实际研究方法决定，报告只规定应把结果说清。

需求宽泛或符合常见研究主题时，可用 `report_structure` 选择独立模块或组合。19 个模块、11 个组合、字段类型、用户覆盖与方法结果绑定见 [module-templates.md](module-templates.md)。模板是建议：用户给出的章节和字段清单覆盖默认值，不补回已删除内容；具体理论与分析方法由用户或编排选择。以 `content.kind: "modules"` 呈现其固定结果；`report_compose` 仅作预览。历史依据与置信度保留真实语义和验证状态。用户指定的方法无法提供某字段时说明缺口，不换成默认算法。

优先以模块的内置图表字段呈现关键证据，图型与输入见 [模块可视化](../report-design/module-visuals.md)。置信度绑定历史可比情景和实际后续结果；各项推断独立记录匹配规则、样本与验证状态，综合判断另有历史依据。没有相应结果就标明未支持，不把主观自评分、历史频率和已校准概率混为一谈。

逐字段含义、单位/时间与解释边界见 [字段指导](field-guide.md)，先读取 `report_structure` 所选字段的 `agent_guidance`。[技术研究结果形式](technical-research.md)承接不同方法给出的特征、状态和历史参照；Report 不指定指标或发起方法扫描。知识机制与历史统计的已有对照保持可读。未覆盖任务允许自由拼接/自建字段，不以目录限制独立研究侧的方法选择。来源分类与插件覆盖仅供内部核查，不显示给报告读者。

组合报告把最终判断与历史验证分开：开头给结果与依据摘要，历史章节给样本概览、主要对照图和逐项判断，完整样本放末尾附录，最后用一个综合情景树收束条件与后续观察。避免在多个章节重画相同情景或重复展开同一批历史证据。置信度的 assessment 只补充有信息量的解释；验证状态归入对应证据信息，不填充有关模型打分方式的说明。

- `judgment.text`：对象 + 明确判断或倾向 + 关键依据，一句话只有一个判断。例如「该策略验证期表现偏弱，净亏损 9.49 USD（−0.09%）」。数值本身不代替判断，不写研究执行过程。
- `judgment.note`：可选，补充关键依据或影响使用的一项条件，不为填字段强加限制。
- `sections[].title`：尽量直接表达本节结论，例如「验证期仍亏损」；已有清晰标题不必为了形式重写。
- `chart.takeaway`：用图上可见的比较支撑判断；标题已说明结论时只补有用理由，不再复述，不写「下图展示了……」。
- `metrics.items[].label/value/note`：简短名称、原结果及单位；分析性数字的 note 说明它支持什么判断，口径只保留必要信息，相邻指标可由同一句判断概括。
- `reasoning.steps`：可核查的观察、推导和历史对照摘要；`conclusion` 或对应 `claim` 明确当前倾向，有冲突时说清目前哪边更有依据，避免重复摘要和图注。
- `details`：完整方法、参数、来源、样本、版本与文件信息，统一放末尾附录。影响决策的适用、失效、监控或停用条件仍在正文说明。
- `formula.latex`：需要表达的公式，交由 Report 渲染；不以英文函数串替代公式。

## 数字

- 每个数字都来自固定研究结果：用模块结果绑定或 `chart.data_id` 引用固定 DataRef，也可呈现已提供且来源明确的结果。数据读取和分页由 Report 处理，不写页面脚本。展示格式化不改变源精度，不手写或重新计算研究统计。
- 带单位和比较对象：「比 B 组高 2.17」，而不是「较高」；区分收益率与百分点差。
- 同一指标全文同名、同精度、同单位，以第一次出现的名称为准（净利润 ≠ 盈亏 ≠ 收益）。
- 面向读者的连续数值指标选择合理显示精度，原精度保留在依据，不手工改研究数据。模块的 `number`/`integer` 字段可显式设置 `presentation: {"kind":"metric","digits":2}`（省略 `value`，沿用字段单位）；不强制所有价格或统计量统一精度。
- 关键统计旁给出交易数或观测数。样本不足确实影响比较时，说明具体影响和下一步验证；已有不确定性估计就展示，不为所有小样本统一追加免责声明。

## 语言

- 先结论后依据；一句一事；主动语态；用具体动词（亏损、高于、过期、排除）。
- 正文不出现代码标识符、函数名、字段名、文件路径、哈希、ID 或 JSON；需要追溯时放进末尾 `details` 附录。用读者的名称：「Lookback 16」而不是「InpLookback=16」。
- 同一边界只写一次：影响结论或行动的贴近相应判断，追溯细节放折叠方法区；折叠区也只放有用信息，不把已删的套话搬过去。
- 默认不单列“时效与覆盖”“数据质量”“研究局限”等检查性章节。数据截止与时区放元信息；业务触发、失效条件留在情景或决策树。来源报错、权限、凭据缺失等过程信息不占正文，必要核验记录放折叠方法区。用户要求数据审计或这些问题本身改变决策时，再解释实际影响。
- 不写过程叙事（首先、然后、经过核验）、工具调用与修复经历，也不写「本页」「下方」这类指引。
- 不确定时直接给事实与下一步：「每组 1 笔交易；继续积累同口径样本后比较参数」，而不是「可能存在一定局限」。没有安排自动执行时，下一步写成建议或待观察项。
- 语言跟随任务：中文任务写中文，界面需要双语时自行提供本地标签，通过 `report_publish.locale` 选择。

## 可选内容顺序

以下章节按任务取舍，不为凑模板增加无用内容。

Research：

1. judgment：核心问题的答案。
2. metrics：样本量，加 2–4 个直接回答问题的数字。
3. sections：主要发现（趋势或对比图）→ 影响判断的驱动或比较（bar / heatmap）→ 下一步与条件情景；按实际问题取舍，不为凑章节加入质量、覆盖或核验汇报。
4. details 附录：需要追溯的清洗规则、统计口径和来源，默认折叠。

Strategy（先读 [backtest.md](backtest.md)；完整回测报告按其中的证据结构起步，用户只需部分内容时按实际范围取舍，不声称完成未做的验证）：

1. judgment：验证期（或样本外）结果，以及是否支持策略假设。
2. metrics：验证净利润、收益率、最大回撤、交易数、选中参数。
3. sections：训练与验证（hbar，signed）→ 参数敏感性（heatmap 或 bar）→ 信号或规则漏斗（bar）→ 损益构成（hbar，signed）；逐笔证据放末尾附录，保留固定 run/result/trade 数据。
4. details 附录：选择规则、冻结方式、建模方式、限制、构建与任务 ID。

## 发布前自检

- 只读 judgment 和各图 takeaway，能否复述完整论证？
- 每个分析项是否给出明确判断或至少一种倾向，而不是只留数据、两面可能或等待？最后的情景树是否以当前倾向为起点，说明什么变化会改变判断？
- 每个 takeaway 是否有可检查的证据支撑？每个数字能否在 rows 或其登记计算中找到？
- 首屏是否没有代码、ID 和过程叙述？每条限制是否只出现一次？
- 每个正文章节能否回答用户的实际问题或改变下一步？无用章节直接删除，必要边界并入对应判断。
- 删掉一句话后，用户是否会少知道一个事实、依据、判断条件或下一步？如果不会，就删掉；图注、元信息、节点说明和折叠区同样检查。

## 补充：让图形同时保留证据

延续原版结论语言，只吸收 Lieflat 值得借鉴的读图方法：先让读者一眼看到比较，再允许逐点查看原值；计数适合真实单位点阵，连续价格不应被画成没有明确单位的装饰圆点。图例、直接标注、缺失说明和控件都服务于问题，不把演示组件数量当作报告质量。

价格、金额与票据的精确字符串保留到表格和提示，不通过 Number 重新计算金融统计。所需统计由已登记计算结果提供，来源可追溯。完整 ArtifactRef、revision、digest 和引擎细节放进来源区；主文写用户理解的范围与口径。


## 末尾证据附录

正文保留判断、主要 K 线/热力图/统计图、关键数字、精简读图说明、推理步骤与影响决策的条件。来源、真实原始数据、样本清单、复核计算、参数和完整方法细节统一集中在报告末尾可折叠附录；正文只留小锚点，点击展开对应附录并可返回。不要把主图或全部指标移入附录，不改变研究方法、数据或结果。

原始证据使用 `details` 内容块，或放入 `content.appendix` 中的 `details`。Report 集中到末尾并生成正文与附录的往返锚点，保留完整原值与固定引用，不复制样本或重新计算。正文的主要图表、必要控件和关键条件保持可见；验收锚点往返、窄屏及打印完整性，不自行编写 DOM 标记。


报告正文使用普通读者能懂的话，必要金融名词用一句短话解释。不要把研究或开发用语搬到正文，例如回执、哈希、字段、冻结、校验、量纲、工件、前推折；写清发现、原因、对应历史情况以及何时可能不管用。原始术语和完整技术资料只放末尾附录。不能为了通俗而删掉会改变判断的重要限制。

内容与样式分离：直接向 `report_publish` 提交结构化 `content` 与 `style`，不上传 HTML、CSS 或脚本。默认蓝灰、无框、留白；用户可调整组件与顺序，现有样式不足时使用受控 `style.custom`，或 `report_style_save` 保存后按精确版本复用。主题、图表、间距和公式由 Report 统一提供，样式不改变数据与方法；通用组合见 report-design/style-guide.md。

公式使用 `formula` 内容块的 `latex` 字段，可选 `caption` 与 `display: "inline"` 或 `"block"`。Report 使用内置 KaTeX 本地渲染，无需外网；不把英文函数串或未渲染的 LaTeX 当作公式交付，原始代码保留在末尾附录。
