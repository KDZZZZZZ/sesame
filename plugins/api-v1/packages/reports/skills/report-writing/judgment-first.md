# 先确定要判断什么

研究起点是用户的问题。先用一份精简任务单说明：需要做的判断、观察角度、对象和期限、比较对象或备选，以及什么证据会改变答案。区分用户指定的角度与Agent提出的补充角度；信息足够就合理假设继续，不把任务单变成反复询问的表格。

`report_structure.judgment_brief` 和目录中的 `judgment_questions` 是各模板建议承担的职责。它们不规定方法、步骤或必填字段。用户删改优先；Agent为方便删掉章节，不代表用户放弃原问题。自定义报告也先列问题，再决定结果形式。

开头直接给总体结论，通常1–3句即可；下面按必要判断分别论证，小标题说结论，已有图表和短理由说明为什么。保留原来清晰的结论、分析、图表和风格，只补缺失的必要结论与衔接。摘要、卡片、图注不反复讲同一件事；不为精简删掉重要数据、反例或条件。一句总评也不能代替用户确实需要的不同判断。

默认结果形式新增分项判断：经营质量、估值与分歧、市场共识、事件影响、消息影响、情绪含义、期权定价、结构取舍、候选取舍、主要风险、预测采用、重点事件、策略适用、组合配置。`M01.timeframe_states` 表达分期限技术判断；M13逐项历史推断、M14综合判断和M15最终情景继续复用，不增加重复情景树。

问题、对象、期限、判断、依据、改判条件和历史参照是可用信息，不是每项都要填满的七栏。共同对象与期限可以只交代一次，独有的关键条件和历史数字放在对应判断旁。用户和方法可以调整子项；不新增必填schema或硬性篇幅。分清观察窗口、数据周期与判断期限。资产概览可以定义短、中、长期；单一事件、日历或回测不强加三种期限。

统一呈现映射：

```json
{"kind":"judgments","label":"问题","value":"判断","subject":"对象","horizon":"期限","basis":"依据","condition":"改判条件","history":"历史参照"}
```

它仅映射已有数组，不根据文字推断多空或生成分数、概率。不兼容内容完整回退，原值进附录。例见 `examples/judgment-presentation.json`。

以下只示意改写方式，结论仍须来自实际分析：

- 「本次校准误差高于原评分，应暂停采用该调整结果」→「这次校准反而更差，先停用这套概率调整。」下面接原来的误差对比图。
- 「受收益集中度约束，该策略现阶段仅适合作为候选」→「收益主要来自少数交易，先保留为候选。」下面接原来的交易与回撤分析，不再复述一次摘要。

财报解释、确定性损益比较、日历关注顺序、历史回看和用户目标下的方案取舍，都可以作出明确判断，不必先变成未来价格预测。涉及行情预测时仍结合实际同类历史结果；无数据不编概率。知道什么条件有效、什么条件失效的方案可有条件使用，不要求通过全部检验。

发布前按判断任务单逐项对照正文：已回答、具体证据缺口，或用户明确删减。缺哪个角度就补相应研究，不能只把旧报告再渲染一遍。对事实充分但存在冲突的情况说明当前更支持哪边；对具体未知说明其影响，不用泛泛否定代替职责。
