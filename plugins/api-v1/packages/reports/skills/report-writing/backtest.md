# 回测报告：从结果比较到策略解释

回测报告属于 **Strategy**。委派阶段使用 `task.output.space:"strategy"`；未绑定任务的新报告用 `report_publish.space:"strategy"` 明确分类。用户指定的任务目录和已有报告位置优先，更新修订不迁移文件。只有实际回测使用了 SVL，才用 `report_publish.strategy_source` 传入对应固定源码；完整 ref 同时放发布外壳 references 或 related；便利入口会补入 references。Python、MT5 或其他原生回测用 `strategy_evidence:{engine,summary,references:[完整固定Ref]}` 关联真实源码与运行证据，且每个 ref 同时出现在发布外壳 references/data/related；保留全部原数据与执行结果，不为分类另造 SVL，也不把原生回测降为普通 Research。

## 完整回测报告的建议结构

以下内容是完整研究的默认起点。用户可以缩小范围、增删字段或指定其他结构，按本次要求检查完整度；删去的默认章节不自动补回。所展示的数值、源码、选优与验证状态仍须与真实成果一致。

1. **策略逻辑图**：统一复用应用现有的 Netron 风格 SVL 渲染，从实际源码表达数据依赖、事件、条件、动作与仓位/风控逻辑。原生回测默认把真实规则整理为 `strategy_evidence.logic`；普通因子/策略文档使用 `logic` 内容块，见 [逻辑图](../report-design/logic-diagram.md)。主要图放正文，固定源码与运行引用放末尾附录，不制造另一份 SVL 执行源码。已有固定 SVL 时，backtest 内容可读取对应 strategy_source，或复用 `strategy_graph` 的真实结果，函数可展开、节点可查定义。图与运行结果必须来自同一源码修订。仅有因子计算时只画计算和已知使用条件，不补造尚未定义的买卖规则。
2. **品种 × 周期热力图**：每格是该组合按事先声明的优化规则选出的最优参数组的结果。颜色默认展示选优指标；可切换夏普、最大回撤、净盈亏，切换颜色不重新选优。写清目标、样本、约束和并列规则。用正负与数值表达结果，不能把全亏损中的最优格解释成盈利。
3. **点格子查看全部参数组**：保留每组参数、夏普、最大回撤、净盈亏、试验 ID、状态及其他真实统计。支持分页和明细，不只列 Top N；失败、未运行、指标未定义分别显示，不能写成 0。
   恰好声明两个参数且参数对唯一时，另显示全部试验的双参数热力表；两轴使用原参数值，每格可打开完整原记录，✓ 只标记已登记选中组。颜色随同一个指标切换，不重选赢家。每轴超过 20 个值时分页；失败、未运行和无记录分别保留。若参数对重复或不同原值显示相同，明确保留逐项散点和表格，不平均、不合并为一格。
4. **参数敏感性**：逐个参数可切换，图示夏普、最大回撤、净盈亏如何随参数改变。每个点能回到完整参数组；多个参数同时变动时，固定/筛选其他参数或明确每点其他参数不同。相同横坐标不能被静默平均，排序不等于因果。类别参数按类别展示。

这四项是可调整的内容建议。先回答“策略表现如何、哪些参数与市场值得继续验证、损失来自哪里”，再选有帮助的净值/回撤曲线、成本分解、逐笔交易、滚动样本外、参数平台与过拟合诊断。使用 Report 统一的通用 style 与无框蓝灰排版，按 report-design 选择适合证据的统计、排名或关系图。不要为填满模板发明数据；只有一个品种、一个周期、一组参数时如实显示 1×1 和单点，将需要继续验证的对象列为下一步。按 report-writing 通篇精简套话，边界用实际样本、成本与验证条件表达。

## 数据与选优

优化、指标计算和获胜组选择都在可追溯的后端/登记计算中完成，报告只读冻结结果。样本内负责选择，样本外负责验证；不能看过样本外后再挑最好的一组。分开不同样本、资金口径、币种、成本模型和不兼容的年化规则；只有经过登记的口径转换后才能共用色阶。

backtest 内容的一个固定 `data` 绑定包含全部试验行（最多 100,000；更多时在报告分成具名分页绑定，不删数据）。每行字段：

| 字段 | 内容 |
| --- | --- |
| `trial_id` | 全报告唯一的真实试验 ID |
| `symbol`, `timeframe` | 品种和周期，字符串 |
| `sample` | 同一比较样本/区间标识；不要混合训练和样本外 |
| `status` | `completed` / `failed` / `not_run` |
| `selected` | 登记计算已选定的获胜组 `true`，其余 `false` |
| `parameters` | 全部实际参数的对象，保留原值 |
| `sharpe` | 原统计值或 `null`，说明年化/无风险利率口径 |
| `max_drawdown_pct` | 非负百分比幅度（12.5 表示 12.5%，不是 0.125），或 `null` |
| `net_profit` | 已扣规定费用、统一币种的净盈亏，或 `null` |

金额、精确小数和票据保持字符串。backtest 内容要求每个有成功试验的品种/周期恰好一个已登记选中组；全失败/未运行的组合没有获胜者。如果约束导致无合格试验，用通用 document 的判断与明细明确展示“不满足约束”，保留全部试验，不假选一个。无对应试验的组合显示缺失；不会自动补造一次运行。

可选 `parameter_labels` 只给 `parameters` 已声明的键指定显示名，例如 `{"entry_period":"入场周期","exit_period":"出场周期"}`。每个名称须为 1–64 字符的非空单行文本；未指定的键按原名显示。下拉、轴说明、图标题和表头使用名称，内部参数键、精确取值、试验 ID 和已选身份不变。中文正文把状态与选中标记显示为“完成/失败/未运行”和“已选/未选”；英语保留相应英文。正文试验表和双参数网格的夏普、最大回撤与净盈亏显示两位小数，原始数字仍完整保存在末尾证据和“完整试验记录”中；已有图表仍采用其有限位数刻度。参数值不套用指标四舍五入；“组合 1”等按钮的标题和原始明细保留精确试验 ID。

`source_note` 写引擎和版本、数据来源、起止区间/时区、样本划分、币种/初始资金、费用/滑点、成交模型与指标定义。把真实 result/run/translation 的完整引用放来源区。结论有交易数和样本外证据支撑；不足时限制结论强度。

## 开始编写

- 用 `report_data({operation_id,dataset_id})` 冻结 `host#datasets` 的宿主登记数据；插件回执中的 `dataset_id` 须使用原来源的完整 `SourceRef`，传 `source+input:{datasetId:<原ID>}+title`，不传顶层 `dataset_id`。已有固定 DataRef 直接复用。
- 直接 `report_publish`，内容为 `{kind: "backtest", data_id, parameters, parameter_labels?, selection_metric, selection_rule, source_note, currency}`，配通用 `style`；`data_id` 对应固定数据绑定。selection_metric 填研究已经采用的夏普/回撤/净盈亏口径，不在报告重选。仅真实使用 SVL 时在提供者 input 中传 `strategy_source`；否则提供实际 `strategy_evidence`。两条路径共享原有热力图、完整参数分页与敏感性。缺少实际参数或必要列时保留缺口，不编造数值凑输入。`report_backtest_template` 只用于预览，不要求先生成模板，也不上传可编辑 HTML。演示发布用 `provenance_kind: "demo"`。
- 已登记选优指标超出 backtest 适配范围时，用通用 document 的图表、指标和明细呈现原结果，不把它改为另一选优方法；按用户需要组合组件与声明式样式。
- `report_publish` 明确 `space:"strategy"`，传固定数据绑定和关联证据；实际使用 SVL 时才附上对应 `strategy_source`。随后 `report_check` 检查新 ref。源码、内容或样式更新都需要新修订和新检查，不能沿用旧成功回执。
- 检查矩阵选中至少两个真实存在的组合、参数切换、完整试验分页、缺失/失败状态、键盘/触屏以及窄屏。只在真实回执 `rendered` 后交付“已渲染”；发布成功本身不代表交互无误。


## 末尾证据附录

正文保留判断、主要 K 线/热力图/统计图、关键数字、精简读图说明、推理步骤与影响决策的条件。来源、真实原始数据、样本清单、复核计算、参数和完整方法细节统一集中在报告末尾可折叠附录；正文只留小锚点，点击展开对应附录并可返回。不要把主图或全部指标移入附录，不改变研究方法、数据或结果。

原始证据使用 `details` 内容块，或放入 `content.appendix` 中的 `details`。Report 集中到末尾并生成正文与附录的往返锚点，保留完整原值与固定引用，不复制样本或重新计算。正文的主要图表、必要控件和关键条件保持可见；验收锚点往返、窄屏及打印完整性，不自行编写 DOM 标记。
