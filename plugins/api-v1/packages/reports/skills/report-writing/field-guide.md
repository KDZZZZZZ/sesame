# 逐字段语义与分析边界

使用 `report_structure` 选择模块或组合后，先读取返回的 `guidance` 和本次所选字段的 `agent_guidance`。它们告诉 Agent 某字段表达什么、需要哪些已有输入、单位与时间口径、近似概念的区别以及资料缺失时如何处理。它们不启动分析，不增加隐含必填项，也不约束用户必须采用某种理论、供应商或公式。

模板可以裁剪、重排、拼接。用户的章节与字段清单完整替换建议清单；本次修改不会自动写成长期偏好。字段内列出的输入是语义提示，object/array 的子项仍按所选方法组织。用户改写字段的 `meaning` 或 `type` 后，默认 `agent_guidance` 会移除，以免旧定义约束新含义；仅改标题、显示方式或必填状态仍可保留语义。自定义字段遵从用户定义和通用规则，不用类型套话冒充专门指导。

## 从已有研究到字段

每个默认字段另有 `agent_guidance.lineage`，说明建议来源性质与内容性质。这些仅供 Agent 内部理解结果，不在报告正文加“获取/计算/推断”标签。实际可由不同方法提供同一结果形式，建议分类不是执行回执。现有插件的获取/计算覆盖另行审查，不进入模板的算法、依赖或必做任务；知识文档存在也不等于已有可执行计算。

`agent_guidance.judgment` 说明该项结果如何支撑可读判断。围绕用户问题补齐必要结论：方向、相对强弱、风险所在、贵便宜或适用条件，随问题选择，不指定判断算法。已有清晰判断保持，相关图表和指标共同论证；takeaway、note、conclusion/claim 不必各说一遍。对象和期限可共享，关键条件按需要就近说明，不把语义提示变成每项必填栏目。日期、来源和原始值保持原义，其意义放在关联分析中；内部来源分类不决定看多或看空。

冲突证据要说明目前更支持哪边以及原因，不能只罗列两种可能或否定所有解释。先说什么关系更可能成立、何时有效，再说具体未知；未严格证明因果不等于没有因果，缺少普遍规律不等于没有条件性规律。实际机制、时间顺序、同类历史与替代解释共同支撑判断，不把相关性夸大成已证实因果。事实充分而没有方向优势，可以明确判断“尚无单边优势”；资料缺失不等于没有优势，更不能填“中性”或 50%。确实无法区分时说明具体原因，不硬造倾向。定性倾向不冒充置信度；数值概率和置信度继续遵守历史证据要求。因子可以在已识别的条件下使用，说明适用和停用条件，不要求所有检验都通过。

获取方式与内容性质独立。例如分析师目标价可以 `kind:acquired,nature:prediction`；自己计算 ATR 为 `derived,statistic`；据波动判断未来方向为 `inferred,prediction`。同一字段可因用户选择变换来源；混合对象逐子项记录实际来源，不能按字段名或图型猜。用户输入和控制条件为 `user_supplied`，无需冒充外部获取或统计结论。

结果行的可选 `origin` 包含 kind、nature、source/note/refs；mixed 用 parts 分别列 path/kind/nature/source/refs。获取结果需要来源身份及固定引用；计算/推断需要实际 method_ref。声明 inferred 时同时提供 reasoning。省略 origin 不阻止旧成果展示，但在 `report_compose.lineageAudit` 中记为未声明，不自动继承建议分类。此审计和来源标签不出现在读者正文。

`reasoning` 是可核查的业务推导摘要，不要求完整思考记录：observations 为 1–4 条短观察，steps 为 1–4 条推导，conclusion 为简短判断，history 为 `{status,note}`。status 为 linked 时必须有该推断自己的 historical_basis；pending 表示待检索，unavailable 表示已有明确缺口。纯确定性复算或用户偏好可标 not_applicable 并说明原因，预测不可用此状态跳过历史对照。未获得样本时不产生置信度。完整原始输入、知识来源和方法版本留在展开明细。

先确认用户要回答的问题、对象、截点、目标和期限，再选择能承接已有成果的字段。`method_refs` 约定实际研究方法，`theory_refs` 说明实际采用的知识；理论、特征识别、历史匹配和综合方法可以自由组合。知识通常提出机制或假说，历史实际结果检验其是否适用于当前情景。不要因字段存在就增加研究任务，也不要为满足字段改用别的方法。必要成果不可得时标明具体缺口。

逐项保留原值、量表、单位、版本与真实时间属性。财期结束不等于财报已公开；价格观察不等于抓取时刻；报告生成不等于报价时点；技术事件形成、检测、确认和最早可行动时间可能不同。历史研究使用当时可得资料，不能把后来修订值或事后确认形态回填。不同财期、币种、目标期限、分母和语料范围不能未经说明合并。

`instrument_context / data_times / source_scales` 收纳适用的共同说明，避免正文反复堆叠；它们不扩展 `section.context` 的严格匹配键。完整固定证据仍放结果行 `evidence_refs`，不能用自然语言说明、URL 或裸 ID 代替。

## 容易混淆的结果

| 结果 | 应保留的区别 |
| --- | --- |
| 公允价值、模型目标、分析师目标 | 价值估计、指定期限市场价格预测、分析师意见聚合分别记录，保留各自日期与期限，不补空、不平均成总目标。 |
| IV Rank、IV Percentile | 前者为所选历史极值范围内的位置，后者为历史观测分布的分位位置；保留窗口、极值/相等值处理和原尺度。 |
| 新闻证据量、主观性、情绪、预测置信度 | 语料多少、文本意见性、正负方向与预测可靠性不同。供应商名为 Confidence 的证据量只进入 `evidence_volume`，不能填入 `confidence` 或概率。 |
| 定价范围、技术目标、预测区间 | 隐含定价、条件位置与实际未来结果的不确定性不同；风险中性概率不能直接称实际发生概率。 |
| 条件频率、概率、置信度 | 历史已结算样本频率不自动成为当前预测概率；置信度还需说明评价对象、定义和验证范围，不能由模型自评分。 |
| 止损、观点失效、盈亏比、胜率 | 风险控制、判断不再成立、潜在盈亏比较与结果概率分别表达；止损价也不保证最终成交损失。 |
| 同类情景统计、策略回测、实盘业绩 | M13 研究匹配后的实际结果，M18 表达冻结策略与模拟执行产生的表现；模拟和真实成交/业绩均需清楚标识。 |
| 当前组合与目标组合 | 目标权重是方案；原组合业绩或风险不能改名成新方案结果。 |

## 预测与历史证据

任何字段只要承载可检验的行情预测，应能对应历史相同或可比情景的实际后续结果。每项特征推断有自己的目标、期限、匹配规则、案例结果和基准；综合判断另有联合方法的历史检验。不能把多个相关特征当独立投票，也不能让一份泛化资料代替所有推断的历史依据。方法如何估计、综合或校准由用户或任务选择，不固定一种算法。

历史样本记录应说明已有结果的品种、近期窗口、检索范围与状态、符合数量和固定成果。用户默认偏好是当前品种近期同类情景；跨品种结果应附同品种检索已完成且零匹配的记录，以及跨品种可比性说明。未检索、检索失败、数据不可用或样本少，都不等于零匹配。用户明确要求其他范围时记录 `override_reason`。这些是结果的来源语义，不要求 Report 执行检索或规定研究步骤。

历史结果至少要能核对匹配、已结算、待结算和排除数量，实际结果窗口，当时信息可得性，重叠/事件簇，基准及其可比性，不确定性和相反案例。基准不可得要明确说明，不能默认 50% 胜率或零收益。概率、分布、置信度及逐项推断保留真实 `validation`；探索、样本外和前瞻研究是不同状态。固定引用存在、字段齐全、HTML 可渲染均不证明统计有效。具体行契约见 [模块模板](module-templates.md) 与 [模块可视化](../report-design/module-visuals.md)。

## 缺失与呈现

可选字段没有成果可以省略。明确提供不可用状态时，使用 `unavailable / pending / not_applicable`、具体 `reason`，并省略 `value` 或设为 `null`。已知零、false、确认空集合和未知分别表达；未公布实际值不能填预期，未确认事件不能填确认时间，未运行试验不能填零收益。没有可比已结算历史时不给预测概率或置信度，不用 50%、中性标签或主观分数补齐。

图表使用已有固定结果，不重算波动、合成评分、挑选新参数或以插值冒充实测。M02 的方法对照使用实际检测/确认/无信号/不可运行事实；M18 的市场矩阵、参数热力、敏感性、验证、漏斗和损益桥各保留运行/试验引用。选优指标和图中颜色指标可不同，留出数据不能反过来挑参数。源码逻辑图复用真实修订与原生运行，不根据叙述编造执行结构。

## 维护

语义原稿在 [build-field-guidance.mjs](../../scripts/build-field-guidance.mjs)。新增或改动模板字段后，逐项补写具体定义，再运行生成器；生成器对未写字段、已删除字段残留和超过 128 KiB 的分片直接报错，不用 `type` 或目录 `meaning` 生成空泛兜底。

```sh
node plugins/api-v1/packages/reports/scripts/build-field-guidance.mjs
node plugins/api-v1/packages/reports/scripts/build-field-guidance.mjs --check
node --test plugins/api-v1/tests/report-field-guidance.test.mjs
```


## 末尾证据附录

正文保留判断、主要 K 线/热力图/统计图、关键数字、精简读图说明、推理步骤与影响决策的条件。来源、真实原始数据、样本清单、复核计算、参数和完整方法细节统一集中在报告末尾可折叠附录；正文只留小锚点，点击展开对应附录并可返回。不要把主图或全部指标移入附录，不改变研究方法、数据或结果。

原始证据使用 `details` 内容块，或放入 `content.appendix` 中的 `details`。Report 集中到末尾并生成正文与附录的往返锚点，保留完整原值与固定引用，不复制样本或重新计算。正文的主要图表、必要控件和关键条件保持可见；验收锚点往返、窄屏及打印完整性，不自行编写 DOM 标记。
