# 报告路径规则

这是新报告的默认归档建议，不规定研究方法，也不替用户重新整理全部旧报告。用户明确指定的位置优先；沿用已有任务绑定或原报告位置，修订不自动迁移。用户要求整理时，再按本规则移动已有报告。

## Research：先找研究对象，再找时间

`research` 是报告空间，不是路径中的一层。

| 类别 | 放什么 | 默认相对路径 |
| --- | --- | --- |
| 市场与宏观 | 大盘、经济、利率、汇率环境及跨市场事件影响 | `市场与宏观/YYYY-MM/报告.html` |
| 行业与主题 | 行业、产业链、跨标的主题与比较 | `行业与主题/YYYY-MM/报告.html` |
| 个股与品种 | 具体股票、ETF、货币、加密资产、商品等 | `个股与品种/具体标的/YYYY-MM/报告.html` |
| 组合与配置 | 持仓分析、组合风险、资产配置建议 | `组合与配置/YYYY-MM/报告.html` |
| 测试与演示 | 真实用途就是测试或演示的报告 | `测试与演示/YYYY-MM/报告.html` |

- 个股与品种必须先细分标的，再分月份；不能把所有标的混放进同一个月份。技术、基本面、估值和该标的的事件分析集中在同一标的目录，不另设“事件专题”。
- 跨标的事件按主要问题归入市场与宏观或行业与主题；确实比较几个具体标的时，可沿用或建立明确的组合目录，例如 `个股与品种/BTC-ETH/2026-11/01 强弱比较.html`。只保留一个主位置，不为多个标的复制报告。
- 优先沿用已有标的名称；同名或代码有歧义时加市场或代码，例如 `个股与品种/恒瑞医药（600276.SH）/2026-11/01 三季报解读.html`。不要因简称变化另建一份目录。
- `YYYY-MM` 取首次发布日期，不取后来修改、整理或搬动的日期，也不取回测区间的起点。旧报告修订留在原月份；一次新的研究可生成新的报告。月份已知时，文件名可用 `DD 主题.html`；日期不明时先查已有记录，仍无法确认就保留原位置并说明，不编日期。

## Strategy：先找策略逻辑，再找项目

`strategy` 是报告空间。默认相对路径为 `策略类别/具体策略项目/报告.html`；第二级是项目，整个路径不额外建立年份或月份目录。日期可写进文件名。

| 策略类别 | 按主要获利逻辑归类 |
| --- | --- |
| 趋势与动量 | 趋势延续、突破、相对强势 |
| 反转与均值回归 | 单一资产价格反转、超跌反弹、回归常态 |
| 基本面选股 | 价值、盈利、成长、质量等股票选择 |
| 相对价值与套利 | 配对、价差、跨期及相关资产定价差异；配对价差回归也归这里 |
| 利差与持有收益 | 外汇利差、资金费率等持有收益 |
| 事件驱动 | 财报、指数调整、并购等事件触发的实际交易规则 |
| 波动率与期权 | 波动率交易、期权定价或价差、保护策略 |
| 宏观与组合配置 | 宏观择时、轮动、风险平价、多个独立策略的组合 |
| 做市与交易执行 | 做市、拆单、交易成本与执行时机 |
| 测试与演示 | 实际测试或演示项目 |

- 同一策略项目跨月份集中存放因子研究、规则设计、回测、参数优化、条件适用和表现复盘；“回测”“优化”“复盘”是报告内容，不是顶层类别。
- 同一品种上的不同策略分不同项目；同一策略研究多个品种时，仍可放同一项目。项目名应能看出策略本身，而不只有品种名。
- 因子研究按它主要支持的策略逻辑归类。机器学习、指标、持有周期、交易接口和回测引擎用于说明或检索，不取代主要类别；新增止损或仓位规则也不改变主要类别。
- 仅解释事件对行情的影响属于 Research；用事件定义可执行交易规则属于 Strategy。持仓与配置建议属于 Research；可重复执行并研究表现的配置策略属于 Strategy。
- 实际研究即使亏损、无效或存在缺口，也保留在对应项目，不能因此归为测试与演示。确有未覆盖类型时可增设类别，用户调整优先。

例如同一个项目可同时保留：

```text
趋势与动量/BTC 趋势策略/2026-10-31 因子研究.html
趋势与动量/BTC 趋势策略/2026-11-01 回测与参数比较.html
趋势与动量/BTC 趋势策略/2026-12-01 表现复盘.html
```

## 用现有接口落实路径

1. 先看用户要求、当前任务绑定和已有目录，沿用同一标的或策略项目。只为本次报告建立必要目录，不预建一套空目录。
2. 委派任务时把位置交给现有 `output`，例如：

   ```json
   {"output":{"type":"report","space":"research","path":"个股与品种/恒瑞医药/2026-11/01 三季报解读.html"}}
   ```

   ```json
   {"output":{"type":"report","space":"strategy","path":"趋势与动量/BTC 趋势策略/2026-11-01 参数比较.html"}}
   ```

   宿主为声明的任务输出创建必要父目录；目标文件须未被占用。已有绑定由宿主管理，不在内容里另造路径。需要整理的子任务由父 Agent 提供相应报告文件权限，不能绕过权限。
3. 没有输出绑定的新报告先按实际 `space` 发布，再用 `host_reportFiles_list`（`host.reportFiles.list`）按返回的报告身份找到真实文件，不能只猜标题或路径。需要时逐层调用 `host_reportFiles_mkdir`，然后用 `host_reportFiles_move({space,path,destination,expectedVersion})` 归档；版本取最新 list/read。目标已存在时核对身份，修订原报告或换明确的新文件名，不覆盖别的报告。
4. `host_reports_publish` 和 `report_publish` 均没有 `path` 参数；路径不放进 `content`、`assets` 或发布外壳，也不通过直接写 HTML 创建报告。空间与路径分别传：`space:"research"` 的路径从 `个股与品种/...` 开始，不能加 `Research/`、`research/` 或本机绝对路径。移动只能在同一空间内；发现原空间选错时说明，不假装已跨空间搬动。
5. 多文件报告按包整体移动，保留内部相对资源路径、JSON、图片和附件；单文件报告不额外套标题加随机 ID 的目录。共享附件或归属不明的文件先确认依赖，不能为了目录好看删掉。只整理位置，不改结论、重新生成、复制或删除报告，不改变已有发布引用。
6. 完成后核对真实路径和已发布状态，再给用户最终报告入口。标题写报告名称，不带 `.html`；实际文件仍保留 `.html` 或 `.htm`。JSON、原始数据、图表资源和预览不是另一份最终报告，不作为独立报告交付。需要查看来源时在报告末尾附录中提供。
