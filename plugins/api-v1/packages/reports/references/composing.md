# 组件与组合

components_list 按表达关系查目录；components_describe 返回准确 schema、何时用、数据要求及最小示例。38 种图表和 15 种内容块均可用；report.highlights 是复用 metrics 的首屏关键结果入口，无需先选报告模板。

```js
components_show({ title: "范围内的位置", lead: "演示：观测值位于区间中部偏上。", highlights: [{ label: "观测值", value: 6 }], target: "report", provenance_kind: "demo", components: [
  { type: "range", label: "观测值", min: 2, max: 8, value: 6 }
] })
```

完整报告使用 title、lead、highlights 和至少一个有内容的正文章节。lead 是开篇回答，highlights 是随后展示的 1–6 项 {label,value,tone?}，均由作者提供，不从 summary 或正文猜测。component 是单块，components 是最多 12 块的一组，layout 可选 stack/columns；简短报告加 title、lead、highlights 即可沿用便捷调用。长文档用 content:{kind:"document",sections:[{title:"",blocks:[...]}]}，空节标题不占一行。group 与 details 最多嵌套 5 层。target=answer 的独立组件无需报告骨架。目录、摘要标题、附录不作为通用必填章节。

## 先做视觉设计

1. 逐段明确表达意图：要让用户看懂什么、比较什么、据此判断什么。保留原数字、单位、对象、口径、时间及条件；初稿的段落、表格、指标和旧图只是素材。
2. 为每个意图组织所需数据与参照，设计它们在画面里的位置、分组、强调和阅读顺序，再选择组件。尽可能把数据变成直观图形，不等数据已整理为序列或表格才画图，也不把“识别出某种数据关系”当入图门槛。
3. 优先重设计或合并已有图，用必要标注点明要看的地方；不能让读者逐点查数再心算才明白正文判断。指标格只做首屏概览，正文图表传达证据和判断，文字解释原因与意义。
4. 对照初稿逐段复核：意思是否相同，图形是否把本段意图表达清楚，仍留在文字或表中的数据是否还可以转为图形。可以就继续完成转换；只有精确查数确实更方便时才保留表格。内部设计记录不成为报告章节。

例如，意图是解释“增长主要由谁贡献”，就让已有分项与总量组成一幅贡献图；意图是判断“是否接近关注区”，就把当前值、阈值和区间放到同一尺度；意图是比较“哪种结果更稳定”，就让分布、基准与异常观测共同参与比较；意图是提醒“未来何时可能改变判断”，就把事件时间与观察点组织成时间轴，再用条件树表达不同响应。先设计要表达的意思，再落实图型，不为每个数字单开一图。

重新生成或改版要重新执行这一步，复用研究成果不要求复用旧章节数、图数和版式。仅修具体报错才做局部调整。委派时以本次表达目标验收，不自行限制只能适配旧输入。

确定表达意图后，以下关系可帮助落实具体图型；它们是实现手段，不限制可以视觉化的内容。先安排图形再写必要解释，不默认柱形，也不为增加图型数量换图：

| 数据关系 | 优先表达 | 合并方式 |
| --- | --- | --- |
| 上下界、基准与参照的位置 | range；多个有明确尺度的维度用 spectrum | 同一尺度上同时看范围与关注值，不把端点当成独立类别 |
| 时间或其他有序维度上的变化、连续敏感性 | line；强调总量规模可用 area | 同单位序列放同图；斜率或变化量用已有数值标签点明，不另画重复柱图 |
| 对象的前后两个状态与差距 | dumbbell | 同时保留两个端点；已知变化率可放对象标签中 |
| 类别之间的数值大小或排名 | bar / hbar | 同口径类别共用尺度，不给每个指标单开一图 |
| 起点到终点的增减贡献 | waterfall | 起点、可加的分项与终点合成一图，不将独立情景伪装为可加贡献 |
| 两个连续变量的关联 | scatter | 保留各观测的成对关系，不将横纵变量拆成两张柱图 |
| 两个维度交叉的高低值 | heatmap / matrix | 一张网格展示已有交叉结果，不为填格补造数据 |
| 分布或组成 | 对应分布图或组成图 | 分布须有观测/统计量，组成须有真实总量 |
| 多个条件导向不同判断、结果或行动 | decision-tree | 条件放分支，叶子只放结果，保留阈值、时间和“且/或”关系，不用条件表替代 |

只有两个时期就比较这两个时期，不补造趋势；只有区间就展示范围和参照，不编造分布。总量与变化率是同一证据的两个表达，能用必要标签结合就不重复占图；派生数字只在改变判断或帮助读图时呈现。同单位、同问题优先合为一图；不同单位需一起比较时，用共享对象顺序的并排小图并标明各自尺度，不混同一轴。并排是合图不清晰时的安排，不代替去重。

按表达意图是否实现、易读性与合并效果复核，不数图表张数。基准、范围、参照与已有敏感性应在对应图中可见；数据虽然入图却无法直接看出本段要说明的意思，仍要调整。未来展望若包含不同的触发条件和改判路径，应已画成决策树；日期日历本身不等于分支逻辑。敏感性保留既定输入与计算条件，只画已有结果；缺少计算交回研究。正文解释发现、原因和意义，不逐项复述图中数字。

judgment 突出一句已有判断；judgments 接收 items:[{label,value,details?:[{label,value}]}]，不预设研究字段。logic 接收通用 nodes/edges，不解读策略或因子源码。decision-tree 分支表达条件，叶子只放结果。formula 使用 LaTeX。
