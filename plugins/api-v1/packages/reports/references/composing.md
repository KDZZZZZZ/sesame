# 组件与组合

components_list 按表达关系查目录；components_describe 返回准确 schema、何时用、数据要求及最小示例。38 种图表和 15 种内容块均可用；report.highlights 是复用 metrics 的首屏关键结果入口，无需先选报告模板。

```js
components_show({ title: "范围内的位置", lead: "演示：观测值位于区间中部偏上。", highlights: [{ label: "观测值", value: 6 }], target: "report", provenance_kind: "demo", components: [
  { type: "range", label: "观测值", min: 2, max: 8, value: 6 }
] })
```

完整报告使用 title、lead、highlights 和至少一个有内容的正文章节。lead 是开篇回答，highlights 是随后展示的 1–6 项 {label,value,tone?}，均由作者提供，不从 summary 或正文猜测。component 是单块，components 是最多 12 块的一组，layout 可选 stack/columns；简短报告加 title、lead、highlights 即可沿用便捷调用。长文档用 content:{kind:"document",sections:[{title:"",blocks:[...]}]}，空节标题不占一行。group 与 details 最多嵌套 5 层。target=answer 的独立组件无需报告骨架。目录、摘要标题、附录不作为通用必填章节。

## 统一做图文编辑

visual-compose 在初稿后将全文组织、表达编排、语言编辑与成品审读放在同一个步骤。先完整交代主问题的回答及关键条件，再按论点安排解释与证据。自然叙述和改写示例见 text.md；这里说明现有组件怎样承担不同表达任务。

1. 先选择表达形式：少量数值或简单条件可直接写，连续机制用段落，并列证据用列表，需要逐项比较的定量或定性信息用表格，模式、分布与关系用图。不要因组件可用就全部铺上，也不因文字更短就把复杂关系压成一句。
2. 每幅图服务一个清楚的阅读任务。正文讨论差距，图里就能看到差距；讨论关键价位，就有相应参照；讨论尾部风险，就保留尾部。标题或已有标签点明有依据的重点，单位、时点与编码清楚，不能仅展示原始值、让读者自行心算重点。
3. 检查图与图、图与文字是否增加不同理解。允许合并、替换或移除冗余图；明细可留在既有附件。频数、均值和完整分布并非天然重复，删除前确认不会隐去尾部、分歧或反证。不要求一段一图，不以图数或覆盖率验收。
4. 段落解释图对主问题的意义和与其他证据的联系，不逐点抄数。完成后沿整篇阅读，调整顺序、层次与衔接，并核对结论强度和时点。内部编辑记录不进入成品。

例如，意图是解释“增长主要由谁贡献”，就让已有分项与总量组成一幅贡献图；意图是判断“是否接近关注区”，就把当前值、阈值和区间放到同一尺度；意图是比较“哪种结果更稳定”，就让分布、基准与异常观测共同参与比较；事件时间用时间轴，少量平行情景用紧凑表格或列表，需逐层判断时才用条件树。用户明确指定的视觉仍优先。先确定要表达的意思，不为每个数字单开一图。

## 用现有组件建立层次

- section.title 是正文 H2。章节内不同论证任务用 `{type:"markdown",text:"### 哪些证据支持这个判断？\n\n..."}`；并列要点用同一 text 中的 `- **对象：** 证据`。小标题和图题不要同名重复，Markdown 标题不参与自动去重。
- 简短情景与定性对照可用 `{type:"table",columns:["条件","判断"],rows:[["给定条件A","结果A"],["给定条件B","结果B"]]}`，不是只有数字才用表格。保留初稿的且/或关系、阈值与时间，不自行补全缺失路径。
- group 的 layout 为 stack/columns，只组织 blocks 与 controls，没有 title 字段。需要小标题时放一个相邻 markdown 块；不新增主题单元或卡片外壳。
- chart.title 可以是一句有依据的发现或明确的比较重点；单位、时期与编码放在已有轴、图例和标签中。仍需解释的内容使用相邻 paragraph/markdown，不新增 takeaway、source_note 或独立图注字段。

重新生成或改版要重新执行这一步，复用研究成果不要求复用旧章节数、图数和版式。仅修具体报错才做局部调整。委派时以本次表达目标验收，不自行限制只能适配旧输入。

确定表达意图后，以下关系帮助落实图型；它们是实现手段，不限制表达内容。图文共同编辑，不默认柱形，也不为增加种类而换图：

| 数据关系 | 优先表达 | 合并方式 |
| --- | --- | --- |
| 上下界、基准与参照的位置 | range；多个有明确尺度的维度用 spectrum | 同一尺度上同时看范围与关注值，不把端点当成独立类别 |
| 时间或其他有序维度上的变化、连续敏感性 | line；强调总量规模可用 area | 同单位序列放同图；斜率或变化量用已有数值标签点明，不另画重复柱图 |
| 对象的前后两个状态与差距 | dumbbell | 同时保留两个端点；已知变化率可放对象标签中 |
| 类别之间的数值大小或排名 | bar / hbar | 同口径类别共用尺度，不给每个指标单开一图 |
| 起点到终点的增减贡献 | waterfall | 起点、可加的分项与终点合成一图，不将独立情景伪装为可加贡献 |
| 两个连续变量的关联 | scatter | 保留各观测的成对关系，不将横纵变量拆成两张柱图 |
| 两个维度交叉的高低值 | heatmap / matrix | 一张网格展示已有交叉结果，不为填格补造数据 |
| 分布或组成 | 对应分布图或组成图 | 分布须有观测/统计量，组成须有真实总量 |
| 递进判断和分支依赖 | decision-tree | 条件放分支，结果在叶子，保留阈值、时间和“且/或”关系；少量平行情景可用表格或列表 |

只有两个时期就比较这两个时期，不补造趋势；只有区间就展示范围和参照，不编造分布。总量与变化率是同一证据的两个表达，能用必要标签结合就不重复占图；派生数字只在改变判断或帮助读图时呈现。同单位、同问题优先合为一图；不同单位需一起比较时，用共享对象顺序的并排小图并标明各自尺度，不混同一轴。并排是合图不清晰时的安排，不代替去重。

按图文是否共同讲清判断、是否易读且原意准确来复核。基准、范围、参照与已有敏感性应在对应图中可见；数据虽然入图却看不出本段重点，仍需调整。逐层触发与改判路径用决策树，简单条件不强制画树；日期日历不等于分支逻辑。敏感性保留既定输入与计算条件，只画已有结果；新统计或专业计算交回研究。

## 用已有组件明确重点

- candlestick 的 overlays 可显示已有同单位价格列，包括明确给定的参考价。已知固定阈值可作为常数参考列，用 label 命名、style:"dashed" 区别于走势；上下界可用相同 group。它是给定参考线，不是新增逐日观测、动态指标或统计结果。OHLC 和原始固定引用保持不变，参考价的来源与适用时点保留。不要在正文讨论多道关口，却只在主图画当前价。
- range 只能标一个 value 与上下界。若判断需要同时比较多个中间关口，选能容纳这些参照的已有图，不用一个简单 range 假装已经表达完整。
- 比较变化幅度时保留端点、单位和基准，核对已有数字的简单差值、比例或单位换算后，用标题或组件允许的标签点明重点。例如百分比水平的相减是百分点，1 个百分点等于 100 个基点；相对百分比变化另有分母。原值和固定引用保持不变，不新增归因、预测或统计检验。不同量纲用明确尺度，不靠夸张轴域制造影响。
- 分布图与计数图分别回答结果有多大、出现了多少次。正文解释两者是否形成张力；历史频数保留其样本含义，不能改写为未来概率。

标注只用组件已声明的字段，不发明 options、叠加自由 HTML 或把长段落塞进图例。查 describe 确认能力；当前组件无法表达时选择更合适的组件或保留必要正文，不伪称已经画出。

judgment 突出一句已有判断；judgments 接收 items:[{label,value,details?:[{label,value}]}]，不预设研究字段。logic 接收通用 nodes/edges，不解读策略或因子源码。decision-tree 分支表达条件，叶子只放结果。formula 使用 LaTeX。
