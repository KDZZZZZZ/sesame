# 按用户需求组织的插件生态

本文记录 API 1 扩展的合并原则和验收方式；不是安装目录。实际可安装 ID、版本、固定源及摘要以发布后的统一 `plugins/api-v1/catalog.json` 为准。应用最低正式版本为 0.2.0，预发布宿主通过 `>=0.2.0-0` 单独声明。

## 一种需求，一套方法流程

| 用户需求 | 主方法 / 后端 | 合并与分工 |
| --- | --- | --- |
| 多市场看盘 | 数据源插件 + data-access / canvas-control | 每张图明确绑定来源；MT5、AKShare、QMT、CCXT 按覆盖和环境选择，不自动互相替代 |
| 理解市场 | market-interpretation | 行为、制度、历史、叙事放进同一竞争性解释框架，保留反例和证伪条件 |
| 技术图解 | technical-analysis | Dow、Wyckoff、PA、Elliott、ICT、量价共用时点、确认和绘图规则；保留各方法差异 |
| 策略研究与因子挖掘 | quant-research | 创意、数据审查、生成、去冗余、评估、优化和样本外检验共用实验记录，失败尝试不能删去 |
| 可视化策略逻辑 | strategy-authoring | 只负责已定义 SVL 的写作、验证、图与参考回放，不在方法包中私自加语义 |
| 原生回测 | MT5 / vn.py / Backtrader | 各包说明原生语言、引擎、支持范围与撮合假设，不重复实现宿主策略语言 |
| 交付报告 | reports | 所有方法使用同一报告能力，保留真实来源和计算成果，不再单建同义排版包 |
| 长期复盘 | judgment-evolution + memory | 个人可验证判断与单轮因子/策略实验分工，不作为伪用户消息触发 |

方法包不默认携带所有后端，后端包也不替用户选择理论。通用九包维持基础工作能力；新增专题包按需发现、安装和加载。名称相近并不意味着方法一致，合并要记清保留了哪一部分、冲突如何处理、哪些没有采用。

## 来源与作者权益

- 优先使用对应版本的官方文档、源代码、原始论文、作者公开材料和正版出版信息。引用真实 URL、版本或提交、获取日期及所用章节或概念。
- QuantSkills 是参考发现入口。条目收录、项目自述与已经执行的验证分别记录，不把目录中的全部项目当成 Sesame 已安装功能。
- 每包维护 `PROVENANCE.md` 和必要的主题参考文档：原创说明、借鉴来源、实际复用文件及许可证分开。保留原作者、许可证与需要的声明，不复制未授权书籍全文或无明确复用许可的代码。
- 原创 wrapper 的许可证不覆盖外部引擎；依赖在用户环境中独立发现或准备，不能将第三方程序描述为 Sesame 自有组件。

## 发布与验收

1. 独立分支完成实现、来源记录、去重映射与适用范围。默认发现状态，不改变九包默认集合。
2. 对真实宿主做 `plugin_test`、安装、同会话加载和工具/Skill/资源读取；各插件不得依赖本体私有模块或新增供应商分支。
3. 后端提供明确的环境发现/准备方式、取消与清理行为、来源/时间/单位，并实际执行对应引擎或只读数据请求。固定合成样例只能证明代码流程，不能冒充市场实绩。
4. 方法脚本检查时间可见性、前缀稳定性、空值/错误和可重复性；因子评估另检查数据泄漏、多重试验、样本外划分与成本口径。通过代码检查不代表预测有效。
5. 固定 PR head 经独立审查后运行 gate；合并触发发布，核对实际资产字节后再生成安装目录、同步官网。本体只更新不可变锁，不复制插件源码。
6. 在真实模型会话中从公开目录选择和安装多个包，检查即时生效、按需路由、数据与报告成果及重启后的选择保持。没有券商环境的后端标明未验范围，不尝试未经任务授权的订单。

每轮实际通过与未通过的项目、精确版本和证据另存验收记录。新接口语义若确实不够，先交独立 Agent 研究成熟系统、提出设计与确定性示例，再讨论宿主扩展；不能为单个插件临时添加操作符。
