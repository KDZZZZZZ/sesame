# Independent factor evaluation

This is a numerical method for a trusted workflow caller. factor_evaluate requires a real nested host.capabilities.invoke invocation; a direct main-Agent call is not a supported entry. One declared consumer is auto_factor_start with evaluator:{plugin_id:"sesame/factor-evaluator",tool:"factor_evaluate",arguments:<dataset split and gate options>}; other workflow plugins may implement the same sesame.factor-evaluator/v1 protocol. The caller owns research questions, candidate generation, complementary methods and final synthesis. The evaluator supplies measured evidence without choosing an Agent arrangement or publishing a final report.

A single symbol can use the workflow and this evaluator: dataset.mode:auto chooses time-series for one development symbol; cross-sectional mode is the particular method that needs four aligned assets. time-series measures each symbol's factor/forward-return association and then averages symbols equally. It does not turn an IC into a strategy win rate or per-trade R. Read relevant factor/strategy knowledge, obtain suitable data with source capabilities, and combine execution-aware backtests when the user's target needs trade outcomes. A missing input or a narrower metric is a reason to find a suitable complementary capability, not to dismiss the user's idea or make them solve an ordinary data-preparation problem.

Choose optional diagnostics by what they answer: placebo tests alignment against a null control; monteCarlo explores empirical return-path dispersion; outOfSample distinguishes development validation from frozen-selection holdout; walkForward checks fixed-candidate chronological stability; sensitivity checks local parameter neighborhoods; regimes conditions results on a supplied PIT state field; bootstrap estimates block/paired confidence intervals; dsr adjusts Sharpe for a complete registered search and nonnormality; pbo assesses maximum-Sharpe selection overfitting using the actual synchronous full-trial return matrix. Pass only useful items in options.evaluationPlan.tests (or options.diagnostics). DSR/PBO are deferred until select; never supply only winners or fabricate missing return periods. Unrequested checks stay not-requested. A missing state field, parameter-free expression, short sample or individual diagnostic error must not block useful remaining measurements, other candidates or the final report. Preserve those statuses in the handoff. completed means the computation completed, not that the idea passed a universal test. DIAGNOSTICS.md lists the exact configuration and methods.

Thresholds are evidence by default. In 1.2, legacy minRankIC/minCoverage/maxCorrelation are advisory even when an Agent supplied them. evaluationPlan.thresholds entries {metric,value,operator,mode,source,reason} gate only when source:user AND mode:required represents an explicit user instruction. Do not relabel Agent choices as user requirements. Choose tests and reasons to match the task; use conditions and counterexamples instead of a universal all-tests-pass score. Measured development subsets can support conditional consideration when overall validation association is unavailable; wholly unmeasurable candidates remain ineligible. User hard requirements cannot be bypassed by conditional wording. An empty selection is valid and does not claim holdout evaluation.

Input is either an already registered dataset_id or options.inputRef containing a complete fixed data ArtifactRef; choose exactly one. With auto_factor_start, place inputRef in config.evaluator.arguments and omit dataset_id. The fixed json-rows panel must already have {time,symbol,availableAt,fields:{close,...finite numbers}}; raw market rows, workspace paths and guessed IDs do not substitute for it. The evaluator reads the exact published revision, checks manifest/content identity and preserves provenance without registering a new dataset or inventing timestamps. The candidate is the AST itself, for example {op:"field",name:"signal"}, not an expression wrapper or executable code. prepare returns candidateExample and development-only rows; candidate returns measured metrics, eligibility and training-only redundancy; select computes complete-search diagnostics and freezes eligible IDs with measurable evidence; finalize uses the returned selectionDigest and preserves evaluated versus not-requested holdout status. These are data-state prerequisites, not a prescribed research itinerary.

The caller retains data.inputRefs and provenance for audit and binds inputRefs into its final report dependencies. In restricted mode, do not disclose original input references or their provenance references to research roles before selection: a published Ref can be read with host.resources.read. Give those roles only development evidence and non-addressable source summaries. Development-only mode rejects rows after validationEnd and makes no holdout claim.

Return receipts, sample counts, coverage, undefined metrics, redundancy and data identity to the caller. Multiple metrics from the same dataset are related observations, not independent confirmations. Reuse an existing receipt for the same immutable inputs; an empty eligible selection is valid. Unknown outcomes retain the original request for an idempotent retry, while EVALUATION_REJECTED permits correcting an uncommitted proposal. Failed attempts retain their digest and reason; HARD_REQUIREMENT_UNMET prevents freezing a selection that violates an explicit user requirement. Missing input or consumer support is a specific dependency gap for the calling workflow to resolve.

The registered capability usage gives the invocation shape and action requirements. PROTOCOL.md describes composition; README.md documents dataset format and numerical assumptions. Read the relevant section when it resolves a concrete question, rather than rediscovering hidden APIs or inspecting private implementation files.

Treat any conditions identified or discovered on development data as exploratory, not independently validated. Preserve evaluation.conditions, invalidations, evidenceStatus and full diagnostics, including unfavorable strata. A conditional research selection does not establish a reliable strategy or exempt an explicit user hard requirement.
