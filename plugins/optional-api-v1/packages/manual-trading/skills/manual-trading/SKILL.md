---
name: manual-trading
description: Carry out user-directed manual MT5 or QMT trades with fresh native quotes, a short decision deadline, one guarded submission, durable deduplication and order/fill recovery.
---

Use this when the user wants you to place/manage a specific trade or follow an explicitly bounded discretionary trading task. This is a manual Agent workflow, not a permanently running strategy engine.

1. Load the already installed backend and read `manual_trade_inspect`. Reuse its existing account and environment. MT5 requires plugin 1.3.0+ and its official Python SDK channel; QMT requires plugin 1.2.0+, authorized native Windows MiniQMT and an existing STOCK account. Do not enable a disabled plugin or invent live trading for CCXT, AKShare, vn.py or Backtrader. Pure MT5 MCP is described in BACKENDS.md but does not establish UTC quote freshness for this wrapper.
2. Complete research before beginning a time-sensitive decision. Choose M5 or longer. The current version rejects M1. Multi-minute model reasoning, lengthy subagent research or stale input cannot become a timely signal just because the order API is fast. A five-minute chart also does not excuse sending a five-minute-old decision.
3. Call `manual_trade_observe` with the exact backend symbol. Read account identity, source quote timestamp, conditions, positions and the returned expiry. Use this quote in the decision. The observation is valid at most 60 seconds from its **source time**, not from when you finish thinking. Never manufacture an observation timestamp or refresh merely to relabel an old decision.
4. Once the decision is ready, call `manual_trade_execute` exactly once with stable operation_id, observation_id, user_authorized:true, action, side, quantity and price_limit. These reflect the user's requested trade/risk bounds; do not invent position size or authorization. MT5 quantity is lots; QMT is integer shares and limit orders only. `close` targets an exact MT5 position_id and opposite side. QMT reductions are sell limit orders within actually available shares/T+1; there is no dedicated close or short-sale wrapper. `limit_price` applies only to limit orders; optional MT5 stop_loss/take_profit are not supported on QMT.
5. The backend checks account/specification/available position, deadline and fresh tick inside its native process, then sends once. MT5 also uses order_check and refreshes the tick afterwards. Quote age must be ≤5 seconds and quote-to-send ≤1 second. Broker network/acceptance/fill can still take longer; these are separately measured. An absolute `price_limit` bounds the quote used for the decision, not guaranteed market fill/slippage. Use a limit order when an absolute order price is required.
6. Read `status`, native receipt and timing. A returned MT5 tool is not necessarily a successful trade; retcode matters. A QMT order ID is submitted, not filled. `outcome_unknown` means a timeout/disconnection may have happened after submission. Use `manual_trade_status refresh:true`; never resend with another operation_id, and never infer no trade from an empty/missing history row. The plugin blocks a new order on that account while a previous result is unknown. Positive native order/deal evidence can resolve it; incomplete history may require the user's terminal view.
7. Cancel a confirmed pending order using a new operation_id and original_operation_id. `cancel_requested` is not confirmed cancellation; query original orders/fills. A filled position requires a separately authorized close/reduction, never a cancellation disguised as one. Full/native advanced order modifications remain in backend tools; read their actual schemas in TRADING.md first.

Keep the final report useful: account/symbol/side/quantity, submitted vs filled vs unknown, actual native IDs, requested limits, source time, model round-trip age, native quote-to-send time and send-to-receipt time. Identify any missing evidence. Do not call a local fixture benchmark proof of real model/broker M1 capability, profitability, zero slippage, or precisely once delivery across terminal crashes.
