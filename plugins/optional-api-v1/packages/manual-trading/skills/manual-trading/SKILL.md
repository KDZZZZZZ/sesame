---
name: manual-trading
description: One-shot read-only multi-Agent research, or authorized scheduled target execution, using declared capabilities and one native workflow Run.
---

The goal follows the user's scope: advisory Markdown research, or an explicitly authorized target portfolio with a verifiable execution receipt. Installation does not create a trading plan. The execution binding selects an independent account/target capability; research.plugins and optional research.tools select declared research capabilities. The plan freezes those revisions and configured models so a later change cannot silently alter its evidence or execution contract.

External research defaults to sesame/financial-research with financial_research_status, financial_research_query and financial_research_read. Select these in research.plugins/tools unless the user explicitly declines this plugin; preserve that source choice or explicit opt-out in instructions for the members. Other research providers, direct websites, browsers and search methods require the user's explicit opt-out, including when used to supplement this source. Missing installation, credentials, paid access, quota or target coverage identifies a dependency to resolve, not permission to switch. Interrupt an affected running workflow for the main Agent and retain its evidence; the main Agent can repair the selected source with declared capabilities and already supplied credentials, then verify and resume the original workflow. FMP stock news is not general search and does not guarantee XAUUSD or macro-event coverage. Only goal-relevant providers need configuration; account reads, local calculations and declared analysis methods remain available for their own purposes.

For read-only analysis call manual_trading_analyze once with {request_id,title,symbols,execution,model,research?,instructions?,agent_models?,debate_rounds?,report?}. It creates one native workflow with analysts, bull/bear review, risk review and Markdown synthesis; all member Runs belong to it. Do not manually spawn parallel host.agent.run roots or copy a collaboration declaration per member. It never saves executable targets, creates an executor, sends trades, manages positions or schedules recurring work. Confirmed trading-risk rules are not prerequisites for advice; list unresolved rules and protection as requirements before any later trading.

Required setup: model access is configured in the host and manual_trading_models returns the exact {provider,id,configurationDigest?}; the selected native account/terminal must be configured, then the execution producer returns {plugin_id,context_tool,apply_tool,arguments}. Research depends on the question: research.plugins/tools selects only the needed sources and methods, whose public capability schemas/usage and readiness/status describe their actual configuration. With financial-research, financial_research_status({}) returns sources:{provider,kinds,configured,required_environment_names}; the main Agent can save already supplied keys with financial_research_configure({credentials:{fmp_api_key,fred_api_key,...}}), while optional *_env fields choose variable names. A configured variable does not prove access or source coverage; verify with an actual query. Credentials stay in the selected source configuration; missing required evidence interrupts the same Run and identifies the actual missing source/settings for the main Agent, retaining partial findings.

Optional analysis configuration: instructions gives timeframe and question; agent_models overrides named research roles, otherwise they inherit model. debate_rounds defaults 1 (1–3). report defaults false, keeping the summary and member Markdown in the Run without a report file; report:true reserves/publishes one report only when requested. A stable request_id deduplicates identical input. manual_trading_runs reads the business id; manual_trading_activity opens its process; the returned workflow.id controls native read/wait/resume. Full shapes and configuration ownership are in README.md.

Analysis filters explicitly declared trading/configuration/terminal/workflow-control effects and the binding's write tools. With an explicit research.tools list it reports all excluded names; otherwise it selects the remaining research subset. Evidence caching/publication is allowed. Dynamic read APIs remain subject to their producer's operation-level boundary, not a promise of arbitrary native-code sandboxing.

manual_trading_plan saves the explicit configuration. A stable request ID starts one immediate cycle through manual_trading_run; named events and a minimum five-minute interval support scheduled work. Main-session controls own plan changes, pause/resume and run cancellation. A resumed plan produces new work; it never replays an uncertain old order.

A dependency interruption is separate from pausing a schedule. The saved run's workflow reference is controlled by host.runs.interrupt/resume; resuming retains its original Run/session, accepted role Runs and committed decision/execution receipts. Missing dependencies are checked before roles start. A sent action without a saved receipt requires reconciliation of its original operation IDs, never a replacement run.

The public execution producer for configured MT5/QMT accounts is portfolio_execution_configure({backend:"mt5"|"qmt"}); its returned {plugin_id,context_tool,apply_tool,arguments} is the plan.execution value. Its context(identity) supplies the complete composition contract. Native mt5_trading_context identity only supplies an account and cannot replace that contract. Other implementations of COMPOSITION.md are valid. Installed capabilities are listed by plugin_discover/host.capabilities.list; an absent optional implementation is found through plugin_catalog({plugin_id}), not source-code inspection.

H1/1h is an analysis timeframe, independent of interval_minutes. manual_trading_analyze does not accept schedules. Authorized trading plans use single/team and both include execution; no interval defaults to null, enabled defaults to true, and a requested draft uses enabled:false. Research scope cannot be widened into recurring trading authorization by choosing a mode or writing instructions.

manual_trading_context supplies paged account facts, all-origin positions, orders/fills, mounts, peer reports and memory. The required evidence follows the question: research roles can use only the selected capabilities, and downstream roles consume the actual prior results. Limited coverage or contradictory findings after a relevant investigation can justify unchanged targets. Missing access to evidence required by the role instead interrupts the Run through the standard host_runs_interrupt({reason}); omit runId to target the current host Run. Another role's analysis cannot replace that goal. Account quantities use the execution binding's declared units, signedness and integer rules.

In an authorized trading plan, the manager records its decision with manual_trading_decide. Omitted symbols stay unchanged; an explicit zero closes the symbol's actual positions, including quantitative holdings. pause_strategies identifies an observed risky deployment and reason. The executor calls manual_trading_apply, preserving exact operation IDs and receipt states; stopping a strategy does not prove its positions closed. Unknown, partial or pending outcomes require reconciliation rather than a replacement operation.

Decision evidence names its real storage interface. evidence_dataset_ids refers to host-saved datasets. For plugin-owned data pass evidence_sources:[{datasetId,source,query}], using the exact descriptor returned by financial_research_query or another declared source. For published data such as ABU result_artifact, pass evidence_artifacts:[ArtifactRef]. The controller reads complete content and data dependencies before freezing the decision; publication never upgrades user-input or synthetic provenance to an external fact.

The native workflow Run declares the frozen plan's Agent collaboration: analysis has analyst evidence, bull/bear debate, risk review and manager synthesis; authorized single uses manager→executor, and authorized team adds executor to the research roles. Stable identities remain unchanged across debate rounds. Actual child Runs, iterations and result-consumption events are work details, not the source of graph topology. manual_trading_activity opens this host view; roles use output:none and share Markdown conclusions without separate files. Trading publishes one report, analysis does so only with report:true; analysis also attaches its Markdown summary. manual_trading_report reads an existing artifact; user edits, moves or deletion remain authoritative.

manual_trading_review preserves trading-case evidence and uses genuine subsequent observations, never implied gains from a target. Prospective judgments, verification, calibration and criteria use the independent sesame/judgment-evolution plugin. It must be installed and enabled; host.capabilities.list supplies its registered judgment_* declarations and the plugin supplies their usage. These management capabilities are main-session only. If unavailable, report the missing dependency; manual-trading has no judgment forwarding tools. A role can consume an existing criteria ArtifactRef through an explicitly allowed host.resources.read. Old private histories remain in place without automatic import. Controlled fixtures establish interface behavior, not broker latency or trading performance.
