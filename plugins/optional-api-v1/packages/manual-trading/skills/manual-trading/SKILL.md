---

Use the user's existing trading scope and risk requirements. Installation or research alone does not create a live plan. An authorized recurring plan continues without repeated permission questions.

1. Read backend resources. Load manual-trading, the configured MT5 1.5+/QMT 1.3+ backend and financial-research. List models with manual_trading_models. Save a plan through manual_trading_plan; agent_models maps every role to its own configured provider/id. Reuse account configuration.
2. Set a minimum five-minute interval, named event keys and/or supported account events (currently MT5-only). manual_trading_run starts an immediate cycle with a stable request ID. Configure/pause/resume plans and read/cancel runs from the main conversation.
3. Plan tasks read manual_trading_context with all required pages: all-origin positions, orders/fills, mounts, prior decisions and peer reports. Reference research dataset IDs and explain unavailable sources/time boundaries. Use manual_trading_review only once real subsequent evidence exists.
4. Analysts share source-backed reports, bull/bear respond within bounded rounds, risk reviews exposure, and manager calls manual_trading_decide. Use signed MT5 lots or nonnegative QMT shares. Allow unchanged. Omitted symbols stay unchanged; zero closes all actual positions for that symbol, including quantitative-strategy holdings. For extreme risk from continued mounting, add the observed deployment ID and reason to pause_strategies; no extra permission switch.
5. Executor calls only manual_trading_apply, without bypassing it through underlying broker tools. It stops risky EAs, checks remaining quantities and fresh quotes, then submits once. Targets over five minutes need reassessment; atomic observations expire after 60 seconds, source quotes after five seconds, and final quote-to-send after one second. Unknown/partial/pending outcomes require reconciliation rather than replacement IDs. Market fills can slip.
6. Reporter calls manual_trading_report after the business run finishes. Research 手工交易日报/<plan>/ contains HTML, JSON and immutable evidence. Main Agent can recover pending archives. A target, accepted order, stop request or missing broker row is not proof of execution.
7. Merged manual_judgment_* tools provide prospective probability judgments, frozen evidence, reflection and rule evolution. Keep old history until intentionally migrated. Never change verification criteria after the fact or count unexecuted targets as returns.
8. Main Agent can open manual_trading_activity for an existing run. The localhost page follows real tasks and successful report reads; public messages appear below the workflow for page scrolling. Pausing or replaying the picture has no trading effect. Preserve mock-response/truncation labels. Archive after every task finishes for a self-contained collaboration recording alongside the daily report.

For an authorized one-off trade, manual_trade_observe/execute/status/cancel remain main-conversation tools with existing guard/idempotency semantics. A cancel request cannot undo a fill; position reduction is separate. Controlled fixtures do not establish live latency or profitability.
