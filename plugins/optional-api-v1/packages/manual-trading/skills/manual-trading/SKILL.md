Use the user's existing trading scope and risk requirements. Installation or research alone does not create a live plan. An authorized recurring plan continues without repeated permission questions.

1. Read the selected capability resources. Load manual-trading and the execution capability the caller selected. Configure that capability first, then use its returned generic execution binding; never choose a backend inside this workflow. Select arbitrary installed research/skill plugins with research.plugins and optionally narrow their delegatable research.tools. List models with manual_trading_models. Save a plan through manual_trading_plan; agent_models maps every role to its own configured provider/id. Reuse account configuration.
2. Set a minimum five-minute interval, named event keys and/or supported account events declared by the selected capability. manual_trading_run starts an immediate cycle with a stable request ID. Configure/pause/resume plans and read/cancel runs from the main conversation.
3. Plan tasks read manual_trading_context with all required pages: all-origin positions, orders/fills, mounts, prior decisions and peer reports. Reference research dataset IDs and explain unavailable sources/time boundaries. Use manual_trading_review only once real subsequent evidence exists.
4. Analysts share source-backed reports, bull/bear respond within bounded rounds, risk reviews exposure, and manager calls manual_trading_decide. Use the unit, signedness and integer rules in plan.execution.quantityRules. Allow unchanged. Omitted symbols stay unchanged; zero closes all actual positions for that symbol, including quantitative-strategy holdings. For extreme risk from continued mounting, add the observed deployment ID and reason to pause_strategies; no extra permission switch.
5. Executor calls only manual_trading_apply, without bypassing it through underlying broker tools. The independent capability stops risky mounted strategies, checks current quantities and quotes, then applies its own guarded idempotent execution policy. Unknown/partial/pending outcomes require reconciliation rather than replacement IDs. Market fills can slip.
6. Every role uses output:none and shares its conclusion inside the run; do not create per-role daily reports. After all business tasks settle, the reporter calls manual_trading_report once for the whole run. Research 手工交易日报/<plan>/ contains one final HTML, JSON and immutable evidence. Main Agent can recover pending archives idempotently. A target, accepted order, stop request or missing broker row is not proof of execution.
7. Merged manual_judgment_* tools provide prospective probability judgments, frozen evidence, reflection and rule evolution. Keep old history until intentionally migrated. Never change verification criteria after the fact or count unexecuted targets as returns.
8. Main Agent can open manual_trading_activity for an existing run. The HTML in Sesame’s report panel continuously follows real tasks and successful report reads; public messages appear below the workflow for page scrolling. Preserve mock-response/truncation labels. There is no replay and no separate collaboration archive. The legacy archive action returns the same final summary after every task has settled.

One-off manual_trade_observe/execute/status/cancel tools now belong to the independent portfolio-execution implementation; they are not required by this workflow. Old workflow plans must be rebound explicitly after upgrade; legacy execution receipts can be exported through the read-only migration bridge. A cancel request cannot undo a fill; position reduction is separate. Controlled fixtures do not establish live latency or profitability.
