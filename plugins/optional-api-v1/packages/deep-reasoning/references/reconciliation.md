# 跨路径核对与定向修订

本页在 H / D / G 首次独立结果冻结后使用。所有适用路径须先完成内部检查，缺陷未修复的结论不能成为综合的已定前提。

## 先确认是否真的冲突

对 H↔D、H↔G、D↔G 逐对比较。把相关主张统一成：

`对象、目标结果、总体/范围、时间、成立条件、模态/概率、支持前提 ID`。

将关系区分为：一致、互补、定义差异、时间差异、条件差异、证据冲突、推断冲突、模型分歧。估计不同也可能是值得研究的实质分歧，不必是严格逻辑矛盾。相反，短期与长期、试点与全面应用、不同市场状态的结论，不应仅因措辞相反就判冲突。

## 只修最小责任链

记录冲突主张 ID、各自前提和依赖链。定位造成差异的最小部分；能形式化时寻找最小不一致前提集合。不要因局部问题重做所有路径或放弃全部已验证证据。

| 操作 | 用法与边界 |
| --- | --- |
| 撤回 A | 暂时不用 A，检查它是否必要；不等于证明非 A |
| 取反 A | 在非 A 下做反事实检验；不等于确认非 A 为事实 |
| 弱化 A | 将过强的普遍断言改为有证据支持的条件断言 |
| 拆分 | 区分行动者、阶段、状态或术语含义；须与实际问题和证据对应 |
| 替换 | 用有依据的候选机制 B 替换 A，比较解释力与额外假设 |
| 补全 | 加入确实遗漏且有依据的变量、反馈、激励或机制 |
| 修复推断 | 保留有支持的前提，修正无效推导 |

先开临时版本测试，保留原冻结结果。尚未证实但有理由提出、能够区分检验的假设，可以作为明确标记的 A 进入临时分支；不要求反事实先被证明真实。表中的依据要求不能用于禁止此类探索，也不能把试验分支写成事实。永久修改需说明新证据、无效推断、错误适用范围或更有解释力且可检验的模型依据，不能只因另一成员不同意而改答案。

## 提出可检验的综合候选

候选可由共同驱动、不同演变阶段、条件边界、行动者响应改变约束，或某条推断错误来解释。优先保留已支持的事实与有效推断，增加解释覆盖，减少**无依据**的额外假设，并提出能区分替代解释的观察。不能增加不可见机制只为消除矛盾。

只重算受影响路径，再让适用方法各自核验候选，不以投票或统一措辞代替验证。保存原版本、新版本、实际修改、依据及受影响主张。若新增证据改变共同输入，生成 E1，并标明哪些成员需复核；不偷偷让成员拿不同资料比较。

## 进展与停止

每次定向迭代至少带来一项实质进展：消除矛盾、发现无效前提/推断、缩小冲突依赖、得到有意义的条件或时间拆分、增加有依据的解释，或形成新的区分性检验。同一失败操作没有新输入时不重复。

连续两次定向迭代无实质进展，检查是否还有真正不同且有理由的修订方向；没有就停止此轮调和。之后只因新证据或新理由重开。用户暂停、时限或预算等明确约束优先，不将方法写成无限工作循环。

“调和”要求：解释相容、修改有依据、条件或阶段差异真实、与事实兼容、没有夹带无支持机制；不要求所有表述或概率完全一致。经过定向尝试仍未调和时，列出精确的备选解释、已经尝试的实质修订、尚缺哪项可区分证据及可行的下一检验。不得以“存在分歧”提前退出，也不得把暂时不能区分写成支持其中一方。
