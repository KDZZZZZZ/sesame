# 问题、证据与成果协议

## 固定共同输入 E0

先从用户需求和已有材料提取；能自行发现与补齐的证据通过当前可用的数据、搜索或分析插件取得，不把准备表格推给用户。仅当关键歧义会实质改变问题时再询问，同时推进不依赖它的工作。

| 字段 | 内容 |
| --- | --- |
| question | 解释过去、预测未来，或二者；明确要回答的命题 |
| outcome | 目标结果及可观察的衡量方式；尚未证实发生的事件不能先当作既成事实解释 |
| scope | 系统边界、资产或参与者总体、单位与必要术语定义 |
| horizon | 研究截止时点、所研究的历史区间或未来期限 |
| evidenceVersion | E0；补证据后增为 E1 等，注明受影响路径 |
| evidence | 编号、类型、具体内容、来源与日期；估计须写方法，假设须写条件，未知须写待核问题 |

证据类型：**F** 已记录观察，**M** 测量或估计，**A** 暂定假设，**U** 未解事实问题。每项有稳定 ID。来源保留实际链接、文档位置或固定数据引用；缺失来源标为缺失，不制造引用。F 不能只是一段因果解读；M 保留测量误差与口径；A 不能在后文悄悄变成 F。定义有多个含义时拆开或声明工作定义。

E0 的门槛：问题、结果、范围、期限和前提状态明确；不夹带 H / D / G 的预期答案。原始用户观点可作为待检命题或 A，不能成为所有成员必须支持的结论。冻结的是本轮共同输入，不是禁止发现新证据。

## 各路径的窄交接内容

每个成员只交回与问题有关的可审核分析摘要：

- `path` 与 `version`：H0 / D0 / G0；发生有依据的更正才增加版本。
- `evidenceVersion` 与 `applicability`：使用哪版共同输入；适用或不适用及原因。
- `claims`：每项包含 ID、主张、前提 ID、机制摘要、成立条件、支持与反向证据、证据缺口。没有依据的环节明确留空或列为假设。
- `checks`：各自方法的核验结果、具体缺陷与已作修正。通过表示未发现已知实质缺陷，不证明所有前提真实。
- `conclusion`：针对原问题的条件化回答；概率只在存在可信估计方法或校准依据时给出，否则用有解释的定性判断。
- `revisions`：若有，只记修改对象、依据、影响，不交出逐字内部推演。

内部校验依次核对：前提能否同时成立；结论是否由这些前提支持；对象/时间/条件是否偷偷变化；证据和假设是否混用；该方法的特有要求是否满足。有缺陷的推断不能作为综合阶段的已定事实。

## 综合与最终检查

先冻结各路径结果，再进入跨路径核对。没有实质冲突可直接综合，不为完整形式制造一轮争论。

未来演变可按“初始条件 → 主要制约 → 行动者响应 → 结构变化 → 条件结果”解释；过去成因可按“已记录顺序 → 候选机制 → 可观察行动 → 因果推断 → 待核证据”解释。共同、互补、调和后的发现可以整合；未解备选保留各自证据和区分检验。不得平均不兼容的预测，也不得将同一来源经三种方法解释后计为三份独立证据。

只做一次聚焦检查：仍回答原问题；H / D / G 先独立后综合；内部推断成立；分歧已归一化；永久修改有依据；未藏起矛盾或补造机制；事实/假设/结论清楚；信心与证据一致。通过即交付，发现具体材料缺陷才重开受影响部分。

报告围绕用户能用的信息组织：直接回答、证据与机制、演变条件或情景、需要时的不同解释和下一观察。无需机械生成七个章节或三个互不相干的长篇。重要结论追溯至 E0 项及路径版本，只有确实改变判断的修订需要进入正文。图表使用报告插件现成组件与统一渲染；有实质分岔时可用决策树表达条件。
