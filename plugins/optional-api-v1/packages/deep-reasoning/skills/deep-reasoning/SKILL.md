# 深度推理

主线：**独立发现 → 各自校验 → 相互核对 → 定向修订 → 综合解释**。沿着用户的问题探索其成立条件；提出不同解释时说明证据和可区分的观察，不因方法或知识不足直接否定用户。

## 先选择本次职责

- **主 Agent / 协调者**：先读取 [协议与证据](references/protocol.md) 和 [实际编排](references/coordination.md)。固定 E0 后提交独立 H / D / G 成员；收齐并核验实际输出后比较。仅在有实质分歧时读取 [定向复核](references/reconciliation.md)。
- **历史成员 H**：只读取 [历史类比](references/historical.md)，使用 E0 和自身方法，不读取其他成员尚未冻结的分析。
- **矛盾成员 D**：只读取 [矛盾分析](references/contradictions.md)，遵守相同独立性。
- **博弈成员 G**：只读取 [博弈分析](references/game-theory.md)，遵守相同独立性。
- **复核 / 综合成员**：读取协议和定向复核页，使用已经冻结且核验过的成员结果。成员身份由本次任务明确指定，不自行扩成另一套团队。

## 五条原则

1. 先独立推断，再综合；首次 H / D / G 不接收其他路径的临时结论，也不接收协调者指定的答案。
2. 冻结结果的永久修改必须有明确的证据、推断或模型依据。反事实只作为临时分支，不覆盖原结论。
3. 实质分歧先针对具体前提或推断尝试调和，再决定是否保留未解状态。
4. 不强迫一致，不补造事实、行动者、协调关系或隐形机制来拼接故事。
5. 解释自洽不等于经验上真实；置信程度跟随证据，独立方法不等于独立证据。

## 七个阶段

1. 明确问题、目标结果、范围和期限，将事实 F、估计 M、假设 A、未知 U 固定为 E0。
2. H / D / G 从 E0 独立分析，保留可审核的前提引用、机制、结论与条件，冻结 H0 / D0 / G0。
3. 各路径检查前提兼容、推断有效、范围一致、证据归属和自身方法要求；有缺陷只修相关部分并增加版本。
4. 将主张统一到相同对象、结果、范围、时间、条件与确定程度，逐对比较 H↔D、H↔G、D↔G。
5. 有实质冲突时，定位最小责任依赖链，临时撤回、取反、弱化、拆分或替换假设，补充有依据的机制，或修复推断；只重算受影响路径。
6. 区分共同发现、互补解释、已调和分歧和剩余备选，给出整体机制与可观察的分岔条件。
7. 做一次有针对性的最终检查，然后交付。只因具体实质缺陷重开，不进行无止境的自我反思。

某方法没有可用参照、真实矛盾或有意义的行动者时，简述不适用的原因，其余路径继续独立。无法并行时分别完成并冻结分析摘要，说明采用单 Agent 多方法复核，不声称已完成独立团队验证。两次连续定向修订没有实质进展且无新检验方向时保留明确备选，不反复改写同一解释。

## 交付

返回直接回答、关键证据、条件化机制、尚有分歧时的备选解释，以及能区分它们的下一项观察。保留来源和必要的修订依据，不输出逐字内部思考或无关试错记录。完整研究或复杂分析使用 `sesame/reports` 发布并核验统一视觉报告；作为已有研究的内部阶段时只向调用者交回本阶段结果，由唯一交付者汇总。

方法校阅可用包内 [合成案例](../../examples/review-cases.md)。它们用于检查推断边界，不是实际市场证据。
