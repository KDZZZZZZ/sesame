Trading-decision turns fixed research, the actual account and applicable personal risk rules into an authorized target portfolio and real execution receipts. Its default is manager → executor. Installation does not create a plan. Research and a request for analysis are not trading or recurring-execution authorization.

Optional plan.workflow:{reviews:[{id,title?,instructions?}],execute:boolean} changes actual dispatch. Ordered reviewers precede manager and save their own immutable trading_decision_check({run_id,verdict:"allow"|"block",reason}); reviewers have account/research reads and no target-write/order authority. Any block prevents execution. execute:false saves the manager decision and report without an executor; native apply also rejects direct attempts. Omitted workflow keeps the existing default. agent_models may name review IDs. The frozen plan, checks and completed tasks survive same-Run recovery; changing them requires a new run. The main Agent turns applicable remembered workflow preferences into this explicit input.

The main Agent selects an appropriate research workflow first, for example investment_research_analyze, then passes its complete kind:data result_ref through trading_decision_plan.plan.research_refs. The trading manager uses data_read to consume the frozen result, dates, scope, limitations and evidence. It receives no news/search/research-method tool collection and must not create another research team. Missing necessary or current evidence is an interrupt with an actionable gap for the main Agent; it cannot be replaced by invented findings. Existing authorized risk reduction or closing positions does not require unrelated fresh research.

Model and broker access are configured in their owning host/native plugins. trading_decision_models supplies exact configured descriptors. execution is the complete binding returned by portfolio_execution_configure or another COMPOSITION.md implementation, not a guessed pairing of native account/order tools. The manager requires enabled sesame/memory (memory_trading_context, memory_read), sesame/data-access (data_read), and the execution binding's declared account/contract reads. No source API key is configured in this plugin.

The manager applies every confirmed risk rule whose scope matches the actual account, reading paginated/truncated rules completely and checking their version. Style is a preference; strategy knowledge is conditional; pending candidates are not confirmed rules. Increasing risk needs applicable confirmed rules and verifiable account/contract inputs. Use the selected read capabilities for position, quantity-step, currency, margin and loss calculations; assumed protective stops are not deployed protection. Research results are not current execution facts. State meaningful unresolved gaps rather than creating default risk percentages.

trading_decision_decide freezes targets and full evidence including plan.researchRefs. unchanged:true has targets:[]; quantity:"0" closes all sources for that exact symbol; omitted symbols remain unchanged. Quantity units follow the execution binding. pause_strategies stops observed risky deployments, independently of closing their positions. The executor only calls trading_decision_apply for that frozen decision; direct native order tools are not delegated. Accepted, pending or unknown results never imply fills or returns.

Only the main conversation configures plans and schedules. plan supports model, manager/executor/reviewer overrides, workflow, research_refs, symbols, instructions and explicitly authorized interval/event settings; there is no mode, debate_rounds or research tool selection. Native Run interruption/resumption retains accepted child identities, checkpoints, frozen decisions and receipts. The main Agent may fix resolvable dependencies and resume within existing authorization without a new user reply unless the host control contract requires one. Unknown external results require reconciliation under original operation IDs, never replay.

The completed-round report contains the manager's user-facing synthesis once; exact account, research and actual execution disposition stays in frozen run.json and the work process, including when execute:false or a review blocks execution. Claim delivery only from the actual published report; archival failure or a pending report must be reported as such. No reporter Agent or automatic concatenation is used. trading_decision_report reads the existing artifact and never recreates edited/deleted reports. trading_decision_review requires actual later evidence; targets or unchanged positions do not count as returns. Prospective judgment rules belong to sesame/judgment-evolution; personal preferences, risk red lines and strategy knowledge belong to sesame/memory.
