---
name: trading-decision
description: Convert fixed research, current account facts and personal risk rules into an authorized target portfolio with actual execution receipts.
---

Use this workflow for an explicitly authorized trading decision and, when enabled, execution. A research request belongs to a research workflow such as investment-research; it does not create trading authorization. The default workflow has a manager and executor. Optional workflow.reviews adds ordered read-only checks before the manager; execute:false or any block verdict prevents executor dispatch and target execution. There is no analyst team or research-source selection.

The main Agent provides an execution binding, configured model, symbols/instructions and optional complete fixed research_refs. A research result is a kind:data ArtifactRef with id, revision, digest and schemaVersion; consume it with data_read and preserve its time, scope, assumptions and limitations. If evidence essential to the decision is missing or stale, interrupt with that specific gap for the main Agent to resolve through a chosen research workflow. Do not start another research team. Already authorized reduction of exposure or closing positions can proceed when actual account and execution facts are sufficient.

The manager's available capabilities are trading_decision_context/review/decide, memory_trading_context/memory_read, data_read and the selected execution binding's account/contract reads. The executor only has trading_decision_apply. The plugin requires configured model/broker access and enabled memory/data-access; it stores no API keys. Full input shapes and configuration ownership are in README.md and COMPOSITION.md.

Treat personal risk red lines as binding when confirmed and applicable to this account. Complete paginated rule reads and verify versions; preferences, conditional strategy knowledge and pending rule candidates do not authorize risk. Use current account/contract facts for quantity, step, currency, fees, margin and loss exposure. Do not invent default limits or claim protection is deployed when the execution interface cannot deploy it.

The manager records a fixed decision before execution. unchanged:true means empty targets; an explicit zero closes all sources for that symbol, while omitted symbols remain unchanged. Pausing a strategy and closing a position are independent. Complete research refs automatically become frozen decision evidence. The executor preserves exact operation identities and reports actual receipts; submitted/unknown is not filled, and retries cannot create replacement orders for uncertain effects.

Optional interval/event schedules require the user's continuing execution scope. Pause cancels future/current decisions but cannot undo broker effects. Native host Run controls retain the same workflow, children, checkpoints and receipts; dependency resolution can resume without another user reply when authority already exists. No mode, debate configuration, research plugin list, compatibility alias or separate live HTML protocol is provided.

The program archives one manager-summary report when the round completes, including decision-only or review-blocked rounds, with the actual execution disposition and detailed evidence in the original work process and frozen run.json. Confirm the published artifact before claiming report delivery; report archival failures and pending delivery honestly. It does not add a reporter or append analyst documents. A later review uses real later observations; a target is not realized return. Independent judgment calibration belongs to judgment-evolution; long-term preferences, risk rules and strategy understanding belong to memory.

Report presentation follows the host-selected provider. The fixed document adapter first calls `host.reports.describe` and uses the `sesame/reports` facade only when that provider and its declared content/style schema are supported. An incompatible provider returns a specific unsupported result with the frozen decision and evidence retained; it never changes host settings or repeats execution. An Agent can instead read `host_reports_describe`, adapt the existing evidence to the returned inputSchema and publish through `host_reports_publish`; content/style is a Reports vocabulary, not the generic host schema. Do not upload HTML, CSS or scripts, or require a template step. Keep judgment, chart annotations, brief reasoning and material risk conditions in the body, with original account/research/execution records in the end appendix. The default Reports provider owns blue/gray borderless styling, LaTeX and reusable declarative style versions. Persist the exact published ref before checking; a failed inspection rechecks that ref and never replays trades. Presentation changes neither authorize execution nor reinterpret accepted orders as fills.
