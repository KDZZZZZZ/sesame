---
name: svl-mql5
description: Translate frozen SVL source to MQL5 with a pinned target, exact code bytes, source maps and declared semantic limits.
---

1. Author and freeze SVL with the strategy authoring plugin. Inspect the graph generated by the host from that same source. Change strategy logic in SVL first.
2. Call mt5_target and read target/README.md, target/sdk-integration.md and target/examples/Strategy.mq5 through plugin_read. The complete lifecycle example has no order logic. Read the packaged backend/sdk headers and implement the frozen SVL rules using the actual signatures. Keep authorization, cancellation, equity, transaction and OnTester result hooks. Do not guess template APIs.
3. For long source, read target/translation-file.md, write a JSON manifest in the workspace with the source and target ArtifactRefs, exact file text, parameter_map, one source_map entry per SVL node and all adaptations, then call mt5_translation_file with only operation_id and manifest_path. The manifest is the mt5_translation body without operation_id; no source text needs to be repeated in tool arguments. Small translations can still use mt5_translation inline. Retry the same ID/path to recover the fixed snapshot after a lost response or file cleanup; edits require a new ID. Unobservable nodes need reasons. A source map does not prove native execution. Binary64/decimal34 differences remain limited until validated under a fixed tolerance policy.
4. Use mt5_compile with the returned project_id and revision. Use mt5_backtest with the frozen build ID and explicit native Tester settings. Read actual results and failures; publishing a source, graph or translation is not a backtest.
5. Read each pass's actual run_record and result_artifact. Use mt5_report_data and report_data to freeze native datasets for reports. Read the reports plugin's skill; bind complete DataRefs, source/translation/result ArtifactRefs and the actual {id,version} run record through report_publish.related, then report_check. No MT5 components are inserted automatically. Never attach a legacy trace to an SVL node unless exact translation mapping and real instrumentation establish the relationship.
6. When deployment is intended, register mode:live and explicitly use ProductExecutionAllowed() in the source before compiling and backtesting. This mode supports Tester and the same frozen successful build can later be mounted. A live run additionally requires actual channel checks and the user's trading intent. Follow MT5 deployment tools and native account/position checks; do not replay unknown commands. Account balance changes from manual trades alone do not prove that the translated EA ran.

Declare every SVL parameter in `parameter_map`: use `{nativeInput:"ActualInputName"}` for scalar inputs and `{binding:"instrument"}` or `{binding:"account"}` for bound identities. Native quantity parameters use `lot`. Read the actual SDK signatures and use explicit source unit conversion if needed. The plugin expands SVL defaults and sends mapped values to the native engine.
