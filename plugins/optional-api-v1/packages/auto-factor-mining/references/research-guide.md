# 因子与策略研究的共同证据规则

目标是回答可检验的问题：某种机制在什么品种、期间和成本约束下，为什么可能优于明确基准，哪些观察会推翻它。方法、模型、研究方向及 evaluator 由任务决定；不自动遍历所有指标，不以方法数量或成员投票替代证据。固定相同输入，复用已有来源与计算回执，只补具体缺口。

研究前先形成精简判断任务单：用户决策/要Agent回答的问题、对象与期限、比较对象、用户指定角度、Agent补充角度（区分来源）、何种证据会改变判断。沿用现有需求交接和plan.reason；用户省略plan阶段时由首个研究成员在现有rationale等说明文字中记录，后续复用，不新增强制字段或另开模板。信息足够就说明合理假设继续，不重复询问；仅关键且无法合理推断的目标歧义才澄清。用户可裁剪问题与角度，Agent不能把自己的补充项说成用户硬要求。

取证、候选与试验分别说明在回答哪项判断、能支持或区分什么解释，不以资料和指标数量安排研究。假设、评审与反思回答各自承担的问题，已有清晰结论保持，只补必要缺项；用已有比较、机制、历史实际结果与反例说明判断，共同对象和期限可以沿用，不逐项填满一套说明栏。历史未检索、不可取得或不适用如实区分；确定性计算和用户偏好不硬造样本，不能从模型措辞补造概率。可用机制与历史参照支持范围明确的判断，不要求完整因果证明；已知适用/失效条件可以支持条件使用，不要求所有检验通过。具体指标、阈值、方法和评价范围仍由用户与问题决定。

因子假设写清经济机制、反证条件、表达式、方向、窗口、输入及单位、当时可用时间和来源引用。特征与成分必须在决策时已知，标签随后发生；不能用未来 shift、全期拟合或最终修订财报。保留历史成分、退市、复权和公告版本；时区转换需真实时钟依据。OHLCV 不能推造财报、订单簿、借券或资金身份。unknown/unavailable 不填零，也不靠删掉缺失尾部包装为完整样本。

实验先声明目标、基准、搜索空间、评价与停止口径和预算。每次表达式、窗口、方向、参数或样本变化均记录；失败、取消、常量、缺失与负结果也进入账本。标签跨分割边界要按已定义的 purge/embargo 处理。滚动前推的每折仅用其训练段拟合归一化、权重和方向；全期变换也会泄漏。

真实 evaluator 根据其候选协议产生实测回执，Agent 不补造指标，不为同一候选另外实现一套评价算法。检验计划按问题选择，用户明确要求的检验必须覆盖；诊断和 Agent 阈值默认 advisory，只有用户明确 hard requirements 才淘汰。整体或实际子情景有可测证据、且未违反用户硬要求时，可以有条件使用，记录 applicability 的适用/失效情景、实测依据、局限、监控/停用条件和反例，不要求所有诊断都过线。eligibility 不是未来盈利承诺。Rank IC、方向收益、分组曲线或训练相关性不能充当完整策略回测、成交收据、账户权益或因果证明。DSR/PBO 只接受 evaluator 的真实完整试验集结果；未算/不可算不补概率，不将因子诊断组合收益冒充原生成交收益。

开发数据用于提出、改进和选择候选，选择先固定再进行声明的留出评价。已接触的样本不能重新称 untouched。受限输入访问才能保留隔离留出；开放通用数据能力的会话使用 development-only，不声称留出验证。单 Agent 与多 Agent 使用同样隔离条件：研究 Agent 仅见开发证据，选择冻结、该 Agent 结束后才由原生工作流执行最终评价。留出结果不回流本轮选型。无合格候选也是有效结果。

策略层还必须明确何时决策、目标仓位、入场/出场、风险、订单、资金与恢复规则。用 strategy-authoring/SVL 或明确原生源码表达；不能无损表达就标 unsupported。因子统计 evaluator 与真实交易规则回测引擎承担不同任务；因子组合曲线通过不意味着已检验撮合、交易权限或策略可交易性。

回测引擎选择顺序：用户明确指定的引擎 → 预期交易平台的原生引擎 → 与实际数据/合约最一致的引擎 → 必要替代方案并明确差异。比如 MT5 数据且预期在 MT5 交易，优先考虑 MT5 原生 Strategy Tester；这不要求每次因子统计计算都运行 MT5。记录预期平台、来源、合约规格、交易日历/时段、点差/佣金/swap、成交规则和数据粒度的对应关系与差异。MT5 或其它原生引擎不可用时保留未验证状态及后续真实验证请求，不伪造回测成功，也不自动下单。

选定回测引擎若自带参数搜索或优化器，优先复用该原生能力。Agent 有明确机制或反证假设需要测试特殊参数组时，可提交定制组，记录假设、参数集合、预期观察与实际结果。搜索范围、目标函数、成本、约束、预算及全部失败试验仍需保留，不额外制造重复优化引擎。开发段选优与冻结后的独立检验分开，不能拿同一段优化结果再当样本外成功。

`config.strategyValidation` 保存预期平台及数据/成本/成交差异，仍是意图。显式 `config.nativeValidation` 可在因子选择冻结、研究 Agent 结束后调用已声明 Backtrader/vnpy/MT5 回测；Backtrader auto 搜索实际使用 Cerebro.optstrategy。MT5 原生 optimizer 必须以真实 catalog/schema 为准，宿主管理网格不是原生优化，本适配器未绑定的 optimizer 保留 unavailable。源码和固定数据窗口先冻结，开发选参用预先目标，之后单独 holdout；每次中断先查同一操作收据，不换 ID 重跑。原生源码是已编写策略，不会被自动宣称为因子候选的等价翻译。本机外部进程不属于因子 evaluator 的 sealed 环境。具体 schema 和边界见 `references/native-validation.md`。缺引擎不阻断因子研究，研究通过不授权实盘操作。

本包已融合因子与策略指南。`references/factor-method.md` 与 `references/strategy-evidence.md` 说明详细研究边界；`references/factor-cli.md` 与 `references/strategy-cli.md` 对应可选 `scripts/reference-factor.mjs`、`scripts/reference-experiment.mjs`。这些 CLI 是公开参考资源，不是注册能力，不自动执行，也不替代当前真实 evaluator。已有等价回执直接复用；可选 CLI 不认证外部历史真实性，也无法发现隐藏试验。

新研究交付到 Strategy。selection.reason与reflection.summary等现有综合文字开头直接给总体结论，下面按必要判断展开，用原有图表和短理由说明取舍。保留已有清晰结论、分析、图表和风格，只补缺失的必要结论；小标题说结论，摘要、卡片与图注不重复。对象和期限可共享，关键条件、代价与历史数字就近说明，完整证据在末尾；不逐项增加整套栏目，不为精简删重要结果，用户裁剪优先。保留候选、方法/版本、输入引用、实测数值、反证、失效条件及仍未完成的交易规则验证；完整试验账本与回执可供附录核查，不为写结论重选已冻结结果。真实报告路径、发布修订和渲染回执要实际核验。独立数据成果与聊天总结不等于报告交付。
