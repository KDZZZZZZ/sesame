# 单步执行与恢复

研究调度由 Agent/工作流承担。每次 prepare、search、compute、evaluate 调用对应一个宿主 native function Run；不存在隐藏总控、后台自动搜索循环或报告任务。open/read 只读写搜索会话，不启动数值探索。

调用受理后用宿主 Run read/wait 观察终态，并从 run.output 取固定结果。function Run 不会自动唤醒主 Agent；要在工作流中等待它，或由主 Agent 显式等待。不要把 Run ID、受理回执当作数值成果。

requestId 标识一次逻辑操作。同 ID 不同输入冲突；同输入完成后返回已固定结果，活动中重复调用拒绝。恢复不选择候选或发起下一阶段。搜索会话的 pending propose 必须使用同 requestId 核对后再请求新批次，避免跳过一次已消费的尝试。

暂停、恢复与取消使用宿主 Run 接口。安全 checkpoint 恢复会重建 handler，并核对已完成进程/不可变结果。正在执行的 host.process.exec 不支持盲目重放，可能使原 Run resume 拒绝；先观察旧 Run/进程状态，再显式重提同 requestId，由新操作核对保留回执或隔离重算。用户主动暂停后，需要后续用户指令才能恢复，不自行绕过。

若子进程状态仍为 unknown，不把已有文件当成进程已结束的证明，也不释放其预算或启动替代进程。须先核实原执行；只在宿主状态已确认停止后才能核对或重算。

每次提交检查当前 signal 与 CAS 栅栏，取消生效后不允许迟到入库；取消之前已经成功归档的证据保留。直接文件写入仅为本次私有临时内容，最终成果须经发布与事务确认。

每步有活动时间与 worker 输入/输出字节预算（请求、结果及数值文件）；JS 元数据受公开 schema 和 artifact 大小上限约束。搜索会话另累计候选尝试及资源消耗。暂停时间不记作活动时长。数据、环境或空间变化用新的明确请求，而不是偷偷扩大原预算。各进程 kernels=1；并行度由调用者决定。

报告由 Agent 在研究完成或阶段交付时调用报告插件生成，并检验统一视觉。这里返回矩阵/评价证据，不自动占用报告路径，也不自动修改策略因子池。
