# 从研究问题到报告

`investment_research_start` 负责执行研究，`sesame/research` 提供如何调查与回答的知识，`sesame/reports` 负责通用组件与统一视觉。主 Agent 选择实际来源、计算能力和模型，绑定 `task.output:{type:"report",space:"research",path:"...html"}` 后启动。简单问答不必启动本流程。

## 默认执行

1. **明确问题。** 沿用用户需求与已有证据，用 `research_methods({query})` 发现相近方法，`research_read({ids})` 读取少量相关正文，每次最多 5 项。常见问题的调查与回答结构是参考；没有精确命中时按相近结构适配，不把全部问题或建议栏目变成必填。目标、对象、期限和会改变判断的关键证据足够明确就推进，必要假设留在交接中。
2. **取得证据。** 按实际问题复用固定材料，只补有影响的缺口。已知可靠入口直接取得原文，未知入口使用已授权搜索；一个来源不可用时尝试授权范围内适用的其他来源。保留来源、发布时间、观察期、获取时间、覆盖与历史可用性；访问失败不是零结果。预测、规律或条件性建议需要实际历史支持时，同时保留适用历史和后来结果。
3. **研究与判断。** 组合选定的专业知识与计算方法，回答问题并检验竞争解释、反例和适用条件。可使用已授权安全来源补充具体缺口，或向原取证成员定向追问。理论、样本、时间隔离和用户要求仍须准确；不因方法目录存在就做全部检验，不用同源指标数量或成员投票替代证据。实际无法取得的材料保留尝试及边界，仍给出有支持的较窄结论，不虚构概率。
4. **交付报告。** 综合者使用固定证据与已完成问答，按用户需要组织答案。先确认宿主选定 provider；若为 `sesame/reports`，直接 `components_show({target:"report",content:{kind:"document",sections:[...]},data,...})`。不清楚组件时才查 `components_list/components_describe`。文字用 Markdown 或 paragraph，图表按数据特性选择；不先套业务模板，不生成 HTML，不自动添加附录或解释性小字。发布后以 `report_check` 核验精确修订；失败保留原引用重试，不能重跑已经完成的研究。

默认四阶段顺序执行；自定义 `workflow` 可按任务组织阶段内并行和成员。这里只执行既有 Run 机制，不建立新的调度层。scope 读取方法和已有材料；取证及分析获得调用方选定的研究安全能力；综合者不会直接采集新来源。自定义成员仍受显式能力与研究/交易边界约束。

## 可选任务 brief

`report_brief` 的字段全部可选，不重复要求用户填写已经明确的内容：

| 字段 | 用途 |
| --- | --- |
| `objective` | 用户需要解决的问题或作出的判断 |
| `questions` | 本轮实际需要回答的子问题 |
| `method_ids` | `research_methods` 返回的方法参考 ID，不是报告模板编号 |
| `evidence_requirements` | 用户证据要求与有影响的缺口 |
| `delivery` | 需要交付什么，以及用户明确删改的内容 |

报告内容大纲由问题决定，单项比较、事实日历、机制解释或预测不会使用同一必填结构。Research 的方法预设与 Reports 的视觉组件各自发现、各司其职；用户需求优先，不补回删去的内容。

## 新研究、刷新与改报告

- 新研究：调用 start，传问题、对象、来源/计算能力、模型与可用 `evidence_refs`。start 自动带上 Research 的两项只读方法工具；它不因此扩大来源、配置或交易权限。
- 更新资料或结论：新建 start，传本次截止时间与原成果引用，只补变化和关键缺口，保留新旧结果。
- 只改文字或视觉：`investment_research_report({result_ref,model})` 只运行原计划的综合者，沿用证据时点，不取数、不重新研究。
- 从特定成员重做：analyze 的 `start_from` 继承已冻结上游，执行明确的剩余计划，不修改历史成果。

`investment_research_analyze` 用于显式成员研究和内部固定数据交接；默认八成员不决定报告格式。`investment_research_event_outcomes` 只对齐已固定事件与行情结果，不搜索相似事件、不选择特征、不提供概率。

报告绑定路径不是文件本身，内部成果和聊天不能代替报告。只由 synthesis 发布唯一报告；单文件直接交付，不额外套目录。新研究用研究主题命名。发布失败保留研究，报告成功但视觉检查失败保留精确引用。其他 provider 使用其真实 inputSchema 和 `host_reports_publish`，不改宿主设置。

## 与策略研究的边界

本工作流回答市场和投资研究问题。独立因子评价由 sesame/auto-factor-mining 执行。交易规则、参数搜索、加入因子后的边际贡献及样本外确认由 sesame/strategy-development 检验。两类固定结果均可作为研究报告的证据。Research 与专业知识负责调查充分性，Reports 负责格式、组件、数据绑定、统一视觉与实际渲染。交易授权、目标仓位和订单由相应交易流程处理。
