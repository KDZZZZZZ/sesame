# Research：从用户问题到报告

主入口是 `investment_research_start`，交付到 `task.output:{type:"report",space:"research",path:"...html"}`。直接工具 schema 支持时用业务参数同级的 `_task.output`；通用 `host_capabilities_invoke` 用调用选项 `task.output`，均传对象，不能通过 resume 改绑。报告只规定建议结果形式；方法、知识和来源由问题及用户要求选择。用户可以调整字段、顺序、视觉和实际工作成员。简单问答仍可直接回答，不为套流程另开报告。

## 实际步骤

1. **先形成判断任务单，再选择结果形式。** 沿用用户问题、已有 `report_brief` 与需求交接，精简列出用户要做的决策/要Agent回答的问题、对象与期限、比较对象、用户指定角度与Agent补充角度（分开标明）、何种证据会改变判断。角度是问题，不是待收集的指标清单；不预设结论。信息足够就说明合理假设推进，不重复询问；只有会改变目标且无法合理推断的关键歧义才澄清。再用 `report_structure` 查看建议字段与视觉，选择能承接这些判断的单模块、组合或自定义结构；用户裁剪优先，不新增强制API字段。本阶段只读知识与字段，不联网或做市场判断。
2. **围绕判断取得消息和数据。** 按任务单说明每项证据能支持、区分或推翻哪项判断，先复用固定证据，再补会改变答案的缺口；不按来源数量搜齐所有指标。已知官方入口直接获取，未知入口用搜索发现，随后取原文并解析。优先无需配置的来源，再考虑免费配置；保留原文引用、发布时间、获取时间、历史可用时点与实际覆盖。拒绝访问不等于没有事件。
   取证不只收最新快照：问题涉及预测、规律或条件性建议时，同时取得所需历史和随后结果，保留可计算、可画图的完整引用。优先同品种近期，再扩展同品种历史，没有合适样本再考虑可比品种；取不到不能记为零匹配。
3. **逐项回答并对照知识与适用历史。** 对用户需要的问题给出明确判断，已有清晰结论保持，只补必要缺项；共同对象和期限可沿用，依据、关键反证和改判条件按其实际影响说明，不逐项填满一套栏目。组合已选知识和计算能力，说明适用理论、机制或恒等关系如何连接证据与答案；不要求完整因果证明或所有检验通过。技术特征、指标、阈值与方法由问题和用户选择。对预测、规律和条件性建议，即使不给概率，也要实际检索或复用同类历史与后来结果；自由选择方法不等于跳过历史论证。对照同品种近期及可比历史的实际后果，保留匹配规则、基准、结果窗口、重叠和当时可知性；不适用、未检索与不可取得分别说明，确定性比较和用户偏好不硬造历史概率。策略说明条件适用、失效、反例及监测，不把有限证据包装成普遍有效。近期涨跌、指标和理论名称不能替代同类情景对照。分析阶段不直接取网，仍能取得的重要历史缺口应向原取证成员定向补问，确实无法取得时说明具体尝试与限制。把逐次结果、分布和基准数据随固定引用交给报告成员，不只交文字总结。
4. **生成与核验报告。** 新研究先检查重要推断的历史对照，仍可补齐的缺口交回原成员；不把未检索当作验证完成。用内置图表呈现价格、比较和历史结果等定量依据，按数据关系选图，不规定图数。主要图、实际样本数、后来结果与必要反例留在对应判断旁，完整记录放末尾。只改版时沿用原研究，不重新取数。报告阶段先调用 `host_reports_describe`，按宿主所选插件返回的 `inputSchema` 组织结果，再用 `host_reports_publish` 发布；宿主通用 envelope 使用 `operationId`、`title`、`summary`、`data`、`provenanceKind`、`references`，插件输入放 `input`，大型完整输入可先登记为固定 JSON 后使用 `inputRef:{ref,entry}`。`input` 与 `inputRef` 二选一，不把默认 Reports 的 content/style 当宿主通用格式，不自行改选 provider。仅当当前 provider 是 `sesame/reports` 且 schema 适用时，使用它的 `content` 与 `style`、字段/图表助手和通用样式；助手只预览。正文保留判断、读图注解、简短推理和关键条件，原始明细在末尾附录，公式交由所选插件的组件呈现。不能上传 HTML/CSS/脚本或以不匹配接口绕过当前选择。发布后核验精确 ref；检查失败保留该 ref 重试检查，不重新研究或重选结果。

报告开头直接给总体结论，下面让原有分析和图表围绕各项必要判断展开；小标题表达结论，用短理由连接证据，重要数字和条件就近保留，完整证据在末尾。保留已有清晰结论与风格，不在摘要、卡片和图注中反复讲同一件事；不同对象、角度和期限的真实分歧仍须说清。用户可以删改角度、字段和章节；只要求事实或日历时不强行加入预测。

默认四阶段各一个成员，由原生 Run 顺序执行并保存交接。实际权限随阶段变化；用户给 `workflow` 时采用其自定义成员和顺序，不强制四阶段或八角色。没有独立scope成员时，首个承担研究的成员沿用现有交接形成简短任务单，后续复用，不各自另造任务。模板字段缺失时先判断是否影响问题，不强制搜齐所有建议项。

## 不同报告情况

`report_brief` 仅描述需要的结果。`case` 可用下表建议，`template_id` 可选任意当前 M/R 模板；显式 `sections` 替换建议组合，`adjustments` 记录用户修改。不能在这里固定分析算法。

| case | 建议形式 | 研究重点 |
| --- | --- | --- |
| auto | 按需求读当前目录选择 | 不明确但可合理推断时采用适当建议，并说明范围 |
| overview | R01 资产概览 | 当前状态与主要变化，不强迫预测 |
| outlook | R02 综合行情 | 不同特征、历史参照与最终情景 |
| event | R03 事件冲击 | 事件时序、预期差、实际反应与可比历史 |
| company | R04 公司研究 | 财务、估值假设与共识口径 |
| briefing | R05 简报 | 有范围的消息、日历和机会线索 |
| options | R06 期权/波动 | 期限、行权价、波动与结构；缺期权数据不以现货替代 |
| portfolio | R07 组合诊断 | 暴露与风险，不因此产生交易授权 |
| forecast_review | R08 预测复盘 | 原预测时点与后来结果，不能事后补写旧预测 |
| calendar | R09 事件日历 | 日期、事件和已知预期，通常无需方向概率 |
| custom | 用户自定义 | 拼接所需字段与相近视觉，方法自由组合 |

仅技术面等单项报告可以直接传 `template_id:"M02"`，无需增加不相关宏观、财报章节。自定义任务可使用 `sections:[{id,module_id?,title?,fields?}]`，语义与当前 `report_structure` 保持一致。表中映射是本版建议，字段详情由已装 Report 决定。

## 新研究、刷新与改报告

- 新研究：调用 start，传问题、对象、所选来源/方法、模型和可用 evidence_refs。
- 更新资料或结论：新建 start，传本次问题、截止时间及原 result_ref 作为已有证据；只补新缺口，保留旧成果及新旧变化。
- 只改结构、文字或视觉：调用 `investment_research_report({result_ref,model})`；只运行综合者，不取新数据。已有 packet 的 report_brief 会保留，具体修改放本次任务说明。
- 特定成员之后重做：原 analyze 的 start_from 是高级兼容入口，继承已冻结上游；不修改历史结果或自动换方法。

`investment_research_analyze` 保留显式角色计划、历史八成员调用与内部数据交接。新报告优先 start。`investment_research_event_outcomes` 是独立的固定事件/行情结果对齐计算，不是搜索器、特征匹配器或置信度模型。

## 与 Strategy 的分工

Research 回答市场和投资研究问题；Strategy 研究信号、交易规则、参数和真实回测。已有策略回测可作为 Research 的一份证据，Research 不把它改写为新的策略试验。两者共享来源、分析方法、固定数据和 Report 视觉；Report 不承担研究编排，也不自行重新取数。
