# 投资研究

研究问题使用 `investment_research_analyze`，交易决策消费研究成果，账户执行消费明确目标；三者各自负责自己的产物。研究入口没有账户、执行绑定或交易授权参数。选择已注册的信息来源和分析方法，按问题组合，沿用用户明确的来源要求。

输入 `title/question/subjects/research:{plugins,tools?}/model`，可选 `as_of/horizon/evidence_refs/agent_models`。模型来自宿主模型目录；已有固定证据用完整 DataRef 传入。没有账户也可以分析公司、行业和市场。调用使用宿主 operationId 去重；按宿主 Run 读取、等待、中断、恢复和取消，不创建平级的重复分析师任务。

所有研究员、多空、风险和经理共用分析与行文标准：从当前事实形成范围明确的主判断，以可检验机制连接证据和结论，按问题选用可靠理论与可比的横向、历史材料，检验最强替代解释，说明期限内的主导因素、证据边界与改判依据。方向与信心分开，缺少精确点位或概率不自动阻止定性倾向；确实无法判断也要说明比较过的解释、不能区分的原因与具体未知，不能用作默认的保守答案。开篇给出总观点，各小标题先说结论，正文围绕总观点解释证据为什么支持、限定或挑战它，图表服务论证；不规定工具顺序、具体案例、固定章节或讨论次数。定向核查和仅重做报告的经理也沿用这些标准。

默认保留完整成员 Markdown、经理总结和固定 `result_ref`，不创建报告文件。用户需要报告时在宿主调用选项中提供 `task.output:{type:"report",space:"research",path:"...html"}`。只有经理获得报告编辑与渲染能力，报告遵循 `sesame/reports` 视觉规则，只呈现经理综合。

多头、空头、风险和经理可以按证据缺口调用团队内 `investment_research_ask({analyst,question})`，让对应原研究员核查；该能力授予研究工作流中的所有后续角色（多头、空头、风险、经理），主 Agent 不需逐项转发或重复派员。答案可能改变判断且仍有可核查的缺口时可以继续追问，不固定讨论轮数，不为凑轮数或共识重复观点。把缺口作为主判断或置信度的主要限制时，应有实际核查记录或明确的能力/覆盖限制。原研究员仍有适用能力且尚未核查的关键缺口应定向补问，不能把继承的未知视为不可取得；已有失败且无新路径则不重复请求，非关键缺口不为完整而补齐。宿主自动沿用本轮模型、来源选择和既有成果，回答仍归属原研究员。完整问答和新增证据保留在 `result_ref` 的 qa 中并交给后续风险审查与经理；报告只呈现经理综合及必要依据。

用户只要求改报告时，使用 `investment_research_report({result_ref,model})` 和同样的报告 output 选项。该入口只启动一个经理，读取原固定成果与证据；无需原研究插件或交易账户，不重跑分析师、不重新取数，不把旧资料包装成新研究。

依赖缺失暂停原 Run 并保留成果。主 Agent 解决可自行处理的事项后恢复同一 Run；缺少用户尚未提供的资料或明确决定时才与用户沟通。源码中的分析算法、具体来源配置和模板说明分别属于被选方法、信源和 reports 插件，不由本工作流重复规定。

## 从指定进度重跑

已有完整 `result_ref` 时，使用同一 analyze 入口传入 `{start_from:{result_ref,role},research,model}`。role 是第一个重跑的角色：bull、bear、risk 或 manager；从多空完成后继续使用 risk。原标题、问题、对象、证据截止时点、期限及输入证据自动继承，不必重复填写。新工作的来源与模型由 research/model 明确选择。

早于起点的成员全文、Run 引用及其问答原样保留，起点及以后的旧结论和问答不交回上游。执行剩余角色时仍可按需向原研究员 QA，新增证据进入后续角色和新结果。新原生工作流与报告保留 `start_from` 来源记录，不改写已完成的原工作流、固定成果和旧报告；它的暂停/恢复仍使用普通宿主 Run 接口。只改排版行文而不补研究时，继续使用 report 入口。
