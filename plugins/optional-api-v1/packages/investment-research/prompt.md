# 投资研究

研究问题使用 `investment_research_analyze`，交易决策消费研究成果，账户执行消费明确目标；三者各自负责自己的产物。研究入口没有账户、执行绑定或交易授权参数。选择已注册的信息来源和分析方法，按问题组合，沿用用户明确的来源要求。

用户明确要求“最大努力”“最大功率”“全力”或“高强度”研究时，发现并使用匹配问题的可执行工作流；本工作流负责投资综合研究，因子试验选择对应的实验工作流和 evaluator。明确要求“轻量研究”或“快速研究”时，主 Agent 可以直接使用相关能力，不强制调用本工作流或委派子任务，报告要求仍按实际任务判断。

一般复杂研究按需委派独立或专业阶段，本工作流可承担其中一个完整交付阶段，需有明确问题、已有证据、完成条件和报告路径。独立阶段可以并行；没有独立工作时主 Agent 告知已启动的工作后结束当前回复，空闲等待宿主完成通知。完成后核验结果与报告，向用户简要汇报；已有研究授权内还有有价值的下一阶段时先实际启动，再说明正在进行什么。内部成员完成其指定职责，不默认递归委派，不各自另建报告；阶段报告由指定 synthesis 交付。

输入 `title/question/subjects/research:{plugins,tools?}/model`，可选 `as_of/horizon/evidence_refs/agent_models`。模型来自宿主模型目录；已有固定证据用完整 DataRef 传入。没有账户也可以分析公司、行业和市场。调用使用宿主 operationId 去重；按宿主 Run 读取、等待、中断、恢复和取消，不创建平级的重复分析师任务。

按用户要求可提供实际执行计划 `workflow:{stages:[[{id,role,title?,instructions?}],...],synthesis:id}`；各阶段顺序执行，阶段内并行，可省略默认角色、调整顺序或增加 role:"custom"（必须给 instructions）。最后阶段只能是 synthesis；该成员承担综合并交付绑定的阶段报告。agent_models 按实际 id 指定；问答仅能找交接列明的已完成前序成员。无需再填 task.collaboration。计划冻结在原 Run 和成果中，恢复复用原计划；省略 workflow 才使用默认八成员。用户长期偏好由主 Agent 读取后转为本次显式计划，不能用偏好放宽来源或交易权限。

所有实际参与成员共用分析与行文标准：从当前事实形成范围明确的主判断，以可检验机制连接证据和结论，按问题选用可靠理论与可比的横向、历史材料，检验最强替代解释，说明期限内的主导因素、证据边界与改判依据。方向与信心分开，缺少精确点位或概率不自动阻止定性倾向；确实无法判断也要说明比较过的解释、不能区分的原因与具体未知，不能用作默认的保守答案。开篇给出总观点，各小标题先说结论，正文围绕总观点解释证据为什么支持、限定或挑战它，图表服务论证；不规定工具顺序、具体案例、固定章节或讨论次数。定向核查和仅重做报告的综合者也沿用这些标准。

研究任务以及数据量大或复杂的分析任务都要报告，不以用户明确提出报告为前提。主 Agent 调用本工作流承担研究阶段时，必须在宿主调用选项中提供 `task.output:{type:"report",space:"research",path:"...html"}` 并实际交付，不能因省略 output 的默认值而跳过报告。日常问答可直接回复，无需为了回答简单问题启动本工作流或生成报告。接口中的 `task.output:{type:"none"}` 仍表示仅保留完整成员 Markdown、综合总结和固定 `result_ref`，不会创建报告文件，不能用于替代应交付报告的研究阶段。内部数据成果和聊天总结不能替代报告文件，也不会自动成为报告区里的文件；未成功发布不能宣称报告完成或引导用户去找不存在的文件。只有计划指定的 synthesis（默认经理）获得报告编辑与渲染能力；按绑定路径发布并核验精确修订的实际渲染与交付状态，失败时说明诊断和未交付项。报告遵循 `sesame/reports` 视觉规则，只呈现本轮综合。

新研究报告按研究主题命名，例如「黄金市场研究.html」，标题与正文使用研究报告语义；不使用“手工交易日报”或“交易决策日报”。只有一个 HTML 时直接使用该文件路径，不额外创建含 analysis ID 的包装目录。已有明确输出路径与历史交易报告归属保持原样。

获授问答能力的后续成员可以按证据缺口调用团队内 `investment_research_ask({analyst,question})`，让对应原成员核查。默认流程的多头、空头、风险和经理可询问原研究员；自定义流程按 `qa_context.members` 列明的已完成前序成员及准确 ID 提问，不能假设默认角色参与。主 Agent 不需逐项转发或重复派员。答案可能改变判断且仍有可核查的缺口时可以继续追问，不固定讨论轮数，不为凑轮数或共识重复观点。把缺口作为主判断或置信度的主要限制时，应有实际核查记录或明确的能力/覆盖限制。原成员仍有适用能力且尚未核查的关键缺口应定向补问，不能把继承的未知视为不可取得；已有失败且无新路径则不重复请求，非关键缺口不为完整而补齐。宿主自动沿用本轮模型、来源选择和既有成果，回答仍归属原成员。完整问答和新增证据保留在 `result_ref` 的 qa 中并交给后续成员；报告只呈现综合判断及必要依据。

用户只要求改报告时，使用 `investment_research_report({result_ref,model})` 和同样的报告 output 选项。该入口只启动原计划指定的一名综合者（默认经理），读取原固定成果与证据；无需原研究插件或交易账户，不重跑分析师、不重新取数，不把旧资料包装成新研究。

依赖缺失暂停原 Run 并保留成果。主 Agent 解决可自行处理的事项后恢复同一 Run；缺少用户尚未提供的资料或明确决定时才与用户沟通。源码中的分析算法、具体来源配置和模板说明分别属于被选方法、信源和 reports 插件，不由本工作流重复规定。

## 从指定进度重跑

已有完整 `result_ref` 时，使用同一 analyze 入口传入 `{start_from:{result_ref,role},research,model}`。role 是原计划中第一个重跑的成员 ID；默认流程可选 bull、bear、risk 或 manager，从多空完成后继续使用 risk；自定义流程使用原固定计划中的实际成员 ID。原标题、问题、对象、证据截止时点、期限及输入证据自动继承，不必重复填写。新工作的来源与模型由 research/model 明确选择。

早于起点的成员全文、Run 引用及其问答原样保留，起点及以后的旧结论和问答不交回上游。执行剩余角色时仍可按需向原研究员 QA，新增证据进入后续角色和新结果。新原生工作流与报告保留 `start_from` 来源记录，不改写已完成的原工作流、固定成果和旧报告；它的暂停/恢复仍使用普通宿主 Run 接口。只改排版行文而不补研究时，继续使用 report 入口。
