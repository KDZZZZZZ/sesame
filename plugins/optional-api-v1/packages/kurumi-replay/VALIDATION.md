周报请求归档与模型提交分开持久记录：提交前归档失败/取消可沿原冻结请求重试，
只有已进入提交阶段的未知结果才要求对原请求核实，不自动重发。
服务留档修正：角色目录封存成功不再清空之前失败的 journal/file 待补队列，
只有显式逐项补写成功后才解除留档暂停；失败封存后重试也保留原待补证据。
补写调用串行共享，逐项持久化进度；恢复期间新增的失败具有独立身份，不能被旧
恢复清除。主日志已 fsync、仅镜像失败时只补镜像，不重复追加原逻辑记录。
这包括真实临时双日志的镜像故障/重启回归，不等于所有磁盘崩溃窗口的证明。
首次日志追加的目录同步也纳入回滚区间，失败后撤回该行再进入待补队列。
这些修正仅在仓库验证，**没有安装到当前 Sesame，也不代表真实周报验收通过**。

## 发布前剩余验收项

- **周报留档暂停守卫（P1，尚未修复）**：周报 drain 的提交入口尚未统一调用
  `assertArchiveHealthy`；重新写入本次 `request.json` 成功，不保证更早的待补
  证据已修复，可能在留档暂停期间继续提交付费周报请求。恢复实际周报生成或
  发布前须接入该守卫并验证。见 [PR 50 审阅讨论](https://github.com/KDZZZZZZ/sesame/pull/50#discussion_r4250562322)。
  用户明确要求停止继续审阅、直接合入未发布源码，因此本项记录为待办，
  **没有修复或通过验收，不把关闭审阅讨论视为代码问题已解决**。
- **形成中 K 线与指标**：需要真实已消费 tick 的形成中帧在原生前端显示，
  并与账户/标注的 as-of 对齐；闭合 H1 和模块 fixture 不替代此项。
- **真实投资周报**：至少一份按模拟 UTC 周冻结输入、保留完整 Agent 原文、
  可在原生报告页打开的周报。当前尚无真实周报 job；开发交接报告、导出文件和
  `sesame-report-inspector` 回执不算。需精确 report/input/period 与
  `sesame-report` 原生页回执绑定；不额外要求插件自动打开报告。
- **完整新玩家流程**：原包公开 prepare → 暂停的新 50x 状态 → 带状态 reload →
  完整玩家工具工厂和可操作依赖诊断仍待验。隔离 owner 尚未 prepared 或创建 run；
  未准备数据时拒绝 seed 只是负向守卫通过。
- **准备流程缺陷**：此正式快照 `data.js` 在 Electron 中使用 `process.execPath`
  启动 worker 曾得到 Helper exit 64；`runtime-adapter.js` 仍有旧原型 wheel-cache
  fallback。隔离候选已实现 native Node 解析、固定 wheel 校验/显式恢复并移除该
  fallback，但必须经完整流程验证后另行整合，不能宣称本快照已无作者环境依赖。
- **网络恢复**：隔离 owner 已保存并核对 400 个公开源对象，原生依赖已 ready；
  prepare 仍在同源重定向后遇到 HTTP 429，无完整 dataset。单独 host 探测成功
  不等于 SDK transport 恢复，不能把探测结果手工填入缓存冒充准备成功。
- **幂等与回归**：真实重复 ACK、带状态安装/reload 和完整组合测试仍待补齐。
  本地模块、真实 Nautilus 合成计算、SDK 回执与原生像素证据应分别报告。
- **历史覆盖**：全章预检仍有 327 个早期 SNB 事件缺少 60 秒内的直接 CHFJPY。
  不插值、不跳小时、不放宽换汇规则；有敞口时遇到缺口须暂停。

代表性效果与上述门槛通过后，应在已提交 4H 决定边界停止；预算只是上限，
不能为跑满 72H/18 次角色继续付费。第一轮封存和第二次短测状态不得被重置、充值或覆盖。
