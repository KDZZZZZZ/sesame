# 用一个能失败的改动检验诊断

可以从原策略中频繁出现的小额调仓提出一个预测。若新预测和风险预算均未改变，扩大调仓缓冲应首先降低双边成交额与佣金，代价是实际持仓更慢地追上目标。即使成本下降，趋势启动时错过收益也可能令组合净值下降。分别判断执行机制和投资目标。

从有原生开发证据的基线建 parameter_trial，记录改变的组件、原生参数、候选值和对指标方向的预测。选 turnover 时使用同一初始资本作分母。插件从基线继承行情、参数、资金、费率、代码和目标，重跑一次候选。compare 从两个原生回执核对 Python 版本、平台、位数、Backtrader 和已安装软件包版本。路径别名可指向等价环境。若包清单存在同名多版本等歧义，须有内容摘要完全相同的两个环境快照，核对结果会保留这些歧义。环境不同或证据缺失时，单项改动的效果仍待核实。

同时检查指标方向与委托目标。若候选参数组合已在本基线的完整开发网格中测过，记录会标明本次为旧网格复测。该复测可以量出差异。将相同结果用于提出假设后，应在新的数据上检验预测。基线网格以外是否曾试过该想法，仍需从其他项目记录核对。

| 观察到的结果 | 下一步研发判断 |
| --- | --- |
| 换手降低，净收益也提高 | 在新的时间段确认。检查收益是否集中于一段低波动行情，并检查实际风险偏离 |
| 换手降低，净收益下降 | 降成本的机制获得支持，但本次改动牺牲了机会。看延迟建仓的时点，考虑只给小额再平衡设带或回到原版本 |
| 换手几乎没变 | 检查是否触及缓冲，以及订单是否主要来自强制退出。若成交由风险降仓驱动，应重查原始诊断 |
| 逐笔经常有利后回吐 | 保持同一入场机会和仓位，预先选一种退出假设。历史有利极值用于诊断，确切止盈价需要独立试验 |

某些失败支持保留原版本或结束研究。若新增过滤在持仓风险和交易频率匹配后失去优势，先记录它改变了敞口，再决定这种变化本身是否符合委托。因子库中的原始预测证据仍保留。[Peterson 的分组件研究和交易路径诊断](https://www.braverock.com/brian/CapeR_2016_backtest.html)

随包测试用 160 根合成股票日线运行同一原生策略。缓冲宽度从 0 改为 10% 后，成交订单从 75 降到 54，佣金从 1,108.21 降到 660.57，开发净收益率从 5.70% 降到 5.33%。因此“它降低交易成本”得到本例支持。以该开发区间净收益为目标，原版仍领先。要进一步判断放弃了哪些机会，需要核对目标仓位与实际成交之间的延迟。这组结果可在插件端到端测试中复现，数据来源为合成情景。
