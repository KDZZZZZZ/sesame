# 从交易证据选择一次最小修订

先确定异常发生在哪一层，再选择可解释的局部改动。输入包括固定策略版本、参数、原生回测回执、订单、逐笔盈亏、费用及时间戳。未平仓头寸的浮动盈亏应与已平仓交易盈亏分别计算。

| 观察 | 先核对 | 可验证的下一步 |
| --- | --- | --- |
| 没有平仓交易 | 预热、符合条件的信号、过滤理由、拒单、未平仓头寸 | 用一条已知有效事件逐层跟踪到成交或明确阻断点 |
| 交易毛利为正、扣佣后为负 | 实际手续费、换手和小幅改仓频率 | 固定 Alpha 和风险规则，只比较降低换手或增加仓位缓冲 |
| 收益集中于少数交易或状态 | 逐笔贡献、持仓时间和各状态的样本数 | 在同一开发分区分层，报告收益贡献与剩余样本 |
| 回撤超过约束 | 峰谷期间的敞口、杠杆、集中度和跳空成交 | 只修改对应的仓位或风险组件，保留原委托阈值 |
| 持仓中一度有利，退出时利润经常收回 | 按方向计算交易路径中的 MAE/MFE，确认行情粒度和成交顺序 | 在开发数据上测试少量预先声明的退出规则 |
| 参数尖峰、成本敏感或留出恶化 | 相邻参数、成本压力、选择次数、前视与市场状态变化 | 冻结本次结论，修订后另留独立样本确认 |
| 模拟盘与回测行为不同 | 对齐同一窗口的输入时间、信号、拒单、部分成交和费用 | 修复首次发生分歧的适配层，再验证上层策略 |

仓位缓冲可以在目标变化很小时保留现有仓位，越界后再调到边界或目标位置。比较换手、成本后结果、资金风险和偏离目标的幅度。先确定问题来自小额频繁调仓，再测试缓冲宽度。[pysystemtrade 的缓冲设计](https://github.com/pst-group/pysystemtrade/blob/develop/docs/backtesting.md#buffering-and-position-inertia)

将观察与解释分别记录。MAE 和 MFE 描述持仓期间发生过什么，可帮助形成退出假设。用新的受控测试验证候选方案，并记录父版本、干预组件、保持不变的条件和验收指标。[Peterson 的交易诊断与策略开发方法](https://github.com/braverock/quantstrat/blob/master/sandbox/backtest_musings/strat_dev_process.Rmd)

在 strategy_development_read 读取有原生证据的版本，从逐笔路径查方向、真实成交价及完全处于持仓内的行情。多头的不利方向是跌，空头则是涨。进出场所在 K 线的最高最低点可能出现在持仓前后，适合按可观测下界报告。分批进出、无法核对订单身份或行情缺失的交易要单列，保留覆盖率。

同样一笔亏损，几乎从未出现有利移动时，应先用固定退出比较入场质量。若持仓曾大幅有利而退出频繁回吐，先固定入场，比较一种有经济解释的退出。再用成交账本区分毛亏、费用和剩余持仓，以免把账面浮盈和已闭合交易混算。实际变动的交易机会数、样本量和风险暴露决定可以把结论推广到哪里。
