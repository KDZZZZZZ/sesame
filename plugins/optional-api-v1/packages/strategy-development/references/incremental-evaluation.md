# 完整策略的增量与消融

新增因子、过滤器、退出或仓位规则时使用这组对照。保留委托书引用、开发数据、列映射、资金、成本、基准、客观指标、约束和原生运行回执。先选定比较参数并冻结口径。

| 组别 | 要运行的完整策略 | 能回答的问题 |
| --- | --- | --- |
| A 基线 | 上一版完整策略 | 已有方法在该区间取得什么结果 |
| B 改动 | 只修改目标组件 | 同口径下净收益、回撤、成交和资金变化多少 |
| C 匹配对照 | 按事先声明的交易次数、持仓时间或风险敞口匹配 | 减少交易或敞口能解释多少差异 |
| D 消融 | 从候选中关闭所研究的组件，保留其余规则 | 贡献是否依赖该组件及与其他模块的交互 |

分别列出 B−A、B−C、B−D。标记每个实际更改的组件及依赖。多处同时改变时只能归于这一组改动。只比交易数无法证明敞口相同。若各方案重新寻优，单独列出整个系统重新选择后的结果、各自搜索范围、试验数和预算。保留先前的固定参数对照。[Peterson 的逐组件研究](https://github.com/braverock/quantstrat/blob/master/sandbox/backtest_musings/strat_dev_process.Rmd)

过滤器尤其需要追踪基线中被过滤的亏损交易和错过的盈利交易。用同一品种、同一可观察机会 ID 的决策记录核对过滤原因，再跟踪对应成交的成本后盈亏。Backtrader 单数据源的成交账本还能比较两版各自在某个 UTC 入场时点出现的已平仓交易。入场推迟、未平仓、仓位变化也会造成差异。缺机会记录时报告这些观测和归因缺口。

在开发区间筛选和迭代，冻结候选后再用留出数据确认。确定性时间外窗口、成本压力和参数邻域是不同的问题，各自保留实验记录。若选择滚动更新，在第一次评估前写下再估计频率和各窗口边界。[QuantConnect 的参数与样本外评价](https://www.quantconnect.com/docs/v2/writing-algorithms/optimization/parameters)

**一个过滤器怎样造成表面改善。** 以下是教学算例，盈亏和成本沿用同一资金单位。A 有 100 笔机会，毛利 30、费用 50，净亏 20。B 只交易其中 60 笔，毛利 24、费用 30，净亏 6。净结果改善 14，费用节省 20，毛利减少 6。这组数字足以说明少付了费用。若要证明选中了更好的机会，先用开仓前就能确定的时段、方向和风险划分基线机会，再按 B 的机会数重复构造匹配组 C。若 B 落在 C 的常见表现范围，降低换手本身就能解释改善。实际持仓有重叠、退出依赖状态或资金会被占用时，应重跑整个组合。简单删除事后亏损交易会高估机会选择能力。
