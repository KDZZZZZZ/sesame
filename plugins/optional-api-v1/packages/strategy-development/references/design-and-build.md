# 从委托书建立可检验的基线

新建策略时，先从会话、已有项目及数据说明里填出研究目标、可交易范围、硬约束和执行条件。用一句话写下假设，包括可观察的条件、预期发生的价格或交易行为、时间尺度，以及什么结果会使这项假设失去支持。明确用户条款的出处，把 Agent 选择的比较基准和模拟条件标为研究假设。

| 已有条件 | 适合的方法 | 首份产物 |
| --- | --- | --- |
| 有可解释的市场机制 | 明确信号发生时间、预期方向及一种替代解释 | 中心假设和反例 |
| 数据充足而机制尚不清楚 | 预先固定搜索空间、预算、目标和开发窗口 | 可重现的搜索协议 |
| 新策略缺少基线 | 先组合入场、退出、仓位、必要风险规则与执行逻辑 | 一份能产生完整交易行为的策略 |
| 已有约束、组件或既有策略 | 从硬约束反推可选组件，或只替换有证据表明存在问题的一项规则 | 模块职责和版本差异 |

组合型策略把判断传给持仓目标，由风险模块调整，再交给执行模块。入场、退出及挂单需要共同状态时，使用事件状态机记录已发单、已成交、部分成交、撤单和恢复。混合结构可以保留组合层和特殊订单状态机。用同一组固定事件检查改动影响哪些输入和输出。[LEAN 框架](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/overview) · [LEAN 混合结构](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/hybrid-algorithms)

需要组合多个预测时，先说明尺度、期限和方向，再规定组合如何转成风险预算下的数量。把每个预测、过滤条件和交易规则分别写成可测试的行为。使用同一基线回测观察新组件改变了哪些决策。[Peterson 的策略研发方法](https://github.com/braverock/quantstrat/blob/master/sandbox/backtest_musings/strat_dev_process.Rmd) · [pysystemtrade 的系统阶段](https://github.com/pst-group/pysystemtrade/blob/develop/docs/backtesting.md)

**选择信息应该改变的动作。** 一个指标可以产生截然不同的策略。趋势强度从弱到强且条件收益随之递增，适合把标准化强度连续映射到目标仓位。若只有一个能在决策时识别的状态下，突破后的条件收益才反转，优先比较一个开关式过滤。若预测方向稳定而波动上升，优先调整单位风险持仓。三者分别改变交易数量、风险预算和持有路径，用同一输入构建单项对照才能分辨。

**按机会寿命设计退出。** 一条短寿命的反转信号可先用固定持有期检验衰减。对依赖少数长趋势的策略，过紧的止盈可能截掉主要收益来源。比较同一组入场的退出时刻、交易净盈亏和持有期，再检查盈利是否集中于少数持仓。风险上限来自委托，预测退出来自信号寿命，两者有各自的触发依据。

**从预测落到可成交头寸。** 快慢均线差以价格单位计，可先按价格变动的波动尺度换成无量纲强度，限定极值，再用单日风险预算计算可持股数。波动估计只能看已完成样本。多预测组合先在开发数据比较各自在现有预测之外的增量，合成后再施加风险和资金约束。挂单尚未成交时，新目标需要考虑在途数量，风险清仓要能打断普通再平衡。模板的逐步公式、订单处理和可修改参数见[趋势仓位与缓冲示例](forecast-buffer.md)。
