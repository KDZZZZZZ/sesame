# 判断一个参数或改法能否换个条件继续工作

**孤立尖峰。** 如果某个趋势周期略改一档就从盈利变亏损，检查换手、交易数和对少数行情的依赖。先看尖峰是否有与信号寿命相符的机制，再考虑缩小自由度。对执行延迟、周期和风险规模有不同经济意义的轴，预先定义哪些距离算“邻近”。整数编码的交易方式属于类别。

**稳定区域。** 对有数值顺序的参数，可在搜索前指定 neighborhood_worst。每个中心与各轴左右相邻一档共同满足约束，类别保持一致，比较各中心邻域最差的目标值。它回答“小幅设定误差时哪组表现较稳”。轴的边界、缺少两侧、相邻跨度超过预设距离或邻点违反约束，均不足以支持该中心。仍保留单点最优和各自实际得分。多轴同时跳变、跨期变化和交易成本压力需要各自的证据。[QuantConnect 参数研究](https://www.quantconnect.com/docs/v2/writing-algorithms/optimization/parameters)

**成本敏感。** 冻结成交规则和参数，以基准费率为锚，分别增加佣金、点差或滑点。排查盈亏变化来自相同订单的成本上升，还是费用耗掉现金后导致拒单、仓位改变。后者必须用真实引擎重跑。把压力情景的结果留给已有候选，无须在每个情景重新调参。

**市场变化。** 要回答“每月重估是否比固定参数好”，事先规定训练窗、重估频率、固定参数对照、下一段的交易规则。每个窗只能用当时可得的资料，按时间连接真实发生的测试结果，考虑跨窗持仓和换仓费用。单次冻结留出只回答本次选中版本在后一段的结果。标签覆盖未来若干日时，训练末端还要剔除穿过测试起点的标签。[QuantConnect 滚动优化](https://www.quantconnect.com/docs/v2/writing-algorithms/optimization/walk-forward-optimization) · [skfolio 的时间分割和隔离](https://skfolio.org/generated/skfolio.model_selection.CombinatorialPurgedCV.html)

搜索预算大时，把失败候选、试过的规则家族和多轮修订一起计入搜索历史。检查赢家是否依赖单一窗口或少量成交。邻域和一次留出都不能估计整个搜索过程的假阳性率。报告中只给已实际执行的检验结论。
