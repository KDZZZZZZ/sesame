# Preparation validation — 2026-10-09 / 1.0.1

The previous installer downloaded PySide6_Addons 6.8.2.1 (302,704,501 bytes) in one pip command, disabled caching and deleted its private venv on failure. At slow official PyPI transfer rates a host's 600-second tool deadline repeatedly lost that download. This version retains an explicitly owned private environment, stage, wheel partials, metadata/digest receipts and pip cache. It does not overwrite an unknown existing environment or install globally.

A prepare request fetches at most 64 MiB / 420 seconds of the six pinned engine/Qt wheel archives. Official PyPI metadata chooses native platform tags; completed archives require full SHA256 verification. HTTP Range resumes retained bytes. Unsupported ranges, source changes and hash failures are explicit; no alternate index or simulated installation is used. Downloads and installation happen in separate requests when bytes were fetched, leaving headroom for the host deadline. Failed installs preserve private state and expose phase/error/progress rather than readiness. Three unchanged failures return retryable:false and instructions to stop automatic retries. The skill explains reuse first, bounded continuation, diagnosis and readiness.

Actual official-network evidence:
- Engine wheel partial grew from 4,096 to 8,192 bytes on two requests; subsequent engine and CTA wheel downloads completed and verified their pinned SHA256.
- The actual 302,704,501-byte Addons universal2 wheel grew from 4,096 to 8,192 bytes across two Range requests. Only this bounded prefix was downloaded; no claim is made that this test downloaded/installed the full Qt dependency again.
- Actual native private venv creation plus two prepare requests (controlled 400,000-byte test budget) each returned ready:false/downloading with 400,000 new bytes and persisted prior progress. The following explicit existing Python selection imported the real engine and returned ready:true/reused:true/origin:existing. Controlled test data/venv were removed afterward; evidence JSON was retained outside the package.
- The reused Python 3.13.12 / vn.py 4.5.0 / CTA 1.4.1 environment already completed a real A-share-data BacktestingEngine acceptance. Reuse does not invent download hashes for an external existing environment.

Seven JavaScript contract tests and eight Python downloader tests passed, covering private venv/cache retention over repeated install failures, retry guidance, strict engine readiness, resume offsets, refusal of an ignored or inconsistent Range, full response-body boundaries, short-EOF failures, and corrupt completed-cache rejection. Completion requires all wheel files to be hash-verified in the current request; an expired budget cannot treat an unchecked cached file as ready. A failed read after writing partial bytes still reports the actual retained byte growth. Three genuinely unchanged failures stop automatic retry advice; progress is not misreported as a stalled attempt. This change did not repeat a complete fresh 300+MB dependency install.
