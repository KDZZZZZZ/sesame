读者需要先知道三件事：结论是什么、证据有多强、哪些不能下结论。报告文字不是分析过程的记录，而是把已登记数据压缩成可核对的判断。每一句都必须落在 report-design 的 outline 某个字段里；放不进字段的内容属于 method，或者不需要写。

## 每个字段写什么

- `verdict.headline`：对象 + 结果 + 程度或比较 + 口径，一句话只有一个判断。
  - 好：「验证期亏损 9.49 USD（−0.09%），未证明突破回踩有效。」
  - 差：「本研究在严格冻结的流程下经过训练、选择与独立验证后，结果显示策略表现……」
- `verdict.detail`：最影响这个结论可信度的一个原因（样本量、口径或数据缺口）。
- `section.title`：名词短语，说明这一节回答什么（训练与验证、亏损构成）。
- `section.takeaway`：读这一节图表应得出的结论，句中出现图上能看到的比较。不写「下图展示了……」。
- `finding.claim`：一个可以被数据否定的判断。`evidence` 用结构化数值 `[{label, value, format, unit}]`，不要把一串数字揉进长句。`caveat` 写这个判断最大的限制，一句。
- `metric.label`：≤ 8 字的名词（净利润、最大回撤、有效样本）；`hint` 只写口径（原生统计、共 14 条）。
- `method.steps` 写怎样得到结果（选择规则、冻结、清洗）；`method.limits` 每条一个限制；`method.sources` 放 ID、哈希、版本与文件名。

## 数字

- 每个数字都来自 `reportKit.rows` / `reportData.query` 的结果，用 `reportKit.format` 或字段的 `format` 格式化；不手写、不先四舍五入再计算。
- 带单位和比较对象：「比 B 组高 2.17」，而不是「较高」；区分收益率与百分点差。
- 同一指标全文同名、同精度、同单位，以第一次出现的名称为准（净利润 ≠ 盈亏 ≠ 收益）。
- 样本小（如交易数 < 30、每组观测 < 30）时，verdict.detail 或 caveat 必须说明；不突出胜率、Sharpe、利润因子等需要样本量的指标。

## 语言

- 先结论后依据；一句一事；主动语态；用具体动词（亏损、高于、过期、排除）。
- 正文不出现代码标识符、函数名、字段名、文件路径、哈希、ID 或 JSON；需要追溯时放进 `method.sources`。用读者的名称：「Lookback 16」而不是「InpLookback=16」。
- 限制只在 `verdict.detail`、`caveat`、`method.limits` 中各出现一次，不堆叠免责声明或否定句。
- 不写过程叙事（首先、然后、经过核验）、工具调用与修复经历，也不写「本页」「下方」这类指引；原生回测组件所在的那一节除外。
- 不确定时说明不确定的范围：「每段仅 1 笔交易，无法比较参数」，而不是「可能存在一定局限」。
- 语言跟随任务：中文任务写中文，界面需要双语时用 `reportI18n.t({'zh-CN', en})`。

## 结构模板

Research：

1. verdict：核心问题的答案。
2. metrics：样本量，加 2–4 个直接回答问题的数字。
3. sections（3–4）：主要发现（趋势或对比图）→ 分组或驱动因素（bar / heatmap）→ 数据质量（排除原因 hbar + 被排除记录表）。
4. method：清洗规则、统计口径、限制、来源。

Strategy：

1. verdict：验证期（或样本外）结果，以及是否支持策略假设。
2. metrics：验证净利润、收益率、最大回撤、交易数、选中参数。
3. sections（3–5）：训练与验证（hbar，signed）→ 参数敏感性（heatmap 或 bar）→ 信号或规则漏斗（bar）→ 损益构成（hbar，signed）→ 逐笔证据 `{type:'backtest'}`。
4. method：选择规则、冻结方式、建模方式、限制、构建与任务 ID。

## 发布前自检

- 只读 verdict 和各节 takeaway，能否复述完整论证？
- 每个 takeaway 是否都有图支撑？每个数字能否在 rows 中找到？
- 首屏是否没有代码、ID 和过程叙述？每条限制是否只出现一次？
