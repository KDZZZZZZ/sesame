### 重要发现：数值方法组合存在真实接口缺口，并已出现手算错误

**接口组合尚未通过。** market 使用 price-action 的结构解释和手工算式，没有调用任何 ABU 数值能力。五个可用 ABU 方法都要求每根 OHLCV 的 `time`、`available_at` 为精确 UTC 瞬时；本轮 FMP 的原始日线只有 `date`，历史 `available_at=null`。这不是仅在提示词中写得严格：生产纯函数也实际拒绝这些输入。

```text
bars[0].time: canonical UTC timestamp required
```

例如 [abu-volatility runtime](E:/brief2great/sesame/sesame/plugins/optional-api-v1/packages/abu-volatility/scripts/runtime.mjs:19) 的 `instant` 强制毫秒 UTC 格式；`visible`（第 58 行）强制时间及可用时间，`bars`（第 62 行）逐行调用它。其他四包使用同样校验，注册 Schema 也要求两个 string 字段。market 不补造时刻是正确行为，但不代表信息层和数值方法层已能组合。

**已经发现具体计算错误，不能用“手算也正确”替代接口验收。** market 报告 10/14 的 TR 为 5.37，实际上这只是当日高低差。真实输入为：当日高 347.09、低 341.72，前一日收盘 341.27。

```text

          = max(5.37, 5.82, 0.45) = 5.82
五日简单 ATR = (5.99 + 7.41 + 5.82 + 6.25 + 7.36) / 5 = 6.566
ATR / 343.46 = 1.9117%，约 1.91%
```
