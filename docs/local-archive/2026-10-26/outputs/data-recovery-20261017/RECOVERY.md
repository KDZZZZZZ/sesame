# Sesame 0.2.4 本机数据恢复记录

已恢复并重新打开本机 Sesame 0.2.4。原数据没有被删除。

## 原因

此前本机维护时从 Codex 的 Windows MSIX 环境启动 Sesame，实际数据文件写入了 Codex 的 `LocalCache/Roaming/Sesame/workspace`。更新安装器重新启动应用时，使用普通 `AppData/Roaming/Sesame/workspace`，因此显示为新工作区。

取证同时发现：隔离环境按文件重定向，普通目录路径可能组合显示旧数据库与另一个目录的新 WAL/SHM。已分别用文件真实路径及隔离环境外的进程确认两份数据库，排除了原库被清空的误判。

## 恢复与修复

- 完整备份旧工作区，并保留更新后生成的空工作区。
- 将旧工作区复制到正常启动使用的固定目录；同步迁移 729 条包含旧物理路径的元数据，聊天消息保持原样。
- 逐一校验 2,910 个非数据库文件；数据库使用 SQLite 备份接口复制并通过完整性检查。
- 将原隔离工作区归档，避免继续遮蔽正常目录。
- 修复宿主 Store：现存数据库必须是普通文件，以该文件的真实父目录定位数据库及其 WAL、SHM 和相关存储。该修复已应用本机安装目录，同时保留在源码中，尚未另行发布版本。
- 恢复和最终重启均通过隔离环境外的进程完成。
