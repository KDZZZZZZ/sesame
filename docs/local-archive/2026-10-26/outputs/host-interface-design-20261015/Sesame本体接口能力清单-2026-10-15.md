# Sesame 本体接口能力清单

核对日期：2026-10-15。依据当前本体工作区 `0.2.3-dev.8` 的公开入口和实际校验逻辑，包含开发版能力，不代表所有已发布安装包都具备这些方法。本清单描述插件与本体之间的外部契约，供设计接口使用方法、Agent 提示词和可调用能力规范；不规定插件内部如何实现业务。

**可以把 Agent 作为一种任务执行接口：输入任务说明、明确数据、可用工具和预算，输出任务状态、最终答案及交付引用。** 一次模型推理、完整 Agent 任务、直接工具调用分别有自己的契约。

原生插件通过 `host.*` 调用本体；Agent 通过本体内置工具及已加载插件工具使用能力；报告页面通过受限浏览器桥读取内容。三种调用面应在规范中分别标明。

依据：[本体版本](E:/brief2great/sesame/mt5agent/package.json:3)、[HostContext](E:/brief2great/sesame/mt5agent/modules/plugins/context.js:53)、[Agent 工具注册](E:/brief2great/sesame/mt5agent/modules/agent/tools.js:87)。

## 1. Agent、推理、工具与提示词接口

| 能力 | 已有接口 | 调用者与输入 | 返回及关键约束 |
| --- | --- | --- | --- |
| 完整 Agent 任务 | `host.agents.submit / inspect / wait / cancel / current` | 后台服务或主 Agent 的插件工具提交任务；输入 instructions、input、工具范围、插件、模型和预算 | 创建独立子会话与 Run；提交返回任务回执，完成结果为 `result.text`。子 Agent 不能通过 submit 再启动事件任务 |
| 普通父子任务协作 | `host.tasks.delegate / list / read / run / inspect / finish / stop` | 当前 Agent 委派或继续直属子会话；任务由 kind、title、task、output 等描述 | 返回会话、Run、摘要与最终成果。支持现有三层委派；该接口没有 submit 的 tools/plugins/model 参数 |
| 单次无工具推理 | `host.inference.models / complete` | 显式 model、systemPrompt、input、maxTokens，可选 temperature/reasoning/timeoutMs | 返回 text、usage、模型身份、摘要与时间；不自动携带主聊天、记忆或工具，不自动重试或保证 JSON Schema |
| 注册 Agent 可调用工具 | `host.tools.define(name, description, properties, execute)`；`Type / string / optional` | 插件用名称、说明和输入 JSON Schema 定义操作 | 工具处理器接收 args、signal，返回已完成的业务数据，宿主包装为 ToolResult。清单与工厂工具名必须一致 |
| 跨插件调用 | `host.tools.call({pluginId,name,arguments}, signal)` | 只能在仍有效的 Agent 工具调用中，调用同会话已可用的目标插件工具 | 返回完整 ToolResult；继承范围、取消与预算检查，禁止调用环，最多八层。不自动安装、加载或重试 |
| 证明当前调用来源 | `host.tools.invocation()`；`host.agents.current()` | 前者读取宿主记录的工具调用链；后者读取当前插件事件任务身份及原输入 | 供能力提供方核验真实来源；返回信息不是授权令牌，不能替代业务参数和副作用校验 |
| 提供长期行为说明 | 清单 `prompts` | 已活跃插件的提示词进入 Agent system prompt；支持现有模板变量 | 指导如何使用能力，不会创建工具或扩大调用权限 |
| 提供按需工作方法和资料 | 清单 `skills / resources` | Skill 元数据由 ResourceLoader 提供，声明资料可按路径读取 | 不自动执行流程或定时运行，也不自动把全部参考资料塞入上下文 |
| 对外接入完整 Agent | HTTP/OpenAPI 会话、消息、响应与 SSE 接口 | 外部客户端经应用认证向 `/api/v1/conversations/{id}/messages` 提交消息，经 `/api/v1/events` 接收事件 | 复用宿主会话 runtime；不是直接对外暴露整个 HostContext |
| 对外导出工具 | `POST /api/v1/mcp` | MCP initialize、tools/list、tools/call 等协议 | 只导出受信 `mcp_export` 允许的工具；工具调用不自动变成完整 Agent 对话 |

源码依据：[事件任务](E:/brief2great/sesame/mt5agent/modules/agent/plugin-agent-tasks.js:58)、[推理端口](E:/brief2great/sesame/mt5agent/modules/plugins/inference.js:23)、[普通委派](E:/brief2great/sesame/mt5agent/modules/agent/runtime.js:281)、[跨插件调用](E:/brief2great/sesame/mt5agent/modules/agent/plugin-registry.js:480)、[提示词装载](E:/brief2great/sesame/mt5agent/modules/agent/plugin-registry.js:584)、[MCP 出口](E:/brief2great/sesame/mt5agent/modules/agent/plugin-system/mcp-server.js:31)。

将 `host.agents.submit` 写成统一的任务契约时，当前可用字段如下。

| 契约部分 | 当前字段 | 实际含义 |
| --- | --- | --- |
| 身份与任务要求 | `requestId`、`title`、`instructions` | 三者必需；requestId 在提交插件内幂等，同键不同内容冲突 |
| 输入数据 | `input` | 必需 JSON 对象；显式传入事实与引用，不自动继承主聊天；宿主复制并计算 inputDigest |
| 会话类别 | `kind` | 仅 research / strategy；不是任意角色名称或权限等级 |
| 工具集合 | `tools` | 可选显式白名单，最多64个；不传则沿用普通子 Agent 规则；嵌套跨插件调用也受该集合约束 |
| 插件组合 | `plugins` | 显式挂载最多32个插件，可包含纯 Skill 包；固定版本摘要，不扩大 tools 的范围 |
| 模型选择 | `model` | `{provider,id,configurationDigest}`；默认固定提交时用户选中的模型 |
| 调度 | `lane`、`queue` | 同插件同 lane 串行；fifo / latest，latest 只替换未启动任务 |
| 时效与预算 | `expiresAt`、`timeoutMs`、`maxTurns`、`maxToolCalls` | 有效期包含排队时间；默认15分钟、12轮、32次工具调用 |
| 交付去向 | `output` | `{type:'none'}` 或 `{type:'report',space:'research'或'strategy',path:'目录/文件.html'}`；这是报告目的地，不是模型输出 Schema |

回执中 `id`、`conversationId`、`runId`、调用方 `requestId` 是不同标识。`wait` 的取消仅结束等待；停止任务需 `cancel`。任务取消不撤销已发生的外部操作。`agents.submit` 同键去重，而 `inference.complete` 的 requestId 不提供幂等去重。

当前没有 `role`、`toolScope`、`response_format`、`structuredOutput` 请求字段。研究员、评审员、执行员等角色职责可先写进提示词；要求模型返回 JSON 后，仍需调用方解析并校验。若希望本体保证结构化输出，这是后续接口扩展议题。

事件任务的 tools 限制绑定当前事件会话。普通下级委派走另一套规则，当前不能将它描述为自动传递到整棵任务树的权限对象。

完整字段、默认值、终态和源码定位见 [Agent 接口核对记录](E:/brief2great/sesame/outputs/host-interface-design-20261015/agent-ports.md)。

## 2. 插件可以调用的本体基础能力

下表的方法均以 `host.` 为前缀。主/子 Agent 指有效的相应会话上下文；服务指 `activate` 的后台服务上下文。方法存在与允许当前调用者使用是两回事。

| 本体能力 | 已开放接口 | 能够得到或改变什么 | 关键使用约束 |
| --- | --- | --- | --- |
| 身份、版本与作用域 | `apiVersion`；`application.{name,version}`；`plugin.{id,version,digest}`；`scope.{kind,conversationId,runId}` | 确认本体、插件、会话与当前 Run 身份 | 只读；本体版本、插件版本和协议版本分别核对 |
| 数据提供方 | `providers.register/list/bind/call/subscribe/unbind` | 注册、发现、连接和调用行情/账户数据，消费订阅 | register 仅服务期；按真实 capability 调用；订阅消费 snapshot/ready/close |
| 数据集和研究查询 | `datasets.sources/query/snapshot/list/read/register/registerSource` | 查询来源、冻结查询、读取或登记研究数据 | registerSource 仅服务期；query/snapshot 需要会话；当前 list/read/register 没有会话级过滤 |
| 不可变成果 | `artifacts.blob/publish/read/list/readBlob/inspect/receipts` | 保存字节及固定版本的数据、报告、指标、策略等成果；检查报告渲染 | 保留完整 ArtifactRef；更新需版本检查；publish 幂等。inspect 当前只检查 report |
| 运行事实记录 | `records.create/append/read/list` | 保存有版本的策略运行状态、依赖和观察证据 | 当前支持 strategy.run；按所有者、expectedVersion 与状态迁移追加，不负责执行策略 |
| 策略语言与参考求值 | `svl.validateSource/graph/evaluateReplay` | 校验 SVL、生成逻辑图、确定性参考回放 | 纯函数；结果不能当作原生引擎回测或实际交易凭据 |
| 当前工作区 | `workspace.path/file/snapshot/run/root/taskRoot/owner`；`workspace.operations.readFile/access/mkdir/writeFile` | 任务文件、运行目录、命令输出、快照和资源归属 | 文件/执行需有效会话；任务归属有范围检查；工作区不是 OS 权限沙箱 |
| 显式本机文件 | `externalFiles.list/search/read/import/write/mkdir/move/remove/run` | 查找、导入和修改本机文件，执行明确的命令 | 主/子 Agent 可用；按路径、覆盖、摘要及服务保护规则检查 |
| 执行环境 | `environment.capabilities/pythonPath/execution/executeWorker` | 获取平台/Python/执行信息，运行声明的包内 worker | worker 需在清单声明并归属生命周期；不自动创建隔离进程或线程 |
| 插件私有持久状态 | `storage.directory/get/list/put/update/delete/transaction/idempotent/idempotentAsync` | 保存插件状态，做本地事务与幂等记录 | 按插件隔离而非按会话隔离；transaction 为同步事务；外部副作用不随本地事务回滚 |
| 旧数据迁移 | `storage.legacy.get/list/path` | 读取已有授权的迁移集合和目录 | 属于受限迁移入口，外部插件不能通过自行声明取得既有宿主授权 |
| 长期记忆 | `memory.tree/search/list/read/get/index/propose/candidates/markUsed/save/resolveCandidate/archive/restore/forget/stats/configure` | 读取长期记忆、提交候选、审核和维护记忆 | 子任务可读获准范围并提候选；正式写入、裁决及治理由主 Agent 处理 |
| 画布、窗口和指标实例 | `layout.inspect/apply/script` | 查看布局、修改图表、挂载指标及参数 | 仅主 Agent；版本检查、命令幂等及用户操作锁仍生效 |
| 账户/图表显示字段 | `dataViews.inspect/configure/reset` | 发现可显示字段、调整顺序与图形、恢复默认 | 主/子 Agent 可用；先 inspect，再用 expectedVersion 修改 |
| 已发布报告目录 | `reports.list/read` | 读取宿主报告及发布修订 | 与报告源文件和 ArtifactRef 分开；当前没有会话级过滤 |
| 报告源文件 | `reports.files.list/read/mkdir/write/move/delete/restore/forSpace` | 管理 research、strategy 共享文件树中的草稿、目录和回收项 | 主/子 Agent 可用；覆盖/移动/删除/恢复检查版本；写文件不自动发布 |
| 实时协作页面 | `reports.live.open/close` | 打开临时 HTML 页面，向页面传递最新快照 | open 仅主 Agent；数据由 read/subscribe 回调提供；页面不自动形成持久报告或成果 |
| 执行和消息证据 | `executions.read`；`messages.read` | 读取实际进程记录、消息内容 | 子任务只可读自己或直接子会话；没有 messages.send 或任意改写消息接口 |
| 插件发现和生命周期管理 | `plugins.isActive/discover/load/read/inspect/manage` | 发现、加载、读资源、检查插件；创建/验证/测试/安装/更新/回滚/卸载/导出 | discover/load/read 可供合规子任务使用；manage 仅主 Agent；load 不等于 install |
| 本体及插件配置 | `configuration.read/update/open/exclusive/assertIdle` | 读取配置、修改支持项、打开设置、串行配置变更 | 子 Agent 不可用；update 需主会话；不是通用凭据库 |
| 插件事件发布 | `events.emit` | 发布带插件身份的事件摘要 | 没有通用 events.on/subscribe；emit 不会自动启动 Agent |
| 压缩前处理 | `lifecycle.onBeforeCompact` | 在上下文压缩前处理可见证据，获得本次会话 scopedHost | 仅服务期注册；回调有截止、取消和幂等标识；失败后继续正常压缩 |

## 3. 本体直接给 Agent 提供的 16 个工具

这部分对设计 Agent 的 tools 白名单有直接用途。名称来自本体注册表，不属于默认插件包。`host.tools.call` 要求目标具有插件所有者，当前不能伪造 pluginId 来直接调用这些本体工具；对应能力有 HostContext 入口时应使用该入口，或由 Agent 按其工具集合调用。

| 工具名 | 能力与使用规则 |
| --- | --- |
| `report_files_list`、`report_files_read` | 列出/读取报告源文件、稳定 ID 与当前版本 |
| `report_files_mkdir`、`report_files_write` | 创建目录或写草稿；已有文件覆盖需 expectedVersion |
| `report_files_move`、`report_files_delete`、`report_files_restore` | 移动、回收、恢复报告源文件；保留版本约束 |
| `data_extensions_list`、`data_extensions_read` | 发现真实提供方声明字段，读取当前值或有界历史 |
| `data_view_inspect`、`data_view_configure` | 查看和配置图表、账户与持仓显示字段 |
| `strategy_sources_list`、`strategy_source_read` | 找到和读取冻结的 SVL 策略源及逻辑图 |
| `strategy_mounts_inspect`、`strategy_mounts_configure` | 保存账户与策略源的引用关系；不启动、停止或部署策略 |
| `trade_trace_inspect` | 按真实成交 correlation 追溯运行、策略源、翻译和 trace；没有关联时明确未知 |

来源：[报告文件工具](E:/brief2great/sesame/mt5agent/modules/agent/report-library-tools.js:1)、[扩展数据工具](E:/brief2great/sesame/mt5agent/modules/agent/data-view-tools.js:5)、[策略与成交工具](E:/brief2great/sesame/mt5agent/modules/agent/account-strategy-tools.js:3)。

例如 `agent_delegate`、`report_publish`、`read/write/bash` 等当前由相应默认插件提供；其本体支撑分别是任务、成果、工作区等端口。编写规范时应把“本体能力”和“封装该能力的插件工具名称”都记录下来，避免把默认插件工具误当成不可缺少的本体方法。

## 4. 插件把什么交给本体和界面

| 产品契约 | 插件交付的接口或内容 | 本体负责的能力 |
| --- | --- | --- |
| `sesame.market` | searchInstruments、describeInstrument、queryBars、queryTicks、subscribeQuotes、subscribeBars，以及可选 readExtension/queryExtension/subscribeExtension | 数据绑定、结构校验、读取/订阅、图表消费与来源身份 |
| `sesame.account` | listAccounts、snapshot、queryPositions、queryOrders、queryFills、queryHistory、subscribeAccount，以及同类扩展字段接口 | 账户展示、明细与真实成交关联、订阅和来源校验 |
| `sesame.indicator` | 指标成果；静态序列或单文件 JavaScript `compute(input)` → `{status,series,diagnostics}` | 隔离计算、参数和输入校验、图表实例及绘图 |
| `sesame.report` | 离线 HTML/资源、固定数据和关联成果引用 | 隔离渲染、只读数据桥、渲染检查与回执 |
| `sesame.strategy` | SVL 源、目标、翻译、验证、trace、结果等成果，以及版本化运行记录 | 源校验、逻辑图、参考求值、成果关联与运行事实展示 |

只有 market/account 注册读取和订阅 provider。其他三类主要通过 artifacts/records 交付。本体没有统一的 `submitOrder/compile/backtest/deploy` 业务端口，这些业务能力由插件工具定义。

提供方订阅的公共消费约定应使用 snapshot、ready、close 等稳定字段，不依赖当前返回对象中偶然携带的内部 entry/implementation。

## 5. 接入、曝光与生命周期契约

| 规范要素 | 当前对应入口或字段 | 已有约束 |
| --- | --- | --- |
| 插件身份与兼容 | `id / version / apiVersion / engines.sesame` | 安装包版本、接口主版本和最低本体范围分别声明；新能力需检查实际可用性 |
| 服务入口 | `activate(host)` | 获得 service 上下文，用于一次注册与恢复；不作为当前 Agent 会话使用 |
| 工具入口 | `createTools(host)` | 同步返回完整工具定义；工厂只构造工具，不启动业务或执行 I/O |
| 工具结构 | `tool_names / tool_definitions` | 名称集合及 schema 与实现一致；名称归属由宿主登记 |
| 曝光和可委派范围 | `default_state / agent_scope / main_tool_names` | mounted/discoverable/disabled；main/all；主会话专属工具由宿主过滤 |
| 提示词与资料 | `prompts / skills / resources` | prompts 可进入系统说明，skills/参考资料按需读取；文字不授予权限 |
| 显式组合 | `dependencies`、任务 `plugins/tools` | 依赖检查、加载选择和工具白名单各有职责，不互相替代 |
| 服务回调 | `dispose / beforeDeactivate / beforeConfiguration / configurationChanged / beforeMessage / messageRejected / protectArtifacts / cleanupRun` | 由宿主在实际生命周期调用；同步 hook 不可返回 Promise；不是自由命名的通用事件总线 |
| 可导入 SDK | `@sesame/plugin-sdk/protocol`、`decimal`、`svl`、`schema`、`schema/value`、`toml` | 类型、验证和纯函数模块；与运行期 HostContext 分开记录 |

## 6. 据此设计规范时，建议每项能力统一填写这些字段

下面是文档结构建议，不是新增宿主 API 或当前已经强制的 manifest 字段。

| 契约字段 | 需要明确的问题 |
| --- | --- |
| 能力身份与调用面 | 谁提供能力，入口是 Agent 任务、模型推理、Agent 工具、HostContext，还是页面桥？ |
| 调用资格 | 主 Agent、子 Agent、服务谁能调用？需要哪个插件、版本、加载状态和工具白名单？ |
| 输入及证据 | 参数 schema、单位、时间、完整引用、数据来源；外部资料与任务指令如何分开？ |
| Agent 提示词职责 | 目标、方法顺序、可以调用的能力、停止条件、需要报告的未知项；哪些检查必须由工具执行？ |
| 输出与验收 | 返回文本、结构化业务结果、任务回执还是 ArtifactRef？谁负责 Schema 校验？什么事实才算完成？ |
| 副作用与幂等 | 会写哪些状态或触发哪些外部动作？同一请求如何去重？结果未知时先读取哪些事实？ |
| 生命周期与恢复 | 超时、取消、过期、配置变化、插件更新、重启后如何处理；谁释放连接与订阅？ |
| 展示与交付 | 临时实时页、源文件草稿、已发布报告、不可变成果分别何时产生？ |

需要后续明确的设计点主要有：结构化 Agent 输出是否提升为宿主契约；工具范围是否向普通下级委派传递；共享数据集/报告空间的可见性策略；本体内置工具与原生插件调用入口如何对齐。这些是当前清单揭示的接口设计问题，不能通过提示词假定已经解决。
