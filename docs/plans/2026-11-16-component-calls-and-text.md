# 统一组件调用和文字职责

## 目标

报告和回答共用 `components_show`。常用图表只提交图型、数据和必要映射；不要求先查目录或单独校验。未知组件按需 describe，show 自动完成规范化、校验和现有发布。

宿主、SDK、消息类型、当前用户工作区与运行中应用不变。本次仅修改 Reports 插件及其验证材料，不引入依赖。

## 调用边界

- 组件保留现有 `type/kind/rows/options` 结构，单个用 component，组合用 components，完整页面用 content；target 选择 report/answer。
- 不再要求 operation_id、外层 title、provenance_kind。operation_id 优先使用宿主已提供的 execution.callId，明确传入仍可用于可重试发布；不按内容跨轮去重。
- 标题从已提供的标题或组件类型生成索引名称，避免重复显示。来源性质继承真实固定数据；没有可继承来源时记录为提交的派生内容，不伪造数据供应商或核验状态。demo 数据不能被标记成真实观察。
- 图表 columns 从实际行推导，title/takeaway/source_note 不再强制。字段映射、单位及有意义的图形约束仍校验。固定引用和明确数据不变。
- show、validate、按需描述及样例保持一致。高级固定输入仍保持不可变与可追溯。

## 文字职责

1. 标题：命名报告、章节或组件。相邻父子标题完全相同时只展示一次，不进行语义猜测去重。
2. 结论与条件：作为正常字号的正文或判断内容，紧邻其对象。可选，不为每个图强制生成结论。
3. 读图信息：轴、单位、图例、数值、时间范围和必要编码说明保留在对应视觉位置，不能当作杂字隐藏。
4. 补充解释：每个单元使用统一位置和样式；不重复输出标题、结论或内容已表达的信息。长说明应写正文或显式明细。
5. 来源、方法与计算记录：保留在固定数据、输入和引用中；不自动生成页尾附录或每图小字。只有读者明确需要的内容才显式放入正文或 details。

统一控制文字生成而非用 CSS 隐藏全部 small/caption。自动生成的泛化教程、重复样本数、交互提示不再占据默认图面；实际单位、尺度、状态和会改变解释的方法信息保留或进入可访问的具体图形信息。

后续确认：图后不自动追加解释段落。必要图例保留短标签；内部处理、校验、样本统计与方法过程保留在固定记录及可访问说明中，不默认铺在正文。金融术语保留；通用语言与语气沿用宿主系统提示词，插件只定义文字位置及默认可见性。

## 实施与验证

先补回归锁定真实数据、映射错误、demo 继承、固定输入、标题去重与必要标签的行为，再分别修改调用规范化和文字渲染。随后更新提示词、按需说明与图鉴。测试覆盖简单组件、组合、完整报告、回答展示、全部图型、窄屏及真实 MCP 发布。独立复核改动和遗漏后本地提交，不推送或重启。
