# 研究检验、条件使用与历史证据

用户要求：补齐原生回测、可选优化器、历史同类情景匹配、概率校准及多次试验校正。检验项目和阈值由 Agent 根据任务选择，用户要求优先。因子不必通过全部检验；能够说明何时有效、何时可能失效，并有实际证据支持时，可以有条件使用。

## 组件分工

| 组件 | 职责 | 不承担的职责 |
| --- | --- | --- |
| `investment-research` | 理解问题、选择来源和方法、组织历史证据、交付 Research | 不规定唯一理论或固定特征 |
| `auto-factor-mining` | 组织因子与策略实验、保存全部尝试、条件选择、可选原生验证、交付 Strategy | 不以所有诊断通过作为统一门槛 |
| `factor-evaluator` | 计算因子指标、可选稳健性诊断、DSR/PBO、冻结选择回执 | 不把理想化组合收益当作原生成交结果 |
| `historical-evidence` | 历史情景匹配、过去预测的概率校准与独立评价 | 不自行联网获取数据，不替用户指定分析流派 |
| MT5 / vn.py / Backtrader | 按已声明接口执行真实回测；有原生优化器时可选使用 | 不把接口存在等同于环境已配置或实盘有效 |
| `reports` | 组织已有结果、图表、精简判断和可核验依据 | 不计算概率，不决定分析方法或因子淘汰标准 |

## 选择与检验

Agent 在评价前记录问题、预期有效机制、所选检验、阈值及理由。阈值默认是判断证据；只有用户明确的硬性要求用于阻止选择。检验未通过、不可测和未请求是不同状态，必须分别保存。数据格式、来源一致性、时间泄漏和不可伪造的实测结果仍属于计算正确性的基本条件。

一个因子的选择说明可以包含有效环境、失效环境、支持样本、反例、使用方向、限制和监控/停用条件。整体表现较弱但有条件证据的因子可以保留。事后发现的有效条件属于探索结果，需要后续独立样本验证，不能在报告中升级为已验证规律。

## 数据边界

1. 因子研究保留现有开发集与最终留出集隔离。一般数据访问能力会使该轮成为 development-only；不能仅靠提示词宣称严格隔离。
2. 原生引擎属于可选的额外验证：开发窗口用于回测或优化，参数与选择规则冻结后再评价留出窗口。原生引擎本机的数据访问范围与因子评估器的隔离范围分别说明。
3. 历史匹配只使用当时已可见的特征及截点前已到期的结果。优先近期同品种；不足时扩大同品种历史，再在明确可比条件下使用其他品种。不同层级和条件保留各自结果。
4. 概率校准使用过去固定预测和实际结果，按时间分开拟合与独立评价。当前预测不需要虚构标签；经验频率、校准后的数值与独立评价表现分别记录。
5. DSR/PBO 处理完整已记录的试验集合。缺失试验、不可对齐收益或不满足计算条件时保留原因，不能只用最后赢家生成看似精确的校正概率。

## 验收范围

数值测试核对已知结果、异常输入、时间边界和不可测状态；真实宿主测试核对安装、能力声明、固定引用和工作流交接。真实引擎样例只证明相应实现路径。合成数据、预制模型回复与真实市场研究结果必须明确区分；没有执行的券商环境和真实模型会话不得写为通过。
