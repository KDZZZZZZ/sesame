# 插件分层与组合改造

目标：让 Agent 根据研究问题组合已声明能力，而不是逐包执行固定教程。按能力划分责任，同一插件可以同时含只读信息与执行能力。

## 分层契约

| 层次 | 负责 | 交给调用者 | 不承担 |
| --- | --- | --- | --- |
| 信息获取、解析与行情 | 获取或转换指定资料，说明来源、时间、覆盖和缺口 | 可复用的固定证据、原始引用、字段和单位 | 市场判断、研究方法选择、交易决策 |
| 分析方法与计算 | 用明确假设回答一个局部问题，复用已满足前提的证据 | 观察与解释、参数、支持/反证、失效条件及证据引用 | 重新组织整项研究、默认重新取数或另开最终报告 |
| 工作流 | 分解目标、选择互补方法、补齐具体缺口、比较与综合结果 | 可复核结论、分歧及下一步依据 | 把同源指标当独立证据计票、假造不可用资料或执行回执 |

这些是语义交接原则，不新增所有工具必须使用的 JSON 外壳。知识方法可以由用户或工作流选择；知识加载不是数值工具执行证据。用户明确限定的来源、交易授权和实际算法前提继续适用。宿主统一负责身份、用户沟通和恢复语义。

## 已确认问题

- 八个知识方法限定“仅用户选择”，并把取数、分析、报告写成固定全流程；知识目录只描述文件路径。
- 手工交易和因子挖掘选择的知识插件没有传入成员 Agent；现有 host.agent.run 只能从授权工具反推插件，因此没有工具的知识包丢失。
- 信息解析教程把 HTTP 20k 预览当全文，并夸大原 URL 保留；MCP 解析器不能直接消费 DataRef，应如实描述真实输入和交接条件。
- 工作流角色没有明确的证据复用、互补方法选择和相关性处理原则；评估器混入工作流角色和报告策略。

## 实施与保护

1. 三个独立审计/实施分工：信息能力；知识方法与 ABU/评估器；工作流。根 Agent 负责宿主知识传递、核心插件指导、集成与实际模型测试。
2. 对知识传递补失败回归，再新增 host.agent.run 的可选 plugins 列表，复用内部任务的现有插件激活机制。工具权限仍只由 allowedCalls 授予；知识加载不会授权执行。
3. 改写目标、输入/输出、方法选择和组合边界，删除重复步骤。保留时间可得性、数据覆盖、真实调用方和交易授权等有效约束。
4. 跑现有方法/计算/工作流/宿主回归与锁一致性。解析器做真实 MCP 样本验证。
5. 使用隔离 Sesame Runtime 和已配置 OpenAI gpt-6.1-sol 做自然目标端到端测试，记录真实调用、错误/重试、证据复用、知识可达性与产物。合成资料只验证工程能力，不声称市场收益。

## 范围与验收

- 不接触真实交易，不修改用户会话/报告/凭据；不回退本轮前已有 Store 修复与 Kurumi 改动。
- Kurumi 本轮只审计：其历史回放边界和现有未提交工作需另行整合。
- 简单问题可以单方法完成；复杂问题能组合互补方法，不强制全量调用或固定步骤。
- 知识包确实进入成员提示上下文；调用权不随知识包增加。
- 已有固定数据能被多个方法复用；来源缺失不被当成零结果；方法输出与工作流综合可区分。
- 验证报告记录实际结果和未覆盖项，不以提示词静态匹配代替实际运行。

## 实施结果

已修改 4 个核心包与 44 个可选包，补齐宿主知识选择、依赖预检和同 Run 恢复；八个知识方法、十八个 ABU 方法、信息能力及两个可执行工作流的组合边界已更新。插件作者说明同步维护，现有数值算法和交易执行 Schema 不变。

真实 openai/gpt-6.1-sol 验证了单问题、互补方法组合、必要证据缺失暂停及八成员工作流。最终工作流仅读取一次冻结行情，两次方法计算供多空、风险和经理复用，十次工具调用全部成功；经理总结保留实际数值且不再复制技术引用 JSON。全部资料与账户为合成测试输入。

全量旧测试仍有 API 夹具、历史/版本断言及 Kurumi 失败，不能宣称全量通过；本轮 MT5 文案回归已修复并重新通过相关 56 项测试。完整审计、逐项验收和未覆盖项见 [验证报告](E:/brief2great/sesame/outputs/plugin-composition-20261018/REPORT.md)。本轮未发布或安装，未触碰原有 Store 和 Kurumi 开发改动。
