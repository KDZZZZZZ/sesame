# 报告宿主与插件的分工

采用用户确定的边界：**宿主选择报告插件，插件决定接受什么内容。**

## 生成流程

1. Agent 调用 `host_reports_describe`，取得宿主当前选择的插件及其内容说明。
2. Agent 按该插件的说明整理内容；较长的内容可先保存为固定 JSON，再用 `inputRef` 提交，避免重复转抄公式和数据。
3. `host_reports_publish` 调用宿主选定插件的 `sesame.report/1` 服务。插件检查内容并生成页面，宿主保存完整报告及所用资料。
4. 实际打开和检查报告后，再确认显示正常。发布成功不自动代表图表、文字或交互已经检查。

宿主保留标题、语言、资料引用、发布版本和页面包等共同要求；不规定报告的金融种类、图表种类、分析方法或内容组件。插件的输入可以是对象、数组或其它受其声明支持的 JSON 结构。更换插件不需要给宿主增加新的金融字段。

## 谁选择插件

只有一个可用报告服务时，宿主直接使用它。存在多个服务时，由宿主的 `report_provider` 设置选择；Agent 的发布请求没有临时切换插件的参数。指定插件失效或版本不符时明确报错，不悄悄换到另一套样式。

已经发布的报告保留原有内容与呈现，不依赖原插件继续安装才能阅读。

## 默认报告插件

Reports 5 使用一套蓝灰、无框的默认排版。Agent 根据内容选择图表、指标、范围、比较、推理步骤和分组；用户可以调整建议模板和组合。旧的三种排版预设不再提供给新报告选择。

默认插件接受结构化内容、资料和受控样式扩展，不接受 Agent 上传 HTML、CSS 或脚本。用户需要的表现超出当前能力时，可以扩展报告插件的内容说明和渲染实现，或安装适合的新报告服务；不要求宿主枚举所有未来样式。

报告只负责呈现。采用什么理论、分析方法、参数和历史检验，由研究过程按任务及用户要求决定。展示概率需要相应的历史统计支持；样式不负责生成概率。

## 实际接入

- 宿主最低版本：`0.3.0-dev.2`。
- 默认报告插件源码：`sesame/reports 5.0.5`；`5.0.0` 是本轮真实任务的首个验证版本，旧结果保留实际使用的版本。安装与打包状态以验收目录中的记录为准。
- 投资研究的报告阶段获准读取当前报告说明并发布；读取插件公开知识的能力，无论自动提供或显式选择，权限一致。
- 固定的策略/交易报告适配器只向其支持的内容格式提交。其它报告服务尚未适配时明确说明，不改变宿主选择，也不退回自由 HTML。
- 原生回测可以提交策略说明和真实结果引用，不再被要求伪造另一种策略语言的结构图；已有热力图、完整参数试验和敏感性图仍保留。

## 验证记录

宿主隔离测试使用两种内容形状不同的报告服务，覆盖正式设置、版本变化、固定 JSON、重复发布、拒绝 HTML 绕行和旧报告读取。默认插件与研究/策略/交易流程另有实际宿主和浏览器检查。这些隔离测试不冒充真实模型测试。

真实模型任务的覆盖计划及逐项结果保存在 `output/report-real-tasks-20261029/`。只有实际取得资料、生成并检查的报告才记录为完成；准备数据和演示预览分别标注。

真实任务暴露的显示问题由对应层处理：图表参数与窄屏情景树在 Report 插件内修复；报告检查器的内存归属在宿主 `0.3.0-dev.3` 中修复。后者分别限制报告页面和可信承载页，共享进程仍按完整进程计算，不取消任一上限。这些改动不向宿主增加金融内容或图表种类。

5.0.2 根据树实际排布后的字大小选择横向或纵向，不再只看固定屏幕宽度。正文保留具体的解释和历史样本，不重复显示内部验证状态标签；完整状态仍留在末尾依据中。

5.0.4 继续只在插件内处理排版：事件名称按实际宽度换行，横条图自动容纳全部数据行。报告作者提供的高度不再把末尾结果裁掉；原始时间位置、数值和点击对应记录保持不变。

5.0.5 在插件的通用内容中增加附件列表。Agent 提供显示名称和本次报告已保存的附件路径；插件生成下载入口，宿主仍通过原有的包内资料下载功能交付文件。这个扩展不增加宿主内容类型，也不放开普通 Markdown 的链接规则或原始 HTML 上传。
