# Reports 新架构：纯视觉插件

2026-11-16 · 已实现为 Reports 6.0.0；[当前架构概要](../reports-and-research.md)。以下保留实施依据。

依据用户最后确认的范围：Report 只负责视觉，不包含固定业务报告模板，不引入主题单元。如何调查、常见问题的预设回答结构及未命中问题的适配由新 Research 插件承担。宿主与 SDK 不改。

配套方案：[Research 插件设计](2026-11-16-research-plugin-design.md)。

## 1. 当前问题与重构目标

组件目前直接实现在 `sesame/reports` 中，统一入口已经建立，但旧报告内容架构没有清理：

- 38 种图表、15 种内容块已经能够统一调用。
- 同一插件仍包含 19 个业务模块、11 个报告组合，研究前选择模板、首屏字段、默认情景树等要求。
- `document / modules / backtest / signal-study` 四类内容分别进入不同处理分支。
- 采样政策、置信度、历史论证等研究校验与视觉渲染混在同一依赖链。

新版本继续使用 `sesame/reports` 这个产品入口，将内部收敛为：**选择视觉组件 → 组合排版 → 确定性渲染 → 现有宿主交付**。

Report 接收已有文字、数据和引用。它不决定要调查什么、不要求补齐某套研究问题，也不自行改变专业结论。

## 2. 按第一个聊天开头的架构组织

采用的是规则的职责与作用范围分层，不是增加一套内容分块模型。

| 层次 | Report 中的职责 | 加载方式 |
| --- | --- | --- |
| 宿主规则 | 沿用通用行为、授权、能力调用、任务和固定成果规则 | 现有宿主机制，不重复写入插件 |
| Registry / 插件元数据 | 简述适用任务、可用视觉和能力入口 | 使用现有插件描述、能力与知识声明，不新增宿主元数据格式 |
| `prompt.md` | 职责、使用时机、边界、默认调用入口 | 选中插件后的短入口 |
| Workflow / `SKILL.md` | 必要步骤、阶段转换、完成条件、失败处理 | 根据任务选择短流程 |
| `references/` | 选图、排版、文字位置、交互、绑定、交付和修复细则 | 具体问题触发时读取 |
| Role Contract | 当前 Agent 要呈现什么、有什么输入、交付在哪里、完成条件 | 写入现有委派指令与输入输出，不另建调度层 |

当前 harness 会在预算内装配选中插件的 Skill；没有资源读取工具的受限 Agent 也可能获得完整入口。因此不能把长 prompt 改名为多个长 `SKILL.md`。短流程保留必要操作，细节放普通 reference；委派时通过现有机制提供所需读取能力。

## 3. 两个短 Skill 与可查询组件目录

### `visual-compose`

输入是已经形成的文字、数值、数据及所需表达关系。

1. 根据已有内容选择文字、表格、指标、图表或关系图；不熟悉时查询目录。
2. 绑定实际数据，选择必要的排列与组合。
3. 提交统一组件入口；修改时复用原数据和原报告。
4. 只修复诊断指出的组件、字段或布局，不重新展开研究。

完成条件是内容进入受控组件，数据关系及必要标签准确，布局可读。需要新分析时交回 Research 或对应生产者，不在这里追加研究流程。

### `report-delivery`

处理实际发布、指定位置、原报告修订、浏览器渲染检查及按需导出。

完成条件分别记录：已发布、当前修订已渲染检查、请求的文件已导出。发布、渲染通过、导出成功不能互相替代。只有内容或相关条件变化、出现新问题时，才重开受影响检查。

这两个 Skill 是使用指南，不是两个额外 Agent 或两个强制串行工具调用。已有短组件可以一次 `components_show` 完成展示。

组件目录由实际定义生成，按需返回：**什么时候用、需要什么数据、准确参数、合法组合、交互与导出能力、最小样例**。不把全部图表教程自动注入上下文。

## 4. 内容与调用不增加新层

保留现有简单调用：

| 入口 | 职责 |
| --- | --- |
| `components_show` | 一个组件、一组组件或通用文档的展示与发布 |
| `components_list` | 按表达关系和数据条件查目录 |
| `components_describe` | 读取选中组件的准确字段与示例 |
| `components_validate` | 需要时只检查输入，不发布；不是必经步骤 |

例子仍是直接提交图文：

```js
components_show({
  target: "report",
  title: "两组结果比较",
  provenance_kind: "demo",
  components: [
    { type: "markdown", text: "演示：B 组的数量是 A 组的两倍。" },
    {
      type: "chart",
      kind: "bar",
      rows: [{ 类别: "A", 数量: 2 }, { 类别: "B", 数量: 4 }],
      options: { x: "类别", y: "数量", unit: "个" }
    }
  ]
})
```

`component`、`components`、`content` 三种输入择一，相关组件可以一次提交。`target: "answer"` 使用同一组件和视觉规则。

完整内容沿用通用 `document` 的排版容器与内容块；`sections` 只在需要章节排版时使用，`group` 只用于纵向或并排组合。它们不绑定研究问题、主题身份或固定必填字段，不新增 `units`、Answer Unit 或其他语义中间层。

正文仍是 Markdown 或文本块；数字和图形通过真实 rows 或固定数据引用提供。目录、数据绑定、渲染和校验使用同一份组件定义。普通输入默认值由插件处理，不要求 Agent 为使用默认视觉额外查样式。

## 5. 程序负责视觉，Research 负责内容

Report 内部只需要三个实现部分：

| 实现部分 | 负责什么 |
| --- | --- |
| 组件与组合定义 | 文字、数值、图表、表格、关系图、布局、允许的交互与数据映射 |
| 统一渲染 | 数字格式、字体、主题、文字位置、坐标轴、标签、尺寸、响应式及联动 |
| 交付适配 | 固定引用、宿主提供者、报告与回答表面、发布修订、渲染和导出检查 |

保留 38 种图表和已有有效内容块。专业图形仍可使用，例如 K 线、净值线和决策树；输入只描述通用数据和图形关系，不要求 Report 理解策略试验或研究 Run。

首页概览不再是必选入口或业务字段集合，可直接用已有文字、指标、表格和图表组合。分项判断组件取消默认的研究字段套装，展示项目和标签由输入决定，不把整页模板藏进大组件。

文字位置统一管理：

| 信息 | 位置 |
| --- | --- |
| 标题 | 当前内容的一个明确标题，不自动重复命名 |
| 判断与解释 | 文本组件、正常阅读字号，只保留实际需要的文字 |
| 单位、时点、数据标签 | 对应轴、图例、标签或共用范围 |
| 明细与附件 | 按需要显式放置，原位查看 |
| 来源与工作记录 | 固定成果和引用，不自动铺成页尾小字或附录 |

收拢重复的 `takeaway / note / caption / source_note` 外围说明入口，正文由文本组件承载；图形自身必要的标签、注解仍由组件声明。保留金融术语和影响理解的重要条件，不复制宿主已有的通用语言提示词。

Agent 不提交任意 HTML、CSS、脚本或自由字号。保留背景、字体、无框排版、蓝灰强调与盈亏涨跌红绿；整个输出共享主题，修订保持用户的已有样式。

## 6. 保留交互与数据真实性，移出研究校验

旧回测页面的能力先提取、再退役专用页：

| 现有能力 | 通用视觉实现 |
| --- | --- |
| 指标、品种与周期选择 | 选择器、选项和展示状态 |
| 参数试验及敏感性联动 | 用明确键关联的固定结果视图 |
| 试验表、逐笔记录、分页 | 通用表格、分页、选中记录与原位明细 |
| 净值、回撤和价格对照 | 共享选择或时间范围的多图组合 |

组件只切换、筛选、排序或高亮已有数据。研究生产者负责统计、选优和计算；不能把按钮或选择器暗中接成研究执行与交易入口。

Report 保留数据类型、合法图形、精度、单位、引用完整性、真实交互及视觉检查。采样政策、假设是否得到支持、置信度怎么算、研究问题是否回答充分等归 Research 与对应专业方法/评估能力。

`components_show` 内部的输入检查和预渲染，不替代 `report_check` 的实际浏览器渲染检查，也不证明研究结论正确。

## 7. Research 与 Report 的窄交接

Research 定义如何调查，并保存常见问题的预设回答结构；未命中的需求参考相近结构，为本次问题形成合适的调查与回答安排。这些结构留在 Research，不重新进入 Report 的 schema。

Report 接收的交接仅包括：

- 已形成的文字与专业判断。
- 需要展示的实际数据、单位、时点与固定引用。
- 本次希望的顺序、重点或展示要求，必要时附已有图形引用。
- 报告标题、交付位置或原报告身份。

这是一组交接信息，不新增强制的语义文档协议。主 Agent 或现有工作流使用双方 Skill 完成同一任务；Report 可以重排视觉，但不擅自改专业内容。发现数据或说明不足以准确展示时，返回具体缺口，交回研究侧处理。

## 8. 建议目录

```text
reports/
  plugin.json / capabilities.json    # 现有插件机制下的描述与能力声明
  prompt.md                         # 短职责入口
  skills/
    visual-compose/SKILL.md          # 选组件、绑定、组合、修订
    report-delivery/SKILL.md         # 发布、检查、导出、失败处理
  references/
    component-selection.md          # 按数据关系选图
    composition.md                  # 纯视觉的排列和组合
    typography.md                   # 文字职责与位置
    data-binding.md                 # 固定输入与精度
    delivery.md                     # 发布、版本、实际渲染和导出
    repair.md                       # 对应错误发生时读取
  components/                       # 定义、目录、参数与样例
  renderer/                         # 主题、排版、图表、公式、交互
  delivery/                         # 工具与现有宿主适配
  examples/                         # 视觉示例，没有业务必填章节
  tests/
```

复用已验证的图表代码，不为了目录整齐重写全部实现。通用 HTML 外壳放在 `renderer/document-shell.html`；它是页面载体，不包含固定业务章节。

## 9. 迁移清单

| 现有内容 | 新去向 |
| --- | --- |
| 19 业务模块、11 报告组合、分析问题、业务字段指南 | Research 的调查指南与常见问题预设回答结构，逐项保留有效原则并重审适用条件 |
| `report_structure`、`report_compose` 与固定模板工具 | 从新 Report 生成路径移除；研究信息改由 Research 发现和读取 |
| `modules / backtest / signal-study` 专用内容分支 | 移出 Report；实际结果生产者提供通用数据和内容，统一渲染 |
| 策略源码、研究 Run 与特殊证据对象的解析 | 对应专业插件负责解释，Report 消费可展示结果 |
| 业务模板绑定的视觉计划与首屏字段 | 视觉关系抽成通用选图/布局规则，业务回答要求归 Research |
| `report_data` 快照便利能力 | 归数据访问插件；Report 仍能消费固定数据 |
| 通用判断、诚信及用户沟通原则 | 沿用宿主；研究专属原则归 Research，视觉规则留 Report |
| 发布、原路径、引用、修订和导出 | 继续使用现有宿主与交付接口 |

`report_render` 留作提供者入口；`report_read / report_prepare / report_check / report_export_check` 与样式管理保留按需使用。新 Agent 的主要展示入口只有 `components_show`，重复的旧发布便利入口随调用方一同迁移。

已确认需同步调整 `investment-research` 的结构/组合依赖、`orchestration` 的旧授权示例、`trading-decision` 的发布转接和工作流测试夹具。当前生产版 `auto-factor-mining` 未发现硬编码旧 `signal-study`，不根据备份臆造迁移任务。

同一报告继续按现有身份和期望版本发布完整新修订，保留未修改内容、引用、附件与路径。旧固定 HTML 和资源不改写；旧输入若需重新生成，先转换到新通用内容。历史阅读与导出分别验证，不承诺旧生成 schema 继续可用。

## 10. 实施与验收

先固定双方职责、通用组件输入和迁移清单，再并行整理视觉实现、Research 内容、调用方。接通后删除旧业务分支，不长期维护新旧两套默认生成体系。

完成标准：

- Report 的 prompt、Skill、schema 和运行依赖链里没有固定业务报告模板、研究问题清单或研究充分性要求。
- 不引入主题单元，不强制研究结构、首屏概览、收尾情景树、说明小字或附录。
- 常见研究问题的有效结构和原则在 Research 有明确接收位置，未命中问题有参考既有结构的适配过程。
- 38 种图表、必要文本与原有关键交互保留；真实数据绑定、单位和数值没有因改版失真。
- 同一内容可以用于回答和报告；修复只影响相关内容，不重跑研究或新建重复报告。
- 桌面、窄栏、深浅主题、长文、公式、交互及 PDF/图片经过实际渲染与文件检查。
- 宿主、SDK 和既有报告位置/版本机制保持不变，历史报告查看与导出可验证。

## 11. 参考与设计取舍

主要架构依据是[第一个分享开头](https://chatgpt.com/share/6af982aa-a824-83e8-94e2-4abe985c850d)的 Skill 内容组织：按职责和作用范围分层；元数据负责选择，短 Skill 负责流程，参考资料按条件读取，当前任务通过角色交接约定目标与输入输出。已取得公开页面和完整解码消息，使用的是前半段内容，不采用后半段的 Answer Unit 设计。

[第二个分享](https://chatgpt.com/s/t_6afaad399a208191bb21671dabbf3c17)中“Agent 提交语义映射、程序处理视觉”和合法组件组合的建议保留；研究内容覆盖责任按本轮要求归 Research。参考 [json-render Catalog](https://json-render.dev/docs/catalog) 的同源组件定义，继续使用现有技术栈，不为重构增加运行时依赖。

决策：组件继续属于同一个 Reports 插件，内部拆清职责；新生成路径移除旧业务模板，代价是同批迁移调用方；受控组件保证视觉，新增图形通过组件扩展，不开放任意页面代码。

本次交付为设计文档。代码基线为 Reports 5.2.0、组件调用提交 `bc1705a`；本次未实施插件迁移、构建或安装。
