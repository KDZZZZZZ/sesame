# Research 插件设计：调查方法与回答结构

2026-11-16 · 已实现为 Research 1.0.0；[当前架构概要](../reports-and-research.md)。以下保留实施依据。

配套方案：[Reports 纯视觉插件设计](2026-11-16-reports-visual-only-design.md)。

## 1. 定位

新增 `sesame/research`，统一负责 **如何调查用户的问题、怎样形成有依据的答案、如何检查这次调查是否足够**。常见问题有预设的调查指南和回答结构，未命中的问题参考相近结构设计本次方案。

Research 与 Reports 使用同样的内容架构：**Plugin Prompt 写职责与选择时机 → Workflow / Skill 写执行流程、阶段出口和异常处理 → References 按需提供专业方法与回答结构。** 本次 Agent 的目标、输入和输出通过现有任务输入形成 Role Contract，不新增宿主层；具体分工见第 8 节。

这些方法由现有主 Agent 或研究成员实际执行。Research 不另建自然语言调度 Agent、Run 系统、数据后端或报告渲染器；宿主与 SDK 不变。

Research 决定应调查什么、回答什么以及答案的内容顺序。Reports 接收实际内容与固定数据，选择组件并统一呈现。报告里不再保存业务模板、研究问题清单或研究充分性规则。两者之间不新增“主题单元”或其他语义中间层，继续通过现有任务交接和成果引用协作。

上述参考给出的有效组合是：**任务专属的专业问题、可裁剪的回答结构、按需详细方法、明确的阶段出口。** 研究深度由问题和证据决定，不用预设篇幅替代完成标准。

执行机制和金融内容分别取材。前者参考上述 Agent 项目，后者已进一步核对 Morningstar 公司研究样例、DBS 财报前瞻与点评成品、IMF 宏观报告、BlackRock 周评，以及 Trading Central、Autochartist、MSCI、OIC 的专业分析说明。各来源的性质与具体内容见[独立回答结构及来源](2026-11-16-research-question-presets.md)。不能仅从软件 Skill 的文件布局推导所有金融问题的答案结构。

上述研究框架证明了问题与内容结构可以随任务调整；本次没有运行它们的跨金融任务效果评测。金融泛用性仍需要用资料检索、数值计算、事件解释、因子研究及持仓诊断等不同任务实际验收。

## 3. 常见问题保存“调查指南＋预设回答结构”

每份方法同时回答三件事：调查什么、怎样调查、最终应让用户弄清什么。预设回答结构属于 Research 的内容指导，不包含组件名称、CSS、页面位置或必须配几张图。

此前示例虽然区分了问题，但多数仍沿用相近的三段式顺序，容易使正文同质化。现改为[按金融问题区分的 21 类内容结构](2026-11-16-research-question-presets.md)，下面只列其主要差异：

| 问题 | 回答必须解释的独特关系 |
| --- | --- |
| 财报前瞻 | 现有预期、待揭晓的经营变量，以及结果公布后怎样解读 |
| 财报点评 | 实际与事前预期的差异、核心与一次性贡献、新旧经营判断的变化 |
| 公司质量与估值 | 业务怎样创造利润和现金，价格又要求多高的经营表现；按问题分别展开 |
| 事件与宏观传导 | 信息出现的时序、预期差、传导渠道、时滞及受影响对象的差异 |
| 技术结构与波动 | 前者解释期限内关键价位和条件路径；后者解释波幅和时段，不混成方向预测 |
| 组合风险与损益 | 前者解释暴露、集中和压力影响；后者解释实际损益的来源 |
| 因子与策略评价 | 因子解释提供的信息及稳定性；策略评价具体规则、成本和收益风险，应用结果单独讨论 |
| 期权结构比较 | 合约与成本如何形成条件损益，以及时间、波动和到期因素的影响 |

复用调查动作和证据，不要求复用相同正文。每份方法保存适用问题、独特调查重点、所需证据、推荐回答结构、条件分支和参考样例；不把这些组织字段直接变成用户报告的章节。

目录可以扩展，但一次任务不必读完。用户给出自己的回答结构时直接采用；预设仅补充有价值的调查角度。事实或概念问答可以直接回答。相关方法可以组合，共同事实和证据只取得一次。旧内容是否保留以第 10 节的逐项迁移检查为准，不能因为未在摘要表展开就删除。

## 4. 未命中时怎样设计更好的回答

未找到同名方法时，仍从已有方法学习调查和回答的组织方式：

1. **确定问题性质。** 用户主要需要解释、比较、诊断、条件判断、复盘还是事实整理；同时保留其真正关心的投资目的。
2. **选择相近结构。** 按问题性质、对象、期限、事前或事后状态及已有证据匹配，不只做名称相似度搜索。例如“利润增长但股价下跌”可借鉴财报差异分析和事件解释。
3. **提取有用部分。** 先确定本次主回答线，再借用相近方法的调查动作和分析关系；删除无关的公司背景、估值或交易安排，不拼接完整报告，不合并出更大的必填清单。
4. **补足这次独有的角度。** 结合用户假设和轻量摸底发现增加新问题，说明哪些是用户要求、哪些是 Agent 的探索；不先否定用户观点。继续深入应对应尚未回答的问题、重要矛盾或可能改变判断的新证据，不靠固定递归层数决定研究是否充分。
5. **用真实成果调整答案结构。** 调查可能改变解释和重点，最终顺序围绕最有价值的发现组织；用户明确要求的问题继续有对应回答。

这样既有专业起点，也能处理混合问题和新问题。方法库没有同名问题时继续寻找专业插件、数据能力与一手参考；已有方法与本次需求不符时调整方法，不能为了套用模板改变用户的问题。可复用的新方法在确认价值后再进入方法库，不把每次临时大纲都自动变成默认规则。

## 5. 一次研究怎样运行

| 阶段 | 本阶段产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| 理解与摸底 | 用户目标、对象、已知约束、已有成果及相近方法 | 已足以开始调查；不因非关键未知反复询问 |
| 制定本次调查计划 | 关键问题、证据需求、方法选择、预期回答及按需展开条件 | 用户问题都有调查安排；不预填结论 |
| 取证与分析 | 固定证据、计算结果、不同解释及其支持与反证 | 形成能回应问题的结果，或发现会改变答案的具体缺口 |
| 定向补查与复核 | 对关键缺口、矛盾或假设的新证据 | 受影响的问题得到改进；不把已经通过的部分整轮重做 |
| 综合与交付 | 有依据的答案、必要条件和可展示数据 | 本次问题已回应；复杂研究实际发布报告并核验交付 |

阶段表示研究依赖，不要求固定角色数或全部串行。独立问题和来源可并行；同一证据可以服务多种方法。已有完整成果可直接进入综合，只改视觉可直接交 Reports。

Research 不为每阶段强制发起确认。需要配置或数据时，主 Agent 先使用已有能力尝试解决，只有确实缺少用户输入或重要选择时才询问。遇到失败先定位原因和可替代路径；没有新条件时不反复撞同一个失败请求。

轻量研究可由主 Agent 直接完成，计划可简化为几行。复杂或最大努力任务使用现有编排与实际工作流；Ultra 的持续并行规则仍由现有模式负责，本插件不另设开关或停止其他任务。

## 6. 本次调查计划与成果交接

无需让用户填表，也不新增必须逐字段填满的大协议。Agent 用现有任务文本或工作区文件保留以下信息：

| 交接信息 | 最少需要说明什么 |
| --- | --- |
| 目标与范围 | 用户希望弄清什么，对象、时点、期限、比较口径和明确限制 |
| 关键问题 | 每项要回答什么，用户要求与 Agent 补充探索分开 |
| 调查安排 | 需要哪些证据，复用或从哪里取得，采用什么方法，哪些发现触发深入 |
| 预期回答结构 | 应回答的内容及顺序，允许基于结果调整，不预设结论 |
| 完成与剩余事项 | 哪些已回应，哪些仍影响判断，有无仍值得执行的具体路径 |

研究成果保留问题与答案、证据与数据、重要条件和未解决事项的关联。原始输入、完整记录和计算细节通过固定引用交接，不要求下游重抄或重新计算。

交给 Reports 的是已有正文、需要呈现的数据与引用，以及用户明确的展示要求。Research 的阶段状态、调查表和验收记录不自动进入报告正文。Report 不再检查抽样方法、置信度模型或用户问题的研究覆盖；内容覆盖由执行研究的 Agent 核对。

## 7. 与现有插件的分工

| 现有能力 | 与 Research 的关系 |
| --- | --- |
| 主 Agent、`orchestration`、宿主 Agent/Run | 选择执行者、并行与依赖关系、权限、通知、暂停恢复；Research 提供当前要研究的问题与方法 |
| `investment-research` | 继续承载可执行的综合研究工作流，按 Research 的本次计划工作；不再从 Reports 选择 M/R 模板 |
| `data-access`、`financial-research`、MT5、搜索及其他来源 | 获取、读取与保存证据；其中现有 `financial-research` 是数据源插件，名称不能误认为它已承担调查方法 |
| ICT、行为金融、机构分析、深度推理等 | 对具体问题提供专业解释或分析方法，Research 负责选择和组合，不复制其全部知识 |
| `historical-evidence`、因子与回测能力 | 进行对应计算和适用验证；Research 确定为何需要、如何解释结果，不重建计算引擎 |
| `reports` | 组件、布局、主题、交互、渲染和交付检查；业务回答结构留在 Research |
| `trading-decision` 与执行插件 | 消费研究结论并处理交易决策和账户动作；研究计划本身不增加交易授权 |

`investment-research` 中与调查方法重复的长提示移到 Research，工作流只保留实际执行与交接规则。现有阶段禁止联网等限制应按任务能力分配决定，不再作为所有调查方法的固定规律；仍要遵守本次实际授予的工具范围。

## 8. 按第一个分享开头组织 Prompt 与 Skill

依据[第一个分享开头的内容架构](https://chatgpt.com/share/6af982aa-a824-83e8-94e2-4abe985c850d)，采用按作用范围分层的结构，不机械地把一个长 prompt 切成多个文件：

| 层次 | Research 中放什么 |
| --- | --- |
| 宿主规则 | 继续使用已有授权、工具、安全和沟通原则，本轮不改宿主 |
| 插件 Prompt | 职责、选用时机、边界；研究前主动发现相关方法，已有成果优先复用 |
| Registry 元数据 | 方法名称、适用问题、需要的输入、相近方法及参考路径，供选择使用 |
| Workflow / Skill | 上述短主流程、阶段出口、未命中分支、补查与失败处理、完成条件 |
| References | 选中任务的专业调查问题、预设回答结构、方法细节和案例，按条件读取 |
| Role Contract | 本次成员目标、输入证据、预期回答、允许工具和交付；通过现有任务接口传递 |

现有 harness 会装配选中插件的 Skill 入口，所以入口自身必须简短；详细方法保留为普通 reference。没有资源读取能力的受限成员应在原任务输入中收到必需方法摘录，不能只给无法访问的链接。

作为基础研究插件，建议默认挂载轻量入口，使研究型问题能主动发现方法；完整专业资料不随默认挂载全部注入。

建议目录：

```text
research/
  plugin.json
  prompt.md
  capabilities.json
  skills/research/SKILL.md
  methods/index.json
  references/
    methods/                  # 每类问题的调查指南与预期回答结构
    evidence-and-judgment.md   # 共用证据和判断原则
    adapt-and-compose.md      # 未命中、混合问题、用户自定义结构
    review-and-recovery.md    # 定向复核、失败、范围变更与完成
  examples/                   # 简单、复杂、混合、未命中案例
  tests/
```

## 9. 对 Agent 暴露的功能

首版只需要两个轻量的发现入口，工具名称在实施时按插件命名约定确定：

- **查询方法目录**：输入用户问题或筛选词；返回候选方法、适用范围、回答结构摘要和详细资料位置。只是发现，不自动决定研究结论。
- **读取选中方法**：按方法 ID 取得调查步骤、预设回答结构、证据需求、条件分支与完成标准；一次可读少量相关方法。

Agent 已掌握适用方法时不必重复读取。两个入口读取同一份方法定义，不另写相互漂移的工具说明与技能长文。方案不新增 `research_start` 调度器，不新增宣称自动判断研究充分性的静态校验工具。

研究计划的保存和传递复用现有工作区、固定成果与任务输入；运行、恢复、取消仍使用现有工作流与宿主工具。格式和引用可用程序检查，研究是否有说服力由实际研究 Agent 根据问题与证据判断。

## 10. 从 Reports 迁入哪些原则

原 11 类报告中的有效研究问题全部保留为可选方法或方法分支。以下是迁移清点，旧组合名称不进入新运行契约，也不恢复整套 M/R 必填模板：

| 旧研究方向 | 新方法中的承接位置 |
| --- | --- |
| 资产概览 | 资产当前状态，按需要组合经营质量、新闻与情绪观察 |
| 综合行情预测 | 期限展望与条件判断，按问题调用技术事件、驱动和历史对照 |
| 事件冲击研究 | 事件解释，必要时与期限展望组合 |
| 公司价值与中长期展望 | 公司经营质量、估值与价格假设、预期修正，区分首次研究和新增信息 |
| 市场日报与机会扫描 | 关注扫描、候选筛选及相关事件安排 |
| 期权波动与策略结构 | 波动及期权结构比较，按目标纳入条件损益与风险 |
| 持仓与组合诊断 | 组合问题诊断，集中解释实际风险与损益来源 |
| 预测复盘 | 原判断与实际差异，适用时开展历史与概率评价 |
| 经济与公司事件周历 | 关注扫描中的独立日历分支；只要事实时只交付事件、时点与已知预期 |
| 策略筛选与回测评估 | 候选筛选、策略诊断与适用评估，真实计算仍由策略能力承担 |
| 组合构建与再平衡 | 配置与再平衡方法，复用组合诊断和已有历史结果 |

原 19 个模块也要逐项登记到新方法文件：行情状态、技术事件、财务质量、估值、共识修正、事件冲击、新闻主题、情绪拥挤、波动定价、期权损益、候选筛选、组合暴露、历史验证、综合展望、条件监测、预测复盘、事件日历、回测表现、配置再平衡。每项记录保留的问题、字段含义、证据原则和新接收路径；合并时保留各自有用语义。未找到接收位置的内容先补齐归属，再退役旧文件，不能将“未列入首批示例”当作删除理由。

| 迁入内容 | 在 Research 的保留方式 |
| --- | --- |
| 用户问题优先、认真探索想法 | 主流程与任务适配；先找知识和能力，再判断方法是否可行 |
| 业务调查问题、字段含义、常见回答结构 | 任务方法资料，按需选择、组合与裁剪，不自动变成每份报告的必填项 |
| 因果、规律、替代解释和反证 | 对应解释和假设评价方法；表述强度与证据相符 |
| 历史可知性、样本外及验证阶段 | 适用研究的方法与计算契约；纯事实或仅改版不追加无关验证 |
| 概率、频率、置信度的含义 | 保留真实统计含义，不用主观评分填概率；不足时仍可交付有证据支持的定性判断 |
| 研究充分性和用户问题覆盖 | 主 Agent / 研究成员的内容复核；关键未知说明实际影响，不用形式检查代替判断 |

不要求所有研究通过所有检验。先判断检验是否与当前结论有关，环境或资料缺失时寻找合适替代并保留真实状态；不能把未测说成通过，也不能因为一个无关检查未完成阻塞整个任务。

旧 `investment-research.report_brief` 的 `case/template_id/M/R/sections` 依赖同批改成任务方法与实际研究要求；旧 Reports 中相应内容退役，避免两处维持相互冲突的默认标准。

原有有效原则必须有接收文件和调用路径，不能仅保留在本设计稿中。采样与评估的具体计算继续由原计算插件执行，Research 说明使用时机与解释方式。

## 11. 验收效果

用真实模型和当前插件验证以下情形，而不只检查文档是否齐全：

- 财报前瞻、财报点评、首次公司研究得到不同的问题与回答重点，体现预设结构的实际作用。
- 同一事件的事实查询、价格传导解释和持仓影响分析采用不同调查；不能只改标题仍输出相同章节。
- “利润上涨但股价下跌”等混合问题能组合相关方法；一个未命中的新问题也能借鉴相近结构形成合适调查方案。
- 用户只问一个局部问题时，能裁剪，不额外启动完整公司覆盖或填写无关章节。
- 已有成果、更新资料和仅改视觉分别采用不同路径；视觉修改不重新研究。
- 重要推断有可追溯的依据，关键矛盾触发定向补查；没有新证据时不重复整轮复核。
- 用户问题得到回应，预设结构不带偏任务；研究侧负责内容质量，Reports 只承担视觉与交付质量。
- 复杂研究按原要求交付真实报告，简单问答可以直接回复；成员和主 Agent 的运行方式沿用现有编排。

本设计只新增调查方法与回答结构的明确归属。实际数据获取、计算、编排和视觉全部复用现有能力，新增价值通过任务是否答到点上、重复取证次数、无关展开程度和交付质量验收。
