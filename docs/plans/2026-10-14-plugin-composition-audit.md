# 插件正交组合：归因与修复计划

日期：2026-10-14。状态：dev 源码已实现并完成定向测试、真实宿主联调及包校验；未替换用户安装目录，未公开发布。各项先记录归因，再修复与验证。延续实时协作和每轮单份报告。

## 用户契约

工作流、研究、数据、执行等插件的功能互相独立，可以按任务组合。手动交易和自动因子挖掘负责组织任务、交流、证据和最终汇总，不替用户选择 MT5、回测引擎、研究来源或模型。组合不取消被调用能力本身的账户核验、真实计算、幂等执行或数据时点约束。

## 已确认的问题与原因

1. **手动交易混合工作流与执行能力。** `manual-trading/plans.js` 强制 `mt5|qmt`，`runtime.js` 拼接后端工具名，`portfolio.js`、`service.js`、`adapters.js` 承担原生单位、订单翻译及执行。扩展后端必须修改工作流，研究插件还受 `research-baselines.js` 名称白名单限制。归因：最初单笔交易功能直接扩充为调度器，没有拆开功能边界。
2. **固定角色工具排斥组合。** 手动交易自动加入 financial-research，只接受 ABU 研究名称；因子挖掘只给 context/submit。归因：把任务权限范围与某一套预设插件清单混为一体。应冻结调用者选择的可委派工具和插件版本，不猜测或自动加载替代实现。
3. **执行后端反向依赖工作流。** `mt5/tools/trading-context.js:8`、`qmt/trading-context.js:27` 只接受 `sesame/manual-trading`。相同账户和签名的另一工作流仍被拒绝。归因：用插件名称代替受托任务契约。保留签名兼容路径；新组合路径必须核验宿主证明的当前调用链、冻结账户及执行角色，不能靠模型传入的布尔值授权。
4. **因子编排与评估实现混合。** `auto-factor-mining/runtime.js` 直接调用 engine 的 AST、评估、相关性与指标阈值；提示词假设唯一实现。当前没有 MT5 绑定。研究/数据工具一旦开放，原始 sourceId 可通过 data_read 读取含 holdout 的全集；不能继续无条件声称留出数据不可见。归因：内置固定评估器的封闭测试假设被写成通用工作流合同。
5. **提示词替组合方决定上游/下游。** AKShare prompt 强制 vn.py；web-extract、rss-collect、market-data-parser 技能无条件先挂 web-sources；MT5 authoring 默认 SVL 并强制报告委派。归因：把一个示例工作流写成能力的强制使用顺序。
6. **既有主会话管理语义不统一。** 手动交易 context/viewer 核验 owner，计划管理未统一核验。该问题属于同一工作流的管理边界，不是新增权限开关；外部工具入口统一核验计划所有者，后台定时器仍按既有保存计划运行。
7. **Kurumi 固定方法白名单。** `kurumi-replay/method-workflow.js` 限制方法 ID。仅记录，遵守本轮排除 Kurumi 的要求；玩家未来数据隔离属于合法能力约束。
8. **调用来源证明的异步失效缺口。** 宿主跨插件调用在异步 schema/配置等待后没有重新核验祖先令牌。夹具证实父工具提前返回后，子工具仍可拿到含已失效祖先的 chain。新增三个先失败回归，再在实际 dispatch 与证明读取时校验完整祖先生命周期；token 不暴露给插件。
9. **复盘来源绑定品牌且混用账户 ID。** `manual-trading/memory.js` 的成交来源正则只认两家后端，记录检索账户键又被当作原生账户 ID 比较。改为冻结执行能力声明的 fillSources，加验宿主登记的 producer_plugin_id，并区分检索域与原生账户 ID。旧记录不补造来源合同、不把报价或目标当成成交。
10. **组合后才发现宿主预算超限。** 独立研究清单和执行/评估依赖各自合法，合并后仍可能超过宿主每任务 32 插件上限，导致保存成功、首次任务失败。两个工作流都在配置阶段按最终去重集合校验，并在提交任务前复核。手动交易升级导出还需仅传播其他所有者的未知订单阻塞项，避免把未知取消回执当作发单阻塞合同。
11. **派生数据可以借原生成交来源误报执行确认。** `memory.js` 沿 lineage 验证根 producer/provider，却把派生行的账户、运行 ID、数量和价格当成成交事实。独立审查用一个零行原生成交源和一行研究插件伪造的 derived fill 复现 `executionConfirmed:true`。影响复盘记忆，不构成真实发单或已实现收益。修复采用直接核验可信原生成交行；派生行仍可作观察，不能借来源谱系升级为成交确认。先补失败回归，保留其他观察与时间界限行为。
12. **拆包后的测试仍跨包引用，新增包遗漏许可证文件。** 最终官方打包校验先拒绝 `auto-factor-mining/tests/runtime.test.js` 导入相邻 factor-evaluator 包，随后发现新 evaluator 清单声明 MIT 但未附 LICENSE。生产代码已分离，随包测试却仍依赖仓库目录，破坏独立安装性。跨包集成测试移到包外统一测试目录，保留有效回归并补许可证文件，不放宽包边界校验。

## 实施顺序与边界

1. 先补能证明组合与授权边界的回归，再修改。保留当前工作区已有改动，不复制其他工作树未提交内容。
2. 手动交易计划只保存显式选择的执行能力工具引用、冻结账户和通用目标仓位；原生执行移入独立执行插件。无执行能力时不自动选 MT5/QMT。不改变原有精确数量、策略暂停、未知订单停止、账户一致性和不可重复发单保护。
3. 研究工具由调用者选择，宿主提供可委派工具元数据，工作流冻结选择。无工具的 skill 插件也必须能随任务挂载；不擅自启用禁用插件。
4. 复用宿主现有跨插件调用边界，增加只读的实际调用来源证明供受托执行验证；不得暴露 Pi、私有签名密钥或允许后台冒充 Agent 工具调用。
5. 因子评估与编排解耦、研究工具组合独立实施；留出集与真实数值回执的边界先明确再开放。无法提供的能力返回可操作前置条件，不伪造成功或自动换实现。
6. 其他插件只修已证实的职责越界提示词；专用后端支持范围和算法自身限制不算越权。

## 验证标准

- 两个不同名称的组合能力/插件可以接入；工作流配置不包含后端品牌枚举，不自动加载固定研究插件。
- 不可用、禁用、变更版本、main-only 工具被明确拒绝；不同工作流通过相同受托合同使用执行能力，伪造调用链/账户/任务仍失败。
- 只读研究角色不能直接冒用执行工具；目标不变、平仓、停止高风险挂载与未知结果保护有回归。
- 无每角色日报；真实事件和公开输出仍经宿主 SSE 到报告 HTML，每轮只有一份总结。
- 使用本地合成数据/模型/券商夹具，运行定向测试、静态检查和包验证；不执行真实交易、付费模型或生产发布。

## 实施与证据

- manual-trading 3.0.0 只保存执行协议和研究选择；原生订单/数量/挂载执行移入 portfolio-execution 1.0.0。MT5 1.6.0、QMT 1.4.0 校验真实工作流委托链，兼容旧签名。
- auto-factor-mining 1.0.0-dev.2 将计算和门槛移入 factor-evaluator 1.0.0-dev.1。通用研究工具使用 development-only 输入，报告明确没有留出验证；封闭流程可用隔离留出数据。
- 主机明确支持可委派工具元数据、无工具技能的选择和固定版本；调用证明检查所有祖先仍有效。独立 Agent 启动脱离父工具上下文，不继承失效授权。
- 执行层原先以共享存储目录串行全部账户，现按原生账户串行完整目标批次和交易写入；不同账户及研究并行。宿主现有 4 个插件 Agent 执行槽未改，未知执行不能借并发重放。
- AKShare 1.0.8 和三个解析插件 2.0.3 移除强制上游/下游组合；MT5 不再要求特定策略表达或报告委派。Kurumi 仅记录发现，包内容与锁条目保持原样。
- 最新交易/执行/QMT 本地回归 166 通过、1 个原生观察用例在该命令中跳过（独立真实宿主观察/报告面板测试 18/18 已覆盖）；复盘单测含 17 项和 3 个派生证据回归。
- 因子工作流/评估合计 67/67，加官方隔离包边界回归 1/1，共 68 项；宿主任务、调用链、配置与跨插件调用 30/30；三个解析器实际 MCP 调用与 manifest 预期 6/6。
- 真实宿主使用本地模型与原生适配夹具完成交易三轮（保持、事件触发、暂停挂载并平量化持仓）、独立执行包安装调用，以及因子并行方向/重启恢复；各轮只生成一份最终 HTML。没有真实券商或付费模型调用。
