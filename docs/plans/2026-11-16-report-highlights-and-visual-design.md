# 首屏关键结果与视觉设计步骤

## 用户目标

报告首屏应有无框、大字的关键结果组件。数据需要设计成简明易懂的视觉，多条件展望用决策树；写报告增加独立视觉设计步骤，在初稿原意不变的前提下形成图文并茂的表达。

## 本次真实生成的问题

Reports 7.0.0 已实际使用，但旧 XAUUSD 报告只移出了开篇段落、重命名首节，仍是 5 章、5 图。Sesame 主 Agent 自行给子任务加上“保留原5章节、5个图表，仅做schema必要适配”的限制；用户输入仅为“请用新版插件重新生成之前的《XAUUSD周报与三日展望》”。visual-compose 的“修改只修复诊断指出部分”未限定报错修复，放大了这种误解。此前 lead 也只有段落，未实现用户期望的关键结果格。

## 实现边界

- 只改 Reports/Research 插件，不改宿主或 SDK，不直接代写用户报告。
- 新增报告输入 highlights，复用 metrics 的 {label,value,tone?} 数组，1–6项；title → lead → highlights → body。数值、简短定性判断均可，渲染器不推断或制造结论。
- report.highlights 可按需发现；独立回答组件免报告骨架，固定输入与直接渲染使用同一规则。历史固定 HTML 读取不重新校验输入。
- 首屏网格最多三列，窄屏自适应；无额外说明槽位，沿用蓝灰主题与金融盈亏色。
- Prompt/Skill/References/示例统一“初稿 → 视觉设计 → 组件生成 → 原意与视觉核对”。首屏概览不替代证据图；多条件路径必须实际用树呈现。
- 重新生成和改版可重组信息，具体报错修复才最小改动。视觉过程保持事实、单位、口径、关键条件、时间、证据和结论含义，不锁旧章数或图数。
- 不用图数、关键词或强制装饰来替代语义验收，不增加新工具或视觉设计 JSON 协议。

## 验证

先锁定首屏缺失、有效数值/定性值、显示顺序、转义/金融颜色、inline 豁免、固定引用等回归，再实施。完成报告/研究测试与桌面/窄屏视觉检查，更新包版本及锁，并通过当前 Sesame 正常插件管理入口安装。实际模型重生成另行核对其任务约束与交付，不能以渲染通过声称视觉设计有效。
