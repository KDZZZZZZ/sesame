# 个人交易记忆：风格、风险红线与策略认知

## 目标与边界

按用户定义在现有长期记忆库内增加三种分类，不新建交易账本或风险引擎。风格是偏好，风险规则是经用户确认后必须遵守的边界，策略是有适用条件和证据的市场、指标及算法认知。交易结果不能自动证明一种风格或规则正确。

这次交付覆盖记忆存储保护、Agent 执行原则、已注册能力及手动交易工作流的读权限。保存红线不等于券商端已挂保护单，也不等于所有绕过 Agent 的原生订单都获得硬拦截。实时计算和交易回执继续由已声明的后端能力负责。

## 最小数据结构

复用现有 SQLite、版本、来源、scope 与候选机制，新增 `trading/style`、`trading/risk-rules`、`trading/strategy-knowledge`。正文使用 Markdown，不另造规则语言。scope 表达 global/project/strategy；具体后端、账户、市场、币种、适用周期和例外在正文中明确，不从同类名称推测适用账户。

正式风险规则必须为 explicit、引用真实用户确认、常驻且不自动过期。`review_at` 提醒复核，不能撤销红线。创建、修订、归档、恢复和遗忘都由主 Agent 操作；`memory_manage.confirmation_source` 指向本次真实用户消息，修订不能复用上次确认。代码核验来源身份，是否确实同意该规则仍是 Agent 必须核对的语义责任。自动整理只提出风险候选；候选、回测结论和风格不会自动成为生效规则。

新增 `memory_trading_context({limit?})`，一次取得全部未被用户撤销的风险规则正文、其他两类摘要及总数。风险跨 scope 返回供调用者核实适用性，避免默认搜索和启动索引漏掉冲突、待复核或较早的红线。正文预算外的 ID 明确返回，`complete:false` 不能当作规则齐全。`documented` 仅表示已登记，不是交易许可。

## 执行原则

- 增加实盘风险前读取完整适用规则；没有规则时引导用户设定损失预算、组合暴露、退出及暂停条件，给出真实数据计算的可比较结果后确认。采用风险偏好不等于接受任意风险。
- 设定或调整时，使用实际权益、合约规格、数量步长、报价、已有仓位和挂单；分别核算计划止损损失、成本、保证金与组合暴露。没有通用的默认风险百分比。预计止损损失不叫保证的最大亏损。
- 用户确认的规则优先于策略和风格。缺数据、规则冲突、后台无法落实必要保护时暂停新增风险并说明恢复条件；不因缺少新规则阻止既有授权内的减仓或平仓。
- 策略保存机制假设、条件、参数含义、证据与反例。结果明确区分用户观点、待验证假设与已验证的局部结论。

## 实现分工和验证

1. 记忆仓库、能力实现和自动整理保护；新测试验证真实确认、版本冲突、候选隔离、分类降级、长期保留、跨范围检索和预算遗漏。
2. 声明、提示词与一份按需读取的交易记忆说明；提供完整调用示例和官方金融计算文档，不要求 Agent 自主探索未知能力。
3. 手动交易 risk/manager 显式授予两个只读记忆能力，缺依赖走现有暂停/恢复；executor 保持只执行冻结决策。
4. 检查源锁和清单，装配宿主测试插件，运行记忆与交易工作流的确定性测试。测试不调用真实账户或付费模型。

保留当前目录中此前的去重改动；不在本次任务自动推送、安装或执行交易。

## 已实现与验证

- memory 3.1.0 提供三类记忆、确认与版本保护、候选隔离、完整交易上下文。上下文按整份格式化 JSON 的 32000 UTF8 字节/1800 行控制；正文超出时明确给出未读 ID，极大量 ID 用 `risk_offset/next_risk_offset` 分页。`memory_read` 保留普通读取，并支持显式 `offset/length` 分段，避免宿主把长红线截成摘要。
- manual-trading 3.2.0 给 risk/manager 精确授予两个只读能力，预检检查后续角色的依赖；缺失或运行中不可用进入原有暂停/恢复路径。executor 仍只执行冻结目标。
- 宿主记忆界面展示三类中文分类；风险规则和候选的启用/修改在对话中核算确认，界面提供查阅与原因说明，不暴露会被后端拒绝的普通编辑入口。公开记忆响应声明包含确认来源。
- 风险归档解除有效冲突，恢复时重新检查；旧引用和版本保留。25 次连续修订不会耗尽来源额度。正文分页和归档冲突均有回归。
