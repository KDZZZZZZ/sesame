# 工作流插件职责拆分

## 目标

研究不依赖交易账户；交易决策不再内嵌另一份研究团队；执行只处理明确目标和真实回执。保留同一套宿主 Agent / Run、暂停恢复、产物与工作过程绑定。

## 边界

| 插件 | 输入 | 产物 | 不承担的工作 |
| --- | --- | --- | --- |
| investment-research | 研究问题、标的/周期、明确选择的信源和方法、固定证据、模型 | 可组合的固定研究成果、成员 Markdown、经理综合与可选图表报告 | 账户绑定、目标仓位、下单、交易调度 |
| trading-decision | 固定研究成果、当前账户、用户风险规则、交易授权/计划 | 目标仓位、条件与理由、执行回执 | 自建行情/新闻/基本面研究团队 |
| portfolio-execution | 明确的目标仓位或订单、账户绑定 | 实际下单/平仓/撤单及观察回执 | 投资观点、研究流程 |
| auto-factor-mining | 可检验假设、固定开发数据、方法、独立 evaluator | 实验与评价证据、候选方法 | 当前账户买卖决策 |
| kurumi-replay | 固定历史输入、模拟账户、决策规则 | 历史模拟账本、过程和复盘 | 实盘执行、通用研究 |

## 统一接口约定

- 新研究入口直接声明为 workflow capability，使用宿主 operationId 去重和原生 Run 控制，不复制 runs/list/wait/cancel/resume/activity 接口。
- `investment_research_analyze` 接收问题、subjects、research:{plugins,tools?}、model、可选固定 evidence_refs 与角色模型。没有 execution/apply/真实账户必填项。
- `investment_research_report` 仅消费固定研究成果，用经理重新组织展示，不启动分析师、不取新数据、不调用交易能力。
- 报告请求使用统一 task.output；有报告的经理使用 `{type:"report",target:"parent"}` 发布到工作流已有绑定。无报告返回内部 Markdown。
- 固定研究成果为 data artifact：问题/时点、成员输出与运行引用、经理结论、证据引用、适用范围/局限；HTML 是展示，不是唯一机器可消费产物。
- 交易计划显式接收研究成果引用；研究不足时明确指出缺口，由主 Agent 先调用研究能力，再启动交易决策。不要静默循环研究或重复同一研究团队。
- 只有研究工作流显式声明多个 Agent 协作关系时显示协作图。单个经理报告任务仍是普通 Agent 过程。

## 实施与验证

1. 先保留已有研究/交易回归，补无账户研究、成员权限、经理精确报告采用与父报告绑定测试。
2. 抽出研究角色/只读能力选择到新研究包；保留宿主 checkpoint/interrupt/resume 与精确数据引用。
3. 将 manual-trading 收缩并改名为 trading-decision，删除只读分析入口、分析分支和旧包；交易保留经理/执行员及现有调度、授权、记忆和回执，不增加兼容别名。
4. 因子挖掘与历史回放仅修正文档/能力描述的职责边界，不重写独有的实验或模拟引擎。
5. 对已有真实研究仅重跑经理报告，使用配置的 OpenAI gpt-6.1-sol；经过 Sesame 内部渲染并输出真实截图。原始研究和两份原稿保留。
6. 验证声明、插件装载、针对性测试、语法/lint、锁文件。此轮不安装本机正式应用、不发布。
