# Sesame 报告模块与组合分析模板设计

2026-10-27 · 设计与实现记录 · `sesame/reports` 3.5.0 · 当前 `feat/local-20261026` 源码。

报告模板提供**可调整的结果字段建议**：定义字段的含义、类型、单位、适用条件及组合关系。建议建立 **16 个独立模块、8 种组合模板**，帮助 Sesame 在需求不明确或任务相近时组织报告。用户可以增删字段、调整章节、重组模块、改变呈现形式或完全自定义结构。同一份研究结果可以用于完整模块、组合摘要卡或用户指定的其他形式。

**用户意愿优先于模板默认值。** Report 层负责结果契约和呈现映射；具体理论、数据要求、分析步骤、特征定义、历史匹配、统计估计、预测合成和校准由独立的方法能力负责。用户指定的方法通过方法引用接入，报告字段不绑定某一种理论或算法。

TC 提供模块划分的参考，以下目录是 Sesame 的设计建议，不是 TC 官方产品或接口清单。行情预测保留特征历史证据与置信度的结果接口；这些字段的计算与有效性评价由研究方法提供。本文不表示当前插件已经具备全部方法和数据来源。

## 一 用户需求与模板选择

模板是建议起点。选择优先级为：**用户当前明确要求 → 当前任务已确认的约定 → 适用的用户偏好 → 模板建议**。执行中收到调整时，更新本次有效结构并复用仍适用的结果；无需为了遵守默认模板再次要求用户确认。

- 用户可以增删、改名或重排字段，合并或拆分模块，调整报告长度、语言、图表及显示密度，也可以不用现成模板。
- 用户可以指定理论、分析方法、参数、数据范围和预测期限。编排层选择相应知识与方法能力，report 接收其结果；模板不能覆盖这些选择。
- 模板中的字段、组合、章节和图表均为建议。标注的适用条件说明字段含义，不要求每份报告全部填满。
- 用户调整先作用于本次报告；只有用户要求保存为偏好或模板时，才修改可复用默认值。
- 所选方法或数据无法满足要求时，说明具体缺口并完成可完成部分，不静默替换用户指定的方法。真实来源、数值含义和验证状态须如实表达；字段可以不展示，未完成的研究不能标成已验证。

以下是没有更明确要求时的候选路由，由主 Agent 结合上下文选择，不是固定执行流程：

| 用户表达 | 建议起点 | 任务上下文 |
| --- | --- | --- |
| “看看这个品种”“分析一下” | R01 资产概览，先说明当前状态和重要变化 | 使用用户已明确选择的标的；没有可确定对象时只询问市场或标的 |
| “接下来怎么走”“下周走势”“综合预测” | R02 综合行情预测 | 明确预测期限、结果定义和数据截点，再组织历史验证 |
| “突破有效吗”“RSI 超卖以后呢” | M02 技术事件与情景；涉及历史效果可引用 M13，综合预测可引用 M14 | 用户指定的规则与方法、确认时刻、观察窗口 |
| “这条消息有什么影响”“非农后黄金怎么看” | R03 事件冲击研究；新闻可先由 M07 定义事件 | 区分已公布和未公布；未公布事件按结果分支研究 |
| “值不值得长期关注”“财报或估值怎么看” | R04 公司价值与中长期展望 | 估值问题可止于估值；预测价格需另外验证 |
| “今天市场重点”“有什么候选机会” | R05 市场日报与机会扫描 | 市场范围与去重后的新增变化；候选不自动成为交易建议 |
| “期权怎么做”“检查持仓”“复盘上次判断” | 分别使用 R06、R07、R08 | 使用对应合约、持仓或原始预测；没有真实账户信息时不生成账户结论 |

预测期限由用户、任务上下文或适用偏好决定；需要默认值时由编排层明示采用的约定，模板不固定 1、5、20 日等窗口。用户说“下周”时按相应市场的下周交易时段解释，具体日历计算由相关能力完成。

需求不明时可先完成状态概览，不默认读取持仓、不启动交易、不强行给概率。普通问题可用模块的简版回答；用户要求报告或任务本身是实质研究时，交付完整报告。

## 二 所有独立模块共用的建议字段

| 字段组 | 可呈现的内容 | 可引用的研究结果 |
| --- | --- | --- |
| 研究对象 | 标的、问题、数据截点、研究期限 | 市场与合约、时区、交易日历、价格口径、来源版本 |
| 一句话判断 | 直接回答这个模块的问题 | 区分事实、解释、预测和条件行动；注明预测所指结果 |
| 关键事实 | 与问题相关的数字、文字或图表，数量随用户需要调整 | 当前值、比较基准、首次可得时间、固定输入引用 |
| 特征解释 | 什么变化值得关注，所选方法如何解释 | 方法产生的特征定义、理论引用、机制假设、替代解释、适用条件 |
| 历史验证 | 同类情况后来怎样，较基准有无变化 | 引用 M13；若不提出预测，可不增加这一段 |
| 预测或条件情景 | 方法提供的判断、概率、范围或待验证假设，附相应状态 | 引用预测结果及其依据；不能用空值冒充中性 |
| 更新条件与来源 | 哪个变化会改变判断；来源可展开 | 触发条件、失效条件、复核时点、模型与结果版本 |

完整模块和组合摘要卡是两种建议显示密度，用户可以另行定义。字段是否采用、显示顺序和详细程度由本次有效结构决定。资产、数据截点、共同历史样本和方法可复用同一引用，避免重复正文。

字段定义建议包含 `key`、含义、值类型、单位、适用条件、缺失状态和来源绑定。方法特有内容通过扩展字段表达；例如用户选择某种价格行为理论，技术模板可以接收其事件与关键位，不要求补算默认均线或 RSI。字段叫“关键位”不代表 report 负责计算关键位。

模块完整度按**本次采用的字段与任务目标**评价，用户主动删去的默认字段不算缺失。完成、部分完成、不可用、不适用描述任务结果；方法提供的验证状态描述证据程度，二者分别保存。纯新闻报告可以完整而不包含价格概率。

## 三 十二个业务模块

以下字段均为候选字段，字段值由独立研究方法或已有成果提供。每个模块可保留 `method_refs`、`theory_refs`、`evidence_refs` 和 `extensions`，用来追溯方法、理论、证据及方法特有结果。Report 不把字段建议转成必做指标清单。

### M01 行情状态与相对强弱

- **用途与参考**：回答现在处于什么行情、相对谁强弱；参考 TC Technical Views 的多期限观察和 Panoramic View 的技术维度。
- **建议字段**：市场状态、观察期限、价格表现、趋势描述、波动描述、比较基准、相对强弱、重要变化、证据引用。
- **字段语义**：状态标签、状态判定依据和价格预测分别保存；方法可提供定性描述或定量结果，不强制使用均线或动量指标。
- **可选呈现**：状态摘要、价格图、相对强弱曲线、期限矩阵；用户可重排或只保留文字。

### M02 技术事件与价格情景

- **用途与参考**：研究突破、形态、支撑阻力和技术指标触发；参考 Technical Insight、Technical Views、Alpha Generation 的任务分工。
- **建议字段**：技术事件、形成或确认状态、确认时点、关键价格区域、主情景、替代情景、触发条件、失效条件、有效期、依据与历史证据引用。
- **字段语义**：事件、区域和情景的识别规则来自所选方法；模板可接收指标分析或用户指定理论的结果，没有必须计算的 RSI、形态或目标价。
- **可选呈现**：价格标注、条件表、情景树、历史结果摘要。

### M03 基本面与财务质量

- **用途与参考**：判断盈利、现金流、杠杆和经营质量；参考 Fundamental Insight 的多维分析。
- **建议字段**：财务期间与口径、经营判断、增长、盈利质量、现金流、资产负债、同业比较、变化来源、资料发布时间、来源引用。
- **字段语义**：指标集合、质量评价和可比公司选择由方法提供；经营质量评分和价格预测使用不同字段。
- **可选呈现**：经营摘要、财务趋势、同业对照、变化解释。

### M04 估值与价格假设

- **用途与参考**：回答价格隐含了什么、估值是否有吸引力；参考 Fair Value 与模型目标的分离。
- **建议字段**：估值方法引用、适用范围、关键假设、估值结果或区间、市场价格、差异、敏感性、隐含假设、局限和证据引用。
- **字段语义**：用户可指定估值理论和模型，其特有参数放扩展字段；估值区间、价格预测区间和上涨概率分别标识。
- **可选呈现**：估值对照、假设表、区间图、敏感性矩阵。

### M05 共识与预期修正

- **用途与参考**：研究市场预期是否变化及分歧程度；参考 Analyst Consensus。
- **建议字段**：预期对象、观察期限、覆盖机构、共识值、分歧、修正方向与幅度、修正时间、覆盖变化、与实际结果的差异、历史证据引用。
- **字段语义**：聚合与分歧指标由方法定义；机构目标价、评级和预测概率保留各自含义。
- **可选呈现**：共识摘要、修正时间线、预期分布、机构对照。

### M06 宏观与公司事件冲击

- **用途与参考**：分析经济数据、议息、财报、分红等事件；参考 Economic Insight 和两类日历。TC Economic Insight 按实际值相对预期分组查看事件后的方向及波动，适合借鉴为历史条件统计入口。[官方教程](https://investor.tradingcentral.com/tutorials/getting-started-with-economic-insight)
- **建议字段**：事件身份与类型、发布时间、公布状态、事前预期、实际值或假设分支、预期差、并发事件、观察窗口、已发生反应、条件预测、历史证据、更新条件。
- **字段语义**：未公布的实际值标为尚不可用；分组规则、冲击定义和事件研究方法由所选能力提供。条件预测与无条件预测分别标识。
- **可选呈现**：事件卡、预期对照、历史反应表、事件前后情景。

### M07 新闻主题与关注变化

- **用途与参考**：解释发生了什么、新在哪里、关注是否异常；参考 Market Buzz。
- **建议字段**：新闻事实、相关实体、主题、首发时间、来源、事件簇、新颖性、关注变化、语料覆盖、影响解释、已发生价格反应、历史证据引用。
- **字段语义**：主题分类、相似新闻匹配与关注度算法来自方法层；关注指标同时保留覆盖范围与比较口径。
- **可选呈现**：新闻摘要、事件时间线、主题变化、来源入口。

### M08 情绪与拥挤状态

- **用途与参考**：区分乐观悲观、情绪变化和交易拥挤；参考 Crowd Insight、Sentiment Monitor 与 Fear 类维度。
- **建议字段**：情绪来源与覆盖、情绪水平、变化、分歧、参与者类别、拥挤状态、与价格或持仓的关系、解释、历史证据引用。
- **字段语义**：文本情绪、实际仓位和衍生指标分开标注；供应商 Confidence、情绪分数和行情预测置信度分别保存其定义。
- **可选呈现**：情绪摘要、历史对照、参与者分歧、价格与情绪关系。

### M09 波动与期权定价

- **用途与参考**：研究市场定价了多大波动以及哪类尾部风险；参考 Options Insight 的波动维度。
- **建议字段**：标的与报价时点、期限、隐含波动、实际波动、期限结构、偏斜、历史位置、事件溢价、尾部描述、定价假设、预测与证据引用。
- **字段语义**：定价、波动估计和预测方法由用户或方法层选定；概率若出现，带有风险中性或实际发生概率等语义标识。
- **可选呈现**：波动摘要、期限曲线、偏斜图、历史分布。

### M10 期权结构与损益

- **用途与参考**：比较不同表达方向、波动或风险观点的结构；参考 Options Insight 的策略部分。
- **建议字段**：结构目标、合约及各腿、报价与成本、期限、盈亏平衡、情景损益、到期前风险、替代方案、分布或预测引用、验证状态。
- **字段语义**：确定性损益情景与盈利概率使用不同字段；定价、路径模拟和策略评价由方法层完成。
- **可选呈现**：合约表、损益曲线、情景矩阵、结构比较。

### M11 条件筛选与机会候选

- **用途与参考**：在明确市场范围内发现符合条件的资产；参考 Strategy Builder、Featured Ideas，并为组合构建提供候选。
- **建议字段**：筛选目标、市场范围、数据截点、条件引用、匹配数量、候选、排序及其含义、入选依据、覆盖缺口、验证引用、后续研究入口。
- **字段语义**：筛选、排序和历史评价由指定方法提供；排序分与预测概率分别保存。结果可按用户要求重排，但不改写原方法的分数。
- **可选呈现**：候选表、证据摘要、分类列表。

### M12 风险与组合暴露

- **用途与参考**：量化走势判断若出错会付出什么，以及多头寸是否押注同一风险；参考 Stop & Risk，自行扩展组合暴露。
- **建议字段**：真实或假设组合标识、持仓与口径、风险目标、资产与因子暴露、集中度、相关关系、流动性、压力情景、潜在损失、风险预算、选择与依据。
- **字段语义**：风险度量、压力构造和规模建议由所选方法提供；用户预算属于决策条件，与市场预测证据分开保存。
- **可选呈现**：暴露摘要、风险表、相关矩阵、压力损益对照。

## 四 四个共享研究结果模块

M13 至 M16 都是结果模板，可以独立展示、嵌入其他模块或只保留结果引用。它们的编号不代表 reports 内置了历史检验、预测算法或复盘引擎，也不强制报告出现四个独立章节。

### M13 历史同类特征验证

用于回答“过去出现这个特征之后发生了什么”，承接独立历史研究方法的结果。

**建议字段**：特征及版本、当前值、预测假设、目标与期限、方法引用、历史范围、信息可得性说明、匹配及排除条件、原始样本数、独立事件或簇数、基准、结果计数、条件频率、结果分布、差异、估计区间、验证划分、稳定性、当前适用性、验证状态、证据引用。

**字段语义**：匹配规则、去重方式、区间估计、样本划分和资格判断均由方法结果携带；模板不选择算法或设置最低样本阈值。方法未提供的字段标注其原因，不自动推算。案例列表与统计样本分别表达。

**可选呈现**：验证卡、条件与基准对照、分期限结果表、样本清单。用户可以把历史证据并入技术或新闻模块，也可以隐藏明细并保留引用。

### M14 多特征综合预测

承接用户所选综合方法的行情预测。方法可以输出定量概率、结果分布、条件判断或明确标识的定性假设，report 按其真实语义呈现。

**建议字段**：预测对象、数据截点、目标、期限、综合判断、方法与理论引用、参与特征及历史证据引用、支持与反对证据、重复信息与冲突的处理说明、预测概率或范围、基准、置信度、验证状态、当前适用性、条件分支、失效条件、预测登记引用。

**字段语义**：综合算法、权重、模型及校准结果由外部方法提供，相关参数仅在方法适用时保留。不同目标、期限、截点的结果分别标识；方法特有的贡献或评分保留其定义。Report 不按模块数量算票，也不从文字措辞生成概率。

**可选呈现**：分期限结论、概率表、情景表、预测范围、证据矩阵。用户可选择只展示结论和依据，方法与验证引用仍可用于追溯。

### M15 条件行动与监测计划

**用途**：把研究变成可观察的下一步。它可以单独存在，也可以作为各组合报告的最后一节。

**建议字段**：用户目标、研究结论引用、主情景、替代情景、触发条件、失效条件、风险或成本约束、观察项目、建议行动、复核时点、实际执行状态。

**字段语义**：条件与行动建议来自研究方法和用户约定；建议、已安排任务、已执行行动使用不同状态。报告发布本身不触发监测或下单。

**可选呈现**：条件树、情景表、清单或时间线，按用户选择调整。

### M16 预测复盘与校准

**建议字段**：原预测与版本、原目标及期限、结算状态、实际结果、方向或幅度或路径评价、对照基准、评价指标及定义、校准结果、适用分组、偏差解释、后续处理、证据引用。

**字段语义**：结算规则、评价指标、校准与归因方法由复盘能力提供；未成熟、无法结算与已结算分别记录。预测质量、策略收益和执行结果分别表达。

**可选呈现**：预测与实际对照、分组表现、校准结果、偏差摘要；不要求采用固定评分函数。

## 五 八种组合模板

组合模板建议模块集合与呈现顺序，最终结构由用户意愿和任务需要确定。所有组合都允许增删、替换、拆分、合并和重排；表中列出的模块不是验收必选项。组合引用已有研究结果，不因换版式重新计算；同一证据可供多处引用。

| 模板 | 建议组合及扩展 | 建议报告结构 |
| --- | --- | --- |
| **R01 资产概览** | M01，适配的 M06、M07；股票可加 M03 摘要，其他维度按问题加入 | 当前发生什么 → 哪些变化最重要 → 各维度状态 → 接下来观察什么。默认不强制预测；用户要求未来方向时转 R02 |
| **R02 综合行情预测** | M01、M02、适配的 M06、M07，加 M13、M14、M15；M08、M09、M12 按相关性加入；股票较长期问题可加 M03 至 M05 | 最终分期限预测 → 价格状态 → 关键驱动 → 特征历史证据 → 多空分歧与联合预测 → 波动和尾部风险 → 情景及更新条件 |
| **R03 事件冲击研究** | M06、M01、M13、M14、M15；新闻事件加 M07，波动和风险问题加 M09、M12 | 事件与事前预期 → 可能或实际结果 → 同类事件反应 → 方向与波动分开预测 → 条件情景 → 发布后如何更新 |
| **R04 公司价值与中长期展望** | M03、M04、M05，相关的 M06、M07，M01 定位价格；提出价格预测时加 M13、M14，最后 M15 | 核心投资论点 → 经营与盈利 → 估值假设 → 共识及催化 → 市场价格预测及其独立证据 → 反论点与更新条件 |
| **R05 市场日报与机会扫描** | 多资产 M01、M06、M07，加 M11；情绪可加 M08；预测卡引用已有合格的 M13、M14 | 相比上一版的新变化 → 市场与板块 → 重要驱动 → 事件日程 → 去重机会卡 → 需要跟踪的变化。简报只汇集底层结果 |
| **R06 期权波动与策略结构** | M09、M10、M06、M12、M15；提出盈利或价格概率时加相应 M13、M14 | 波动判断 → 事件与市场定价 → 首选及替代结构 → 成本和损益 → 经验证的概率或明确情景 → 到期前风险 |
| **R07 持仓与组合诊断** | M12、持仓对应 M01、M15；按暴露添加 M03 至 M09，预测部分引用 M13、M14 | 当前组合 → 收益及风险来源 → 共因子和集中度 → 压力情景 → 条件调整选择。组合不能假设资产预测独立 |
| **R08 预测复盘** | M16，引用原 M13、M14、M15；涉及真实交易另加 M12 和执行证据 | 当时怎样判断 → 后来发生什么 → 哪些预测正确或错误 → 概率是否可靠 → 哪些条件下失效 → 后续验证与版本更新 |

R02 可作为综合行情分析的起点。用户仅需要技术分析时可以只保留相关字段，要求其他结构时直接覆盖默认组合。宏观事件前、事件后可使用 R03 的不同视图；尚未发布的实际值保持其真实状态。R04 可形成纯估值报告。R05 的日报、周报和视频稿是同一研究组合的不同交付形式。

概览参考 TC Panoramic View 并列技术、基本面、新闻情绪的方式；综合预测由独立方法生成，M14 承接其结果。并列摘要与综合预测分别标识。[Panoramic View 官方说明](https://www.tradingcentral.com/blog/trading-central-releases-summary-scores-in-panoramic-view)

## 六 预测与置信度的字段语义

本节定义结果如何表达。预测目标、特征规则、历史匹配、估计方法、评价指标和通过标准由用户约定及独立研究方法决定，report 不在模板里选择算法或设置数值门槛。

### 预测目标字段

建议记录 `target_ref`、标的、数据截点、预测起点与截止、结果定义、观察口径、适用的触发条件、方法版本。以下是可扩展的目标类型示例，不要求采用固定的三分类或同时输出全部类型：

| 目标类型示例 | 结果字段 | 语义说明 |
| --- | --- | --- |
| 方向或类别 | 类别定义、分类阈值或规则引用、各类别结果或概率 | 类别由任务和方法定义；只有互斥且完备的类别概率才按总和为 1 检查 |
| 路径事件 | 事件定义、价格屏障或条件、观察窗口、触发与先后结果、歧义状态 | 到期上涨、曾到目标、先到目标分别对应不同目标 |
| 幅度或风险 | 变量定义、单位、点估计或分布、分位及区间语义 | 收益、实现波动、最大不利波动等分别标识；不从波动结论自动推导方向 |

用户修改目标或期限时，编排层检查旧研究是否仍适用；需要重新研究时调用相关方法。Report 不能把原期限结果换一个标题后当作新预测。

### 置信度字段组

“置信度”保留为可解释的结果字段组，具体定义与估计由方法提供。字段可按用户要求合并、简写或不显示；保留在研究成果中的状态不能被显示设置改写。

| 字段 | 含义与配套信息 | 提供方 |
| --- | --- | --- |
| `prediction_estimate` | 预测值、单位、目标引用、估计类型；只有定义为发生概率的值才标为概率 | 预测方法 |
| `historical_frequency` | 历史结果计数、样本数、时间范围、条件及基准引用；历史频率单独标识 | 历史研究方法 |
| `uncertainty` | 区间或其他不确定性描述、覆盖水平、估计方法引用、缺失原因 | 估计或评价方法 |
| `validation` | 未验证、历史探索、时序样本外验证、前瞻持续验证等状态，以及验证记录和依据 | 研究评价能力 |
| `calibration` | 适用性、评价指标与定义、评价区间、样本范围、方法与结果引用；不适用时明确标识 | 校准或评价能力 |
| `applicability` | 已覆盖环境、当前匹配情况、已知限制及判断依据 | 所选方法或评价能力 |
| `qualitative_assessment` | 定性判断或评分、量表定义、方法依据；与统计概率区分 | 用户指定的定性研究方法 |

概率估计区间与未来价格预测范围使用不同的字段语义。方法没有计算某项结果时，记录未提供、不适用或无法估计等状态，不以 50%、零值或“高置信度”代填。模板不要求所有方法都输出模型参数、校准曲线或统一的 0 至 100 分。

校准涉及预测概率与实际频率的对应关系，具体评价由方法层实现；report 保存并展示其结果和定义。[概率校准说明](https://scikit-learn.org/stable/modules/calibration.html)

### 历史证据的引用关系

保留本项目的研究目标：用于行情预测的每个特征，都应能追溯到历史中同类特征出现后的统计与分析。建议的关联结构为：

`feature_ref → target_ref + history_result_ref + validation_status`

这个关联不要求正文出现一张固定验证卡，也不指定“相同或相似”如何度量。特征定义、样本选择、点时数据、基准、样本依赖、区间、样本外评价、稳定性和质量标准由研究方法负责，M13 保存其结果或引用。某项尚未完成时保留缺口状态，不能通过换模板升级验证结论。

历史分析不等于每个特征都必须通过同一个显著性门槛；条件变量、交互信息或描述背景由综合方法说明其角色。Report 不替方法筛选特征。用户只要求展示结论时可隐藏历史明细；用户选择仅作假设推演时标明研究性质，不称为已通过历史验证的预测。

相同条件下可以引用已有历史成果；是否适合复用、是否需要更新由研究与编排层判断。Report 只检查引用绑定和所声明的时点、目标等是否一致。

## 七 方法选择与报告字段的连接

### 字段契约与方法契约分别维护

| 契约 | 约定内容 | 不同任务如何调整 |
| --- | --- | --- |
| 报告字段契约 | 字段含义、类型、单位、适用条件、结果引用及显示关系 | 用户可调整字段和结构，形成本次有效契约 |
| 知识与方法契约 | 理论依据、所需数据、步骤、参数、适用范围、可产出结果、验证与评价方式 | 优先使用用户指定的方法及其版本；未指定时由编排按任务选择 |
| 研究结果 | 方法实际得到的事实、解释、特征、历史分析、预测与状态 | 固定结果引用可供多个模板复用；需要改变研究问题时重新研究 |

一个字段可以由不同方法提供，一个方法也可以填充多个模块。方法引用建议携带 `method_ref`、`method_version`、`theory_refs`、参数引用和结果引用；纯定性方法没有数值模型时，不虚构 `model_version` 或 `calibration_version`。

Report 不在模板中指定首选联合模型、历史相似度算法、区间估计方法、校准算法、预测窗口或样本量门槛。这些选择属于独立方法的配置与知识资料。不同方法比较使用同一组报告字段时，分别保留方法身份，避免在一张卡片中混合来源。

### 主 Agent 的连接流程

1. 读取用户目标和调整要求，选择、改写或自定义结果字段，形成当前报告的有效结构。
2. 读取用户指定的理论与方法；未指定时根据任务选择适用方法。详细知识和方法说明按需加载。
3. 由方法声明实际数据需求与可提供结果，组织研究或复用已有成果；报告字段不代替方法的输入契约。
4. 将方法结果映射到字段；方法特有信息加入扩展字段。无法填充的内容说明状态，按用户需要省略或保留。
5. 在有效结构上检查字段类型、引用、单位、目标与时点，生成报告。科学有效性和预测资格沿用研究评价结果。
6. 用户随后调整显示时复用研究；调整方法、目标或期限时由编排识别需要重新计算的部分。

### 从特征到综合结论

独立方法负责将技术、事件、新闻、财务等结果组织为特征，为参与预测的特征提供历史分析，并按所选综合方法产生最终判断及置信度。综合结果可包含支持与反对证据、信息重叠、缺失处理和解释引用，M14 负责承接这些字段。

模板不绑定逻辑回归、加权集成或其他合成方式。若用户指定的方法使用权重或评分，其含义、计算与验证记录由该方法提供。Report 不自行平均多个模块的分数、相乘历史频率或根据语言强弱补填概率；它只呈现方法实际交付的结果。

方法只提供定性结论时可以交付定性报告；提供历史统计时按历史统计标识；提供经验证的概率时附相应验证引用。支持这些结果的同一套字段，不要求所有报告最终变成数值预测。

## 八 三种使用示例

以下是模板结构示例。花括号表示需要由真实研究填充的内容，不包含真实行情或模拟的通过结果。

### 示例一 黄金下周综合行情预测

用户问题：“综合分析一下黄金下周走势。”没有额外要求时，可以从 R02 起步。标的、报价和时间范围由任务上下文确定；分析方法由用户指定或由编排层按任务选择。

| 正文位置 | 内容结构 | 对应模块 |
| --- | --- | --- |
| 首屏 | `{该期限的主判断}`；`{方法提供的定量或定性结果}`；`{置信度的含义与依据}`；`{验证状态}` | M14 |
| 价格状态 | 当前趋势、关键位置、近期波动及不同期限的差异 | M01、M02 |
| 驱动与事件 | 已知事件日程、真实预期差、去重新闻；分别说明已发生和仍未发生的内容 | M06、M07 |
| 特征证据 | 每个进入模型的特征：定义、历史匹配条件、样本、基准、结果分布、使用资格 | M13 |
| 综合判断 | 支持及反对证据、方法对重复信息的处理、综合判断及其解释 | M14 |
| 风险与情景 | 波动和尾部变化、主备情景、触发和失效条件；不默认替用户设置持仓 | M12、M15 |
| 展开证据 | 样本清单、输入与计算引用、模型版本、校准图、预测登记 | 各模块共用 |

具体特征由所选方法生成，历史分析与综合结论也由相应能力提供。Report 将结果映射到这些字段，不强制研究某个技术指标、经济数据或新闻类别。某项证据不足时沿用方法提供的状态；只有分项历史频率时按分项结果展示，不在报告装配时补算总体概率。

### 示例二 某次经济数据发布前后的影响

用户问题：“这次数据对某外汇品种会有什么影响？”可以从 R03 起步。

**公布前的建议字段**：发布时间、事前共识、条件分支、分支历史结果、当前背景、方法提供的条件判断、更新条件。分组规则、观察窗口和概率是否可估计由研究方法决定，模板不固定三个分支或具体分钟数。

**公布后的建议字段**：首发实际值、预期差、已发生反应、新的数据截点、剩余预测窗口、后续判断和更新条件。预测结果绑定其真实截点，已发生的价格变化另列为事实。

用户可以仅保留事件摘要和影响判断，也可以要求展开历史样本；两种呈现引用同一份研究成果。

### 示例三 用户调整结构并指定方法

用户要求：“只保留关键位置、两个情景和依据，使用我指定的价格行为方法，不要均线、新闻和概率图。”

- 本次结构采用关键位置、两个情景和依据；不加入用户排除的均线、新闻和概率图，不因这些内容未出现而判为不完整。
- 编排层加载用户指定方法及相关理论，以其输出填充关键位、触发与失效条件；不额外使用默认技术算法补齐模板。
- 如果方法给出了历史分析或概率结果，可保留其引用供追溯，按用户要求调整显示；没有计算的结果不补造。未验证的情景按假设表达。
- 用户随后新增“每个情景的历史表现”时，增加对应字段，复用或调用适用的历史研究方法。此次调整不自动改写公共模板或长期偏好。

### 沿用已有报告底座

当前 `report_template` 是单主图研究骨架，`kind` 表示图型；`report_document_template` 接收已经写好的正文 HTML；`report_backtest_template` 提供回测专用结构。现有 `reportKit.render` 已支持 `title / verdict / metrics / sections / method`。本设计在其上增加业务模板与结果映射，不把业务类型塞进现有图型枚举。

### 各层分别负责什么

| 层 | 职责 | reports 需要拿到的结果 |
| --- | --- | --- |
| 数据与证据 | 真实来源、点时版本、事件去重、固定输入 | 统一时间和来源语义的 DataRef 或 ArtifactRef |
| 知识与方法及评估能力 | 理论说明、输入需求、特征计算、历史研究、综合分析及适用的训练、验证和校准 | 方法、理论、参数和结果引用；M13、M14 只是结果的报告映射 |
| 编排 | 优先执行用户要求，选择或调整模板、选择方法、组织研究和复用成果 | 本次有效字段结构、实际结果和未完成原因 |
| reports | 建议字段定义、组合参考、用户覆盖后的字段映射、结构校验、呈现与发布 | 一份按用户要求组织、能追溯研究证据的报告 |
| 判断与复盘 | 事前冻结、到期结果、版本与校准追踪 | M16 使用的真实历史预测及实际结果 |

现有 `factor-evaluator` 与 `judgment-evolution` 可以复用部分评估、登记和校准能力，但不据此认定联合价格预测、点时事件库、路径先后核验已经齐备。尤其不能用到期的单一价格标量回答“先到目标还是先到止损”；路径结果应由具备相应输入的研究或回测方法生成，再交给报告与复盘使用。参见[当前能力核对](../local-archive/2026-10-26/outputs/Sesame-研究字段能力核对-20261026.md)。

### 模板资料如何进入上下文

保持现有 prompt、skill、reference 的分工：

- `prompt.md` 只补用户要求优先、模板可调整、字段与方法分离及真实结果绑定原则。
- `report-writing/SKILL.md` 增加简短的模块与组合索引、用户调整如何形成有效结构、缺失结果如何表达。
- 按需参考保存 16 个模块的建议字段、8 个组合建议、置信度与历史证据字段语义和示例。不要把全部正文追加进默认系统提示词，也不为每个模块增加默认注入的独立 skill。
- 具体理论、算法、数据需求、验证方案及参数保存在相应方法或知识能力中，通过引用按需加载，不放进 reports 模板的执行要求。
- `report-design` 继续维护布局和图表映射；`interactive-report` 继续负责固定输入、发布、修复及导出。

建议的默认指引可以写成：

> 报告模板提供字段和组合建议。优先按用户要求增删、重排或自定义结构，用户主动删去的默认字段不算缺失。Report 规定结果如何表达，具体理论、分析与评价方法由用户指定或由编排按任务选择，通过方法结果引用填充字段。历史证据、预测与置信度沿用研究结果及其真实验证状态；可按用户要求调整显示，不补造数值。详细字段按需读取，复用已有研究成果。

### 模板定义与研究结果分开保存

下表描述设计对象和字段范围；已实现工具的准确入参见第十一节及字段模板指南。

| 对象 | 建议字段范围 |
| --- | --- |
| 模块定义 | `module_id`、版本、用途、适用场景、`suggested_fields`、字段语义与类型、适用条件、可选呈现、参考入口 |
| 组合定义 | `template_id`、版本、用户意图、建议模块、建议顺序、共享字段与结果引用、可选呈现 |
| 本次有效结构 | 原模板及版本或自定义标识、用户要求、字段增删与覆盖、`active_fields`、本次明确要求的字段、模块与顺序、显示设置、未满足要求及原因 |
| 方法绑定 | 用户指定或编排选择的来源、`method_refs`、`theory_refs`、方法版本与参数引用、方法结果到字段的映射 |
| 模块结果 | 问题、资产、数据截点、固定输入与方法引用、事实、发现、特征、相对本次要求的完整度状态、历史或预测引用、扩展字段 |
| 预测目标 | 标的、起点、截止、结果定义、阈值或价格屏障、价格和成本口径、交易日历、触发与路径歧义规则 |
| 历史证据 | 特征及目标引用、方法与结果引用、适用的样本和基准信息、计数或分布、区间与评价结果、验证状态及缺口 |
| 综合预测 | 目标引用、特征及证据引用、综合方法引用、定量或定性结果、置信度及定义、适用性、适用的模型或校准版本、登记引用、解释 |
| 呈现方案 | 章节与业务结果的绑定、完整或摘要密度、引用去重、统一主题及图表绑定 |

这些是设计对象的字段范围，具体采用哪些由本次任务及结果类型决定，不是全部必填的统一大表。公共模板没有用户不可覆盖的业务章节；本次明确要求的字段只在本次有效结构中检查。方法不适用、未提供、研究失败和用户未采用的字段分别处理。

相同研究结果可以用于资产概览、日报和综合报告。用户修改展示不改写源结果；修改研究方法或目标时由编排产生新的结果及绑定。Report 校验类型、引用和语义一致性，研究评价能力负责科学有效性，`report_check` 负责渲染质量。

### 两步落地

**第一步先落建议字段与覆盖规则**：增加轻量索引、模块字段、组合建议、方法绑定和用户修改示例，在现有统一骨架内编写报告。实现可从 R01、R02 的技术子组合和 R08 起步，再按实际需求扩充；这只是开发顺序建议。能力未覆盖的字段如实说明，模板存在不等于预测方法已上线。

**第二步再补结构化装配与校验**：由装配入口合并模板建议与用户覆盖，得到本次有效结构，再绑定研究结果并映射现有 outline；新入口及 schema 在实现时一并声明。只检查实际采用字段的类型、引用、时点、目标、单位及适用的数值约束，不按原模板强制补回用户删除的模块。`report_check` 仍负责渲染检查。旧报告、原生回测和现有发布导出链路继续可用。

无需先制作 16 套不同 HTML 主题、16 个执行工具或一套新的证据仓库。业务结构在模块定义里，视觉继续复用统一主题和现成组件。

## 十 模板验收场景

| 输入或边界情况 | 应有行为 |
| --- | --- |
| “分析一下黄金”，未要求预测 | 可从 R01 起步，根据任务调整字段；不强塞公司财务或期权章节 |
| 用户删掉模板里的新闻与风险章节 | 按要求移除，按剩余任务目标检查完整度，不自动补回 |
| 用户新增自定义字段、合并模块或调整顺序 | 更新本次有效结构，通过扩展字段或映射接入结果 |
| 用户完全不用现成模板 | 根据用户给定结构组织报告，仍使用相同的研究结果引用机制 |
| 用户指定理论或方法，与默认推荐不同 | 使用用户指定方法；模板不要求补算其他指标 |
| 用户指定的方法不可用或缺少数据 | 说明具体缺口，完成可完成部分；不静默改用另一方法 |
| 用户在执行中改变字段，但研究问题不变 | 更新显示与字段映射，复用已有结果 |
| 用户改变预测期限或分析方法 | 编排层检查可复用范围，需要时重新研究；旧结果不改名冒充新结果 |
| 用户隐藏历史明细或置信度图表 | 按要求调整显示，保留源结果的真实验证状态；不因此丢弃研究引用 |
| 所选方法仅提供定性判断 | 可以完成定性报告；不为了填模板生成数值概率或模型版本 |
| 只有几个相似历史案例 | 按案例结果呈现，不标成完整统计或校准概率 |
| 多项指标同向或多个新闻报道同一事件 | 采用综合方法提供的分析；报告装配不自行计票或合成概率 |
| 方法报告某特征缺失、超出覆盖或尚未验证 | 沿用其状态与解释，按本次要求展示已有结果，不替方法判定通过 |
| 用户仅修改本次报告 | 不自动修改公共模板或长期偏好；明确要求保存时再持久化 |
| 报告渲染通过但历史验证未完成 | 渲染状态与研究验证状态分别呈现，不互相升级 |

已在 reports 3.4.0 实现建议字段目录、用户覆盖、方法结果绑定及固定数据报告装配。具体实现范围与验证结果见下节。

## 十一 已实现的接口与边界

- `report_structure`：空输入读取 16 个模块、8 种组合目录；指定模板或自定义章节得到本次字段结构。显式 `sections` 和 `fields` 完整替换建议数组，顺序保留；字段可改名、改类型、增删、折叠或隐藏。默认没有必填业务字段或研究方法。
- `report_compose`：读取已有固定 json-rows DataRef，将所选方法结果映射到字段并生成统一 HTML，返回完整发布参数。支持原始精确字符串、结构化列表、概率与区间语义、缺失状态、方法和理论引用，以及用户明确要求的上下文匹配。
- `report_publish`：装配报告发布时核对其原始数据与证据绑定，演示来源保持 demo。原有工具的入参契约保持不变。
- 独立方法仍负责特征识别、同类历史统计、模型、预测合成与校准。Report 对数值范围、类型和引用的校验不代表科学有效性；结果明确分别记录字段完整度、研究验证状态和渲染状态。

实现说明和准确入参见[字段模板指南](../../plugins/api-v1/packages/reports/skills/report-writing/module-templates.md)。可复用演示数据见[模板输入示例](../../plugins/api-v1/packages/reports/examples/module-report-input.json)，全部明确为虚构数据。

报告相关测试共 49 项全部通过，覆盖字段修改、非法输入、既有图表与回测、实际宿主加载与固定发布、1000px/390px 渲染和明暗主题；另人工核对折叠来源、桌面及窄屏截图。真实模型 `gpt-6.1-sol` 实测按用户指定字段和方法生成、发布并检查报告：首次调用漏填自定义字段含义，收到字段错误后补齐，最终只保留用户指定的三个字段。该模型案例只验证一次装配行为，不评价金融方法或长期模型可靠性。全仓库 portable 回归在加载匹配 SDK 后为 176 通过、58 跳过、3 失败；三个失败均为旧 MCP 路径测试，在未修改的 HEAD 上同样复现，未将其算作本次通过。

## 十二 2026-10-28：内置图表与历史置信度

按用户补充要求，reports 3.5.0 在相同字段体系中新增 `chart / confidence / inferences` 类型。16 个独立模块共 33 个候选图表，8 个组合各有 suggested_charts 重点建议；用户显式字段清单依旧完整覆盖默认值。新增图表字段定义内置 kind、映射、原始列、数据要求及证据角色，不固定研究理论。

价格和技术情景优先复用内置 K 线，历史结果使用逐次点、分布、基准对比，综合预测使用结果概率和逐项历史支持，复盘使用校准与方法基准对照。`report_compose` 内联已有 reportKit、SesameCharts 和按需加载的行情运行时，不引入新图表库；提供图表原始数据展开及点击联动。图表不在浏览器计算分箱、概率、置信区间或校准。

置信度与预测必须有 `historical_basis`：可比较情景、匹配方法、目标与期限、已知结果截点、匹配/结算/排除/待定样本、实际结果计数、基准、依赖处理、不确定性与固定历史引用。每项可检验推断分别保留这些依据；最终结论另有联合情景或综合方法的历史评价，不能平均单项置信度。缺少历史结果时允许 unavailable/pending，不生成主观分数。Report 只检查数据契约、计数及上下文一致性，科学有效性仍为 not_evaluated。

可复现演示包含 160 次虚构已结算事件。突破特征 80 个样本中 44 次上涨（55%），事件特征 80 个样本中 40 次上涨（50%），联合情景 40 个样本中 26 次上涨（65%），全部样本基准为 45%。这些统计来自脚本实际计数；联合样本是两特征交集，不把重叠事件当作独立样本相加。Wilson 区间只作为显式选择的演示方法，未成为模板默认算法。所有页面持续标记 demo。

接口和逐模块图表清单见[模块可视化与历史证据](../../plugins/api-v1/packages/reports/skills/report-design/module-visuals.md)。`scripts/build-module-fixtures.mjs` 可再生随包演示数据；大型样本文件作为测试数据保存，不注入模型默认上下文。宿主集成测试冻结真实 DataRef 后生成全部 24 个模板页面，并检查 1000px / 390px 渲染；真实模型另完成 K 线、条件树、历史分布、置信度和逐项依据的定制组合。

本轮验证：57 项报告测试、19 项锁/目录/接口契约测试全部通过；24 个模板（101 个图表实例）均在实际宿主通过 1000px 和 390px 渲染检查。真实模型完成含 K 线、条件树、历史分布与逐项置信度的定制报告；浏览器另外核验 K 线和树节点到原始行的选择联动、窄屏和深色主题。测试报告与模板图集位于本地 `output/report-visuals/`，未发布到日常应用安装目录。离线样式修正后 24 个模板再次渲染通过；追加的模型复测未调用工具，最后一次返回 OpenAI OAuth `invalid_grant`，未将该复测记为通过。保留首轮模型成功产物以及后续失败记录。

## 十三 2026-10-28：结论、历史验证与最终情景的职责

综合行情 R02 和事件研究 R03 使用组合自己的字段建议。M14 只呈现综合判断、结果概率/区间及简短历史依据；对应详细证据存在时可跳转到 M13。完整样本分布、基准和逐项特征推断集中在 M13。M02 保留价格与技术证据，最后的 M15 只画一个综合情景树，统一触发、分支、失效条件和后续观察；树不重复展开历史统计。单独模块及显式用户字段选择仍可使用其他结构或多个树。

历史依据新增 sampling：默认先找当前品种近期同类情景，由方法明确近期窗口。确认 no_match 且 eligible_count 为 0 后才能使用其他品种，并保留原检索成果、替代品种和可比性解释；检索 unavailable 不等于没有匹配。用户显式指定其他范围时记录 user_override 及原因。Report 校验这份记录，具体检索和匹配仍由独立方法执行。

演示样本更新为 DEMO 本品种近期的 160 次虚构五小时事件，统计数值沿用相同构造结果。移除有关模型自评分的说明，正文呈现比例、样本数和估计区间，验证细节归入对应历史口径。24 项模块测试和 19 项接口/锁/目录测试通过；全部 24 个模板重新生成并在实际宿主通过桌面和窄屏渲染检查。未重试此前已失效的模型登录。

## 十四 2026-10-28：TC 种类与字段覆盖审查

8. **共用细粒度元数据**：现有 context 有 subject/as_of/target/horizon；建议补充或约定交易所、币种、bar 周期、时区、首次可得时间、供应商/原始量表/结果版本。方法特有参数仍走扩展字段，避免把内容层级变成方法要求。

## 十五 2026-10-28：建议字段、视觉设计与多方法历史证据

reports 3.6.0 将上述缺口补为 19 个独立模块、11 个组合、338 个建议字段和 55 个内置图表候选。M17 单独承接经济/公司日历，M18 承接固定策略与历史表现，M19 承接组合构建；其余缺项扩展原模块，不按供应商品牌重复建立研究层。所有字段仍默认可选；用户可完整替换章节/字段、改变含义与显示、自建章节或跨模块拼接，不因视觉方案补回删除内容。

实现将三类职责分开：字段及 agent_guidance 解释结果是什么、所需输入、单位/时间、不能混淆的概念和缺失处理；独立方法/知识负责特征识别、历史匹配和统计；visual_plan 与 presentation 负责如何呈现已固定的结果。逐字段知识按模块分成五个按需资源；默认提示只给入口。用户改 meaning/type 后不继承旧指导或不兼容的建议视图。

## 十六 2026-10-28：结果形式、内部来源语义与推理呈现

本节是用户进一步澄清后的现行边界：**Report 只设计需要的结果形式，不指定分析方法、指标、流派、插件路线或执行顺序。** 前面的技术方法演示不是默认方法；提示词和技术指南已改为承接既有特征、判断及历史参照。采样偏好保留为已有历史结果的选择记录与证据语义。

338 个建议字段逐项增加 Agent 内部的 `lineage`：suggested_kind 区分获取、计算、推断、用户约定和混合内容，nature 单独记录事实、统计、解释、预测、计划等性质。外部预测不因被获取而变成事实，混合对象按子项理解；用户改写 meaning/type 后不继承旧分类。实际结果可用 origin 记录自身来源，省略时内部 lineageAudit 如实记录未声明。来源分类、插件路由和内部审计不展示给报告读者。

`reasoning` 只承接可核查的推导摘要：观察、解释、历史对照和判断；不要求完整思考记录。无框布局在桌面并列、窄屏纵向，已有历史只用给定计数与分母画比例条，给定置信度和区间保持原义。pending/unavailable 不补概率；确定性复算可说明历史预测不适用。完整依据可展开，summary/hidden 的选择也作用于历史详情。设计参考与组件 API 见[推理呈现说明](2026-10-28-report-reasoning-visuals.md)。
