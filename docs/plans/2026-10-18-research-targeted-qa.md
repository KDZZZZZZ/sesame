# 投资研究中的按需问答

目标：多空遇到会改变结论的证据或机制缺口时，可向原四研究员定向提问、补取证据并继续追问；完整答案进入风险审查与经理总结。没有实质问题时不增加轮次。

## 实现边界

- 复用宿主 agent.run、Run 等待/检查点、既有 agentId 和协作图，不新增宿主 Agent 接口。
- 插件声明一个成员工具 investment_research_ask({analyst, question})，仅授予多空。它是支持恢复的后台函数，不另建工作流或团队。
- 宿主冻结的成员输入携带本次研究选择、模型和研究成果。问答处理器从宿主 provenance 读取，不让模型填写配置、Run ID 或复制整份提示词。
- 原研究员使用原模型、原能力范围和已有成果进行新一轮核查；没有报告、交易、安装配置或递归派员权限。已完成 Run 不伪装成被恢复，而以相同 agentId 保存新一轮。
- 问题、完整 Markdown 答案、来源和运行引用作为 qa 交接记录。多空依据回答修订判断；经理不拼接问答全文。
- 不预设讨论次数。追问是否继续取决于答案是否留下影响判断、且能够继续核查的缺口；新证据不足时保留分歧和条件结论，不追求口头一致。

## 验证顺序

1. 补充定向问答、连续追问、暂停恢复、来源传递和越界调用回归测试。
2. 实现共享成员交接/等待，接入问答及完整结果记录，更新能力说明和协作关系。
3. 运行原研究工作流测试及真实宿主 SSE 集成测试：两轮回答确实被消费，图仍只有八名成员，报告重生不重新提问。
4. 检查语法、lint、包声明/锁文件；记录实际验证范围与剩余限制。

本次不改变研究问题、不替成员搜索，不修改主程序或发布安装包。
